## Confirmed findings

### V4-SMK-01｜5 秒模型 Timeout 無法穩定取得商品 Intent

三筆商品案例分別在 5,006、5,008、5,033 ms 成為 `INTENT_STAGE_UNAVAILABLE`，且沒有 Usage；唯一完成案例的意圖階段為 4,679 ms。程式使用 `CancelAfter(ProductSearchTimeoutMilliseconds)`，設定值為 5,000 ms。時間與分支一一對應，確認是模型回應尚未完成便觸發 Cancellation，不是 Schema parse 或安全 validator 拒絕。

單次模型架構已把先前 8～18 秒改善到約 5 秒，但本次樣本的 Live 可用率只有 25%。若維持目前設定，AI 商品搜尋多數會安全降級，但無法滿足 AI-09 Live 品質 Gate。

### V4-SMK-02｜確定性推薦理由未涵蓋品牌偏好與排除

`SEARCH-NOVICE-025` 的 Intent、候選與 deterministic check 通過，但回答只列商品品牌、類別、價格與預算，沒有說明偏好 `NOVACORE`、排除 `PIXELFORGE` 如何影響合法候選。原因是 `CreateGroundedReason` 目前只組合 Product、Price、Budget 與 Badges，尚未使用 Intent 的 `PreferredBrandCodes`／`ExcludedBrandCodes`。這是既有評估契約可直接界定的 bounded code gap，不需要改公開 API、資料庫或外部依賴。

## Remaining decision

V4-SMK-02 已依既有契約修正。OpenAI 官方模型頁確認 Luna 支援 `reasoning.effort: none`，目前預設為 `medium`；官方 GPT-5 系列指引將 `none` 保留給不需要多步推理的低延遲分類工作，而本系統商品 Intent 正是單次結構化分類。Responses API 也支援在 `text` 設定 `verbosity`。來源：[GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、[Model guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6-luna)、[Responses create](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。

DEC-BATCH-054 已採用最低成本實驗：保留 Luna、單次呼叫、5 秒 Timeout、預設 service tier 與既有公開契約，只把商品 Intent 請求設為 `reasoning.effort: none`、`text.verbosity: low`，並以本機 payload contract tests 驗證。這不保證 P95 達標；必須在另行授權的一輪 Smoke 比較。若仍無法穩定完成，再決定是否調整 5 秒門檻、模型或付費 service tier。本批未執行 Provider 呼叫，也不得直接執行 66 次 baseline。
