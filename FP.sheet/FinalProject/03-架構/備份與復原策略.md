# 備份與復原策略

## 目標

| 項目 | 已確認目標 |
|---|---|
| SQL Server 完整備份 | 每日一次 |
| 額外備份 | 重大 Migration、重設 Demo 資料前 |
| RPO | 24 小時 |
| RTO | 2 小時 |
| Seed | 固定亂數種子，可重建基準 Demo 資料 |

## 備份範圍

- SQL Server 展示資料庫。
- 商品圖片、案件附件及必要檔案中繼資料對應的本機資料目錄。
- 不把 OpenAI Key、SMTP 密碼、連線字串或其他 Secret 複製進 Git 或一般備份紀錄。
- 本機 Secret 另依團隊安全方式保存；資料重設腳本不得覆寫。

## 執行時點

1. 每日開發結束後建立完整備份。
2. 套用重大 Migration 前建立可識別版本的備份。
3. 執行 `reset-demo-data.ps1` 前建立展示前狀態備份。
4. Day 35 功能凍結及正式 Demo 前各建立一份已驗證備份。

## 還原驗證

- 還原至獨立驗證資料庫，不直接覆寫唯一可用 Demo 資料庫。
- 確認 Migration 版本、核心帳號、商品數、訂單特殊案例、庫存不變量與七個報表基準。
- 確認商品圖片可讀、私有附件仍需授權、孤兒檔沒有被錯誤恢復為公開內容。
- 執行五條核心 E2E 的必要 Smoke Check。
- 記錄開始／完成時間，證明能在 RTO 2 小時內完成。

## 尚待落實

- 實際備份目錄、保留份數、檔名及磁碟空間警告。
- `backup-demo.ps1`、`restore-demo.ps1`、`reset-demo-data.ps1` 實作。
- 至少一次完整還原演練及結果紀錄。
