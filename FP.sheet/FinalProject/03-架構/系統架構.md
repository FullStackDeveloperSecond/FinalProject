# 系統架構

狀態：部分已確認

## 系統組成

```text
Vue 消費者前台 ─┐
                 ├─ ASP.NET Core Web API
Vue 管理後台 ───┘          ↓
                       Application
                            ↓
                          Domain
                            ↑
                      Infrastructure
                            ↓
                  EF Core / SQL Server
```

採前後端分離與模組化單體，不在第一版拆成微服務。

## 後端責任

### API

- HTTP Request／Response。
- Authentication 與 Authorization。
- API Contracts。
- 輸入格式驗證。
- CORS。
- 全域例外處理。
- OpenAPI 文件。
- 呼叫 Application Use Case。

### Application

- 使用案例與流程協調。
- DTO、Validator 及 Result。
- 外部能力介面。
- 不依賴 HTTP 或 Vue。

### Domain

- Entity、Value Object、Enum。
- 商業規則與領域例外。
- 不依賴 API、EF Core、SQL Server 或 Vue。

### Infrastructure

- EF Core 與 SQL Server。
- Repository 或 Application 所需資料存取實作。
- Identity、Email、OpenAI、檔案儲存。
- 模擬 Payment Gateway 與 Shipping Provider。
- 背景排程與外部服務 Adapter。

客服附件第一版存放於網站根目錄之外的本機私有目錄，下載必須經過 API 驗證及授權。不得將客服附件直接放在 `wwwroot` 供靜態存取。

## 依賴方向

```text
Api → Application → Domain
Api → Infrastructure
Infrastructure → Application + Domain
Domain → 無其他專案依賴
```

兩個 Vue 應用程式只能透過 API 使用後端，不直接存取資料庫。

## API 路由

```text
/api/v1/products
/api/v1/cart
/api/v1/orders
/api/v1/support

/api/v1/admin/products
/api/v1/admin/inventory
/api/v1/admin/orders
/api/v1/admin/returns
/api/v1/admin/reports
```

API Controller 保持精簡，不直接操作大量 `DbContext` 或包含商業規則。

### 客服、檢舉與退貨邊界

```text
SupportTicket ─┐
ReportCase ────┼─ 統一管理工作台查詢
ReturnRequest ─┘
```

- 三個領域各自擁有資料、狀態及寫入流程，不共用案件主表。
- 管理後台可以透過統一 API 查詢工作台摘要，但後續動作必須送往各自領域的 Application Use Case。
- 統一查詢的排序、分頁、欄位、權限及一致性規則仍待設計。

## 前端

### customer-web

- Vue 3、TypeScript、Vite。
- 手機與桌面響應式介面。
- 商品、AI 搜尋、組裝、購物車、結帳、訂單及會員功能。
- 第一版繁體中文；日文與韓文列為 S。

### admin-web

- Vue 3、TypeScript、Vite。
- 第一版桌面版與繁體中文。
- 商品、庫存、訂單、物流、退貨退款、客服、優惠券、權限及報表。
- 商品管理包含批次上下架、批次調價與 Excel 匯入匯出。
- 報表包含七個已確認為 M 的分析畫面。

前端套件與 UI 元件庫尚待決定。

## 安全邊界

- API 最終驗證所有角色、訂單所有權、金額、優惠、庫存及狀態轉換。
- Vue Router Guard 只改善體驗，不是安全邊界。
- AI 不直接查詢資料庫，也不能執行寫入操作。
- 個資送往 OpenAI 前由後端最小化與去識別化。
- 管理員完整個資存取與退款需要稽核。
- 設定、API Key、連線字串及 Email 密碼不得提交 Git。

## 模擬外部服務

```text
IPaymentGateway   → SimulatedPaymentGateway
IShippingProvider → SimulatedShippingProvider
```

模擬器必須保留真實服務常見的非同步回呼、逾時、失敗、重複通知與冪等處理概念，使未來可替換實際 Provider。

## 本機展示啟動

第一版不使用 Docker，提供：

```text
scripts/
├─ start-all.ps1
├─ stop-all.ps1
├─ status.ps1
├─ reset-demo-data.ps1
└─ health-check.ps1
```

`start-all.ps1` 檢查 SQL Server、啟動 API、前台、後台，等待 Health Check，並輸出服務網址。停止腳本使用本專案保存的 PID，不可一次終止電腦上的所有 Node 或 .NET 程序。
