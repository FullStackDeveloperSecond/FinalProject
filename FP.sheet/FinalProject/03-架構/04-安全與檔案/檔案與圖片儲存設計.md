# 檔案與圖片儲存設計

## 儲存抽象

```text
IImageStorage       商品公開圖片與縮圖
IPrivateFileStorage 客服、檢舉、退貨附件
IFileScanner        上傳安全掃描
```

第一版 Infrastructure 使用展示電腦本機檔案系統；Application 只依賴介面，不能硬編磁碟路徑。

## 商品圖片

- 原圖保存於網站專案與 `wwwroot` 之外的資料目錄。
- 產生不可猜測的 Storage Key，不使用使用者檔名作實體路徑。
- 保持比例產生長邊 320、800、1600 px 三種 WebP；不放大小於目標尺寸的原圖，品質固定為 80。原圖只供管理與重新處理。
- 圖片解碼與衍生圖固定使用 `SixLabors.ImageSharp 3.1.12`；版本由 Central Package Management 精確鎖定，不使用需要每位開發者設定授權金鑰的 4.x。
- 解碼前先檢查實際串流 10 MB、JPG／PNG／WebP 的副檔名、MIME、簽章及 Defender 掃描；通過後才由 ImageSharp Identify／Decode，不信任 Client 提供的尺寸或格式。
- 單張圖限制最長邊 10,000 px 且總像素不超過 25,000,000；Decoder 最多讀取 2 Frame，實際只接受單 Frame，ImageSharp 平行度上限 2、Allocator 上限 256 MB、Pool 上限 64 MB。超限、動畫或無法安全解碼統一為 `image_processing_failed`。
- 依 EXIF 方向校正後產生衍生圖；三種 WebP 均移除原始 Metadata。原圖位於私有目錄且保持原始位元內容，供後台管理與重新處理。
- 三種衍生圖先在 Staging 全部完成，再以目錄 Move 一次發布到正式圖片目錄；任何一步失敗都清理隔離檔與 Staging，不留下部分可讀圖片。
- 只有狀態為已核准／已發布的圖片能由公開路由或受控靜態映射讀取。
- 公開路由使用 `/media/products/{publicId}/{variant}/{contentHash}.webp`；內容雜湊改變時產生新 URL，已發布資源設定一年 `Cache-Control: immutable`。
- 資料庫保存 Product／SKU 關聯、Storage Key、原始檔名、安全 MIME、尺寸、檔案大小、雜湊、來源 URL、授權、下載日期、顯示排序及建立時間。
- 替換圖片建立新 Storage Key；新檔完成、資料交易成功後才排程清理舊檔，避免先刪除造成破圖。

## 私有案件附件

- 客服、檢舉與退貨各自關聯附件資料，不建立共用案件主表。
- 只能透過驗證與資源授權 API 下載，不提供公開靜態 URL。
- 同時驗證副檔名、MIME、檔案簽章與 Microsoft Defender 掃描結果。
- 掃描不可用、逾時或結果不明時拒絕保存。
- 每案最多 3 個，每個最大 10 MB；PNG、JPG、PDF。

## 清理生命週期

| 類型 | 清理規則 |
|---|---|
| 已結案件附件 | 案件結束後 180 天 |
| 暫存／孤兒檔 | 建立後 24 小時且未完成資料關聯 |
| Legal Hold | Hold 期間暫停自動刪除，解除需稽核 |
| 商品舊圖 | 新圖成功發布且沒有其他引用後排程清理 |

- 清理每日由 `maintenance` Queue 執行。
- 實體刪除失敗最多重試 2 次，仍失敗時保留錯誤、Storage Key 與 Trace ID。
- 備份還原時要同時處理 SQL Server 中繼資料與檔案目錄，不能只還原其中一側。

## 未發布圖片預覽

- 未發布原圖與衍生圖不得由公開靜態路徑讀取，只能經後台授權 API 串流預覽。
- 未登入、無 Catalog 權限、資源不屬於允許範圍或檔案不存在時均回 404，不揭露檔案是否存在。
- 正式發布後才產生可公開且不可猜測的內容雜湊 URL；替換不覆寫舊 URL。

## API 與錯誤契約

| Method／Route | 用途 | Policy／資源授權 |
|---|---|---|
| `POST /api/v1/admin/products/{productId}/images` | 上傳一張商品原圖並建立三種衍生圖 | `CatalogImage.Manage` |
| `GET /api/v1/admin/product-images/{imageId}/preview/{variant}` | 預覽未發布的 original／320／800／1600 | `CatalogImage.ViewDraft`；未授權一律 404 |
| `PATCH /api/v1/admin/product-images/{imageId}` | 更新 Alt、排序與來源／授權中繼資料 | `CatalogImage.Manage`＋RowVersion |
| `POST /api/v1/admin/product-images/{imageId}/actions/publish` | 核准並產生公開內容雜湊 URL | `CatalogImage.Publish` |
| `DELETE /api/v1/admin/product-images/{imageId}` | 解除引用並依生命週期排程清理 | `CatalogImage.Manage`＋RowVersion |
| `GET /media/products/{publicId}/{variant}/{contentHash}.webp` | 讀取已發布衍生圖 | 公開；Hash／狀態不符回 404 |
| `POST /api/v1/support-tickets/{id}/attachments` | 上傳客服附件 | 案件擁有者或授權客服 |
| `POST /api/v1/report-cases/{id}/attachments` | 上傳檢舉證據 | 案件擁有者或授權處理者 |
| `POST /api/v1/returns/{id}/attachments` | 上傳退貨證據 | 訂單存取權或授權售後角色 |
| `GET /api/v1/private-attachments/{id}/content` | 串流私有附件 | 依附件領域與資源所有權判斷 |

- 圖片一次只接受一檔，最大 10 MB，JPG／PNG／WebP；私有附件沿用每案 3 個、每檔 10 MB、PNG／JPG／PDF。
- Multipart 欄位固定 `file`；商品圖另接受 `altText` 最多 160 字、`sourceUrl` 最多 1000 字、`licenseName` 最多 100 字及 `licenseUrl` 最多 1000 字。
- 主要錯誤碼統一為：`file_count_exceeded`、`file_size_exceeded`、`file_format_invalid`、`file_malware_detected`、`file_scan_unavailable`、`image_processing_failed`、`image_metadata_incomplete`、`concurrency_conflict`。
- 檔案數量超限回 400、大小超限回 413、副檔名／MIME／簽章不符回 415、確認惡意內容或圖片可接受但無法安全處理回 422、掃描不可用回 503；RowVersion 衝突回 409，未授權預覽／下載與不存在均回 404。
- 同一條件不得再使用舊草稿中的 `attachment_*`、`file_too_large`、`file_type_not_allowed`、`file_signature_mismatch` 或 `file_scan_rejected`。
- 上傳完成但資料交易失敗時立即排程孤兒清理；衍生圖未全部成功前不得發布。

## 圖片保存與備份

- 目前發布中及仍被 Product／SKU 引用的圖片持續保存。
- 替換後且已無任何引用的商品原圖與衍生圖保留 30 天，再由每日清理工作刪除；實體刪除成功後才更新清理結果。
- 未完成發布且無引用的暫存圖片 24 小時後清除。
- 圖片納入 SQL 備份相同 Backup Set ID 的檔案封存，沿用每日 7 份、每週 4 份政策，不另建立互相矛盾的 Rolling 份數。
