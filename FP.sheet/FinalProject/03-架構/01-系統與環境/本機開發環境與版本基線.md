## 新電腦安裝順序

1. 安裝 Git、精確版本 `.NET SDK 10.0.303 x64`、Node.js 24 LTS、SQL Server 2025 Developer Edition 與管理工具；其他 .NET 10 Patch／Feature Band 不符合本專案基線。
2. Clone Repository；第一版目前不使用 Git LFS 或 Docker。
3. 依範例建立 User Secrets／本機環境設定，不把 SQL、OpenAI 或 Brevo Secret 寫進 Repository。
4. 在兩個 Vue 專案分別使用 `npm ci`，不得以 `npm install` 任意改寫鎖檔後直接提交。
5. Restore／Build .NET Solution，建立本機資料庫並套用 EF Core Migration。
6. 產生固定 Seed 展示資料，啟動 API、customer-web、admin-web。
7. 執行 Readiness、基本登入、商品列表及資料庫版本 Smoke Check。

## 版本檢查目標

最終安裝文件必須提供不修改系統狀態的檢查指令，至少確認：

- `dotnet --version` 符合 `global.json`。
- `node --version` 為 Node 24 LTS Major。
- `npm --version` 符合團隊記錄版本。
- SQL Server Instance 可連線且版本／Edition 正確。
- `npm ci`、.NET Restore、Build、Migration 與測試可由乾淨環境重現。

## .NET SDK 鎖版策略

根目錄 `global.json` 建立時固定採用下列契約：

```json
{
  "sdk": {
    "version": "10.0.303",
    "rollForward": "disable",
    "allowPrerelease": false
  }
}
```

- 全組與 CI 必須使用精確的 `.NET SDK 10.0.303`。
- `rollForward: disable` 不接受其他 Patch、Feature Band、Major 或 Minor；即使電腦另有 `10.0.400`，專案目錄內仍必須找到 `10.0.303` 才能執行 .NET CLI。
- `global.json` 不負責下載 SDK；新電腦與既有成員須另外安裝 `10.0.303 x64`。
- 同一 Feature Band 的 servicing update 會取代前一個 Patch；`10.0.303` 取代 `10.0.302` 後，不再要求兩者於機器層並存。
- 若機器層 SDK 安裝不完整或目前帳號無系統管理員權限，可由 Microsoft 官方 `dotnet-install.ps1`／SDK ZIP 精確安裝至使用者層 `%USERPROFILE%\.dotnet`；下載檔須以官方 SHA-512 驗證。當機器層 `dotnet.exe` 排在 PATH 前方時，驗證與專案命令須明確使用 `%USERPROFILE%\.dotnet\dotnet.exe`，不得因此放寬 `global.json`。
- 不接受 Preview SDK。
- SDK 基準升級必須獨立 PR，附 Restore、Build 與 Test 結果。

## .NET 共用編譯基線

Repository 根目錄的 `Directory.Build.props` 統一套用至四個後端專案與四個測試專案：

```xml
<Project>
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
</Project>
```

- 不設定 `LangVersion`，由 `net10.0` 與已鎖定 SDK 選擇相容的預設 C# 語言版本。
- 不在 `Directory.Build.props` 全域設定 `TreatWarningsAsErrors`，避免本機開發因所有警告直接中斷。
- CI 的 .NET Build 必須加入 `-warnaserror`；PR 合併前不得留下編譯或程式碼分析警告。
- 若單一專案確實需要覆寫共用值，必須在 PR 說明原因與影響，不得默默偏離基線。

## C# 格式與命名基線

Repository 根目錄建立唯一一份 `.editorconfig`，並設定 `root = true`。第一版只建立穩定且低爭議的 C# 基線：

- C# 使用空白縮排，每層 4 格，移除行尾空白並保留檔尾換行。
- Interface 使用 `I` 前綴與 PascalCase。
- Type、Method、Property、Event 與 Constant 使用 PascalCase。
- Parameter 與 Local Variable 使用 camelCase。
- Private Instance Field 使用 `_camelCase`。
- 不在第一版一次把全部 IDE／CA 規則提升為 Warning 或 Error；新增或提高規則嚴重度必須獨立 PR，先處理既有違規再啟用。

開發者提交前可執行：

```powershell
dotnet format DoSelect.slnx --no-restore
```

CI 固定執行：

```powershell
dotnet format DoSelect.slnx --verify-no-changes --no-restore
```

CI 只能驗證，不可自動格式化後 Commit；格式失敗時由原變更者在分支修正。

## 套件管理規則

### .NET／NuGet

- 在 Repository 根目錄建立唯一一份 `Directory.Packages.props`，套用至四個後端專案與四個測試專案。
- 設定 `ManagePackageVersionsCentrally` 為 `true`。
- 所有需集中管理的版本使用 `PackageVersion` 宣告；各 `.csproj` 的 `PackageReference` 只聲明需要哪些套件，不得重複填寫 `Version`。
- 精確套件版本在建立 Solution 時依 .NET 10 相容性選定，完成 Restore、Build 與 Test 後才寫入基線。

### Vue／npm

- customer-web 與 admin-web 都使用 npm；不得一個專案使用 npm、另一個使用 pnpm。
- `package.json` 與 `package-lock.json` 必須同一個 PR 更新。
- CI 使用 `npm ci`；鎖檔不一致時直接失敗。
- Node Major 升級、套件管理器更換或鎖檔重建需獨立 PR，附兩個 Vue 專案的 Lint、Typecheck、Test 與 Build 結果。

## SQL Server 本機連線基線

- 本機開發與現場展示採 Windows Authentication；不要求啟用 SQL Server Mixed Mode，也不共用 `sa` 或專案專用明碼密碼。
- API、EF Core Migration、Seed 與腳本都使用設定 Key `ConnectionStrings:DefaultConnection`；環境變數名稱為 `ConnectionStrings__DefaultConnection`。
- 無密碼連線字串範例固定為：

```text
Server=.\SQL2025;Database=DoSelectDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True;
```

- `Trusted_Connection=True` 使用目前啟動 API／`dotnet ef` 的 Windows 身分；每位成員需由本機 SQL Server 管理員授予自己必要的開發權限，不提交或共用 Windows 密碼。
- `TrustServerCertificate=True` 只允許本機 Development／Demo 命名 Instance；若未來改成公網、正式憑證、非 Windows 執行環境或 Container，必須另立連線與憑證決策。
- Repository 只保存上述無密碼範例與 Key；開發者可用 User Secrets 覆寫 Instance／Database，Demo 可用使用者層級環境變數覆寫。若日後改用 SQL Login，完整 Connection String 立即視為 Secret，禁止提交 Git。
- `start-all.ps1` 必須沿用啟動者 Windows 身分，不以管理員權限、服務帳號或硬編 Credential 迴避資料庫授權。
