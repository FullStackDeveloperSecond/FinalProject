# 統一案件工作台設計

## 邊界

客服案件、檢舉案件與退貨案件維持三個獨立 Aggregate、狀態機與寫入 Use Case。工作台只透過 SQL Server `UNION ALL` View 與 EF Core Keyless Entity 提供統一唯讀查詢，不提供跨領域通用寫入 Entity。

V1 投影只允許下列 12 欄，不新增 `CustomerReplyState`、工作台 RowVersion 或另一套 `AssignmentState`。要執行動作時必須再呼叫來源領域詳情 Endpoint，取得其 RowVersion 與 AvailableActions。

## 共通欄位

| 欄位 | 用途 |
|---|---|
| `CasePublicId` | 對外資源識別 |
| `CaseType` | `Support`、`Report`、`Return` |
| `CaseNumber` | 人工溝通與搜尋編號 |
| `Title` | 去除不必要個資後的摘要標題 |
| `Status` | 領域狀態映射後的穩定字串 |
| `Priority` | 四級優先級或領域等價值 |
| `RequesterDisplay` | 已遮蔽顯示值，不放完整會員資料 |
| `AssigneePublicId` | 未指派時為 Null |
| `CreatedAtUtc` | 建立時間 |
| `LastActivityAtUtc` | 最後有效活動時間 |
| `SlaDueAtUtc` | 無 SLA 時為 Null |
| `IsOverdue` | 由有效 SLA 到期時間判斷 |

## 授權

- Application 依目前管理員角色與 Policy 建立查詢，每個 `UNION ALL` 分支都必須在 SQL 執行前加入可見範圍條件。
- 不允許先查出完整工作台再於記憶體過濾。
- `CustomerService` 可見客服與一般檢舉佇列；主管可見其管理佇列與需覆核的個資、安全、詐欺、法律或其他高風險檢舉；退貨角色只見退貨領域。多角色取允許範圍聯集，但寫入仍回到領域專用 Policy。
- `RequesterDisplay`、Title 與搜尋欄位需先完成個資遮蔽；查看完整資料使用領域詳情 Endpoint 並另寫 AuditLog。

## 排序與分頁

- 預設排序固定為 `LastActivityAtUtc DESC, CasePublicId DESC`。
- 使用不透明 Cursor，同時編碼兩個排序鍵；相同活動時間由 CasePublicId 保證穩定順序。
- 篩選條件或角色範圍改變後必須重新開始分頁，Cursor 不得跨查詢條件重用。
- View 只選清單需要欄位；各來源表需依可見範圍、狀態、指派人及 LastActivity 建立適當索引。

## API 契約

`GET /api/v1/admin/case-workbench` 回傳 `CursorPage<CaseWorkbenchItemDto>`，支援 `caseType`、`status`、`priority`、`assigneePublicId`、`overdueOnly`、關鍵字及 Cursor。寫入動作由回應提供的 `caseType` 導向客服、檢舉或退貨專用 Endpoint。

## 驗收

1. 單一角色只看見其領域與允許佇列；多角色看到聯集但不重複。
2. 無權限案件不因搜尋、Cursor、數量或錯誤訊息洩漏存在性。
3. 新案件插入或既有案件更新時，Cursor 分頁不出現同頁重複。
4. 點入敏感資料仍通過領域 Policy 並留下 AuditLog。
5. View／Keyless Entity 不可被 EF Core 當作可更新 Entity。
