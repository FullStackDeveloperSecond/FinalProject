## 共通欄位基線

| 概念 | 建議欄位 | 規則狀態 |
|---|---|---|
| 主鍵 | `Id` | 型別待技術設計 |
| 建立時間 | `CreatedAtUtc` | UTC，必填 |
| 修改時間 | `UpdatedAtUtc` | UTC；不可修改資料可省略 |
| 軟刪除 | `DeletedAtUtc`／狀態欄位 | 僅適用已確認可軟刪除資料，不可全面套用 |
| 併發 | `RowVersion` | 用於後台可編輯且有覆寫風險的資源 |
| 顯示排序 | `SortOrder` | 只有人工可排序資料使用 |
| 外部識別 | `ExternalReference` | 付款、物流等模擬 Provider 需唯一或具範圍唯一 |
| 冪等 | `IdempotencyKey` | 建立訂單、付款／退款通知等高風險命令 |

## 索引與資料完整性檢查

- 所有 FK 必須明確決定刪除行為，不使用未審核的 Cascade Delete。
- 搜尋、列表、報表、庫存保留、SLA 到期及背景清理查詢需依實際查詢建立複合索引。
- 唯一性若只適用有效資料，需評估 SQL Server Filtered Unique Index。
- 金額使用適當的 `decimal`，不得使用 `float`／`real`；精度與小數位仍需定版。
- 日期時間使用 UTC；SQL 型別與精度仍需定版。
- RowVersion 使用 SQL Server `rowversion` 並對應 EF Core Concurrency Token。
- 敏感欄位不得進入一般全文搜尋、Log 或稽核差異全文。

## 完成資料字典前仍需決策

- 主鍵策略、字串最大長度、金額精度、日期時間型別。
- 表名與欄名單複數及命名慣例。
- 每張表保留／刪除／匿名化規則。
- 圖片與附件中繼資料的儲存識別格式。
- AI 工具 DTO、搜尋 Schema 與 CSV 精確欄位完成後，回填對應資料來源。
