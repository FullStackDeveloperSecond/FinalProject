# 多語系與 RWD 驗收矩陣

## 第一版範圍

- M 版本前台啟用繁體中文；日文、韓文為 S，但所有新前台文字必須走語系 Key，不得散落硬編碼。
- M 版本的消費者前台與管理後台只驗收桌面寬度；消費者前台手機與平板 RWD 為獨立 S。
- 後台第一版只驗收繁體中文與桌面寬度，後台手機版不在目前 S 範圍內。
- 語系缺值順序為目前語言→`zh-TW`→穩定 Key，禁止顯示空白或直接崩潰。

### S 啟動條件

消費者前台 RWD 只有在所有 M 功能可建置、Migration 可由空白資料庫重建、API 契約穩定且核心 Demo 測試通過後才開始。未達門檻時，不得要求 M 功能為手機或平板寬度延後交付。

## Viewport

| 區間 | 代表測試寬度 | 前台要求 | 後台要求 |
|---|---:|---|---|
| Mobile `<768` | 360、390 | S：核心搜尋、商品、組裝、購物車、結帳、會員與客服可完成 | 不驗收 |
| Tablet `768–1023` | 768、820 | S：不出現頁面級水平捲動，表格轉卡片或使用可理解的局部捲動 | 不驗收 |
| Desktop `≥1024` | 1280、1440 | M：完整核心功能 | M：1280 起完整操作 |

## 三語與長字串

- 按鈕、標籤、錯誤、導覽與狀態不可截斷到無法理解；必要時換行，不使用固定高度遮蔽。
- 商品名以 80 個 CJK 字元、客服標題 120 個、地址兩行各 100 個字元作邊界案例。
- 表格欄位允許省略號時必須提供 Tooltip／詳情，不可省略金額、狀態或主要操作。
- 翻譯草稿需經管理員確認才發布；缺翻譯時依 Fallback 顯示繁中。

## 格式化

- 新台幣用 `Intl.NumberFormat(locale, { style: 'currency', currency: 'TWD' })`。
- 日期時間由 UTC 轉 `Asia/Taipei`，以 `Intl.DateTimeFormat` 依語系顯示；API 不傳本地化字串。
- 數量與百分比使用 `Intl.NumberFormat`；SKU、訂單編號、優惠碼與技術 Code 不翻譯。

## 核心驗收頁面

M 驗收時，商品搜尋／詳情、自然語言推薦、組裝器、購物車、結帳、訂單查詢、會員登入／註冊、AI／人工客服各需在 1280 寬度至少完成一個成功流程及一個錯誤狀態。RWD S 啟動後，同一批核心頁面再於 360 與 768 寬度執行相同流程；多語系 S 啟動時，再以日文、韓文跑長字串與 Fallback 案例。
