# 相容性規則後台設計

## 管理邊界

- 規則 Code、比較運算式、受保護 Semantic Key、硬性阻擋條件及 PSU 八個級距由程式碼固定，後台不可改寫。
- `CatalogManager` 與 `SuperAdmin` 可查看規則、執行測試，以及在安全範圍內修改警告門檻。
- 規則整體啟停只允許 `SuperAdmin`，需二次確認及原因；停用硬性規則只限 Demo／維護，不得默默視為相容。
- 一般後台角色只可查看已套用於商品的結果，不取得門檻設定權限。

## 可調警告門檻

| Setting Code | 預設 | 安全範圍 | 行為 |
|---|---:|---:|---|
| `GpuClearanceWarningMm` | 20 mm | 10～50 mm | 顯示卡長度未超限，但剩餘空間小於或等於門檻時警告 |
| `CoolerClearanceWarningMm` | 10 mm | 5～30 mm | 散熱器高度未超限，但剩餘空間小於或等於門檻時警告 |
| `PsuReserveWarningPercent` | 35% | 30～50% | 已通過硬性 30% 規則，但額外餘裕低於設定值時提示未來升級空間有限 |
| `RemainingRamSlotWarningCount` | 0 | 0～2 | 安裝後剩餘 RAM 插槽小於或等於門檻時警告 |
| `RemainingStoragePortWarningCount` | 0 | 0～2 | 安裝後相容儲存連接埠小於或等於門檻時警告 |

設定值超界回 `compatibility_threshold_out_of_range`，不得自動截斷。BIOS 映射、Socket、DDR、尺寸上限、容量上限、接頭與 PSU 最低需求都不是可調警告門檻。

## 規則測試 API

### Request

`POST /api/v1/admin/compatibility-rules/test`

```json
{
  "items": [
    { "skuPublicId": "019...", "quantity": 1 }
  ],
  "ruleCodes": ["CPU_SOCKET", "PSU_CAPACITY"],
  "useDraftSettings": false
}
```

- `items` 1～20 筆；同一 SKU 先合併數量，數量 1～8。
- `ruleCodes` 可省略，表示執行全部適用規則；最多 20 個且未知 Code 整筆拒絕。
- `useDraftSettings=true` 只允許在同一請求帶入已通過範圍驗證的暫存警告設定，不保存設定。
- 測試可引用未上架 SKU，但不能繞過 Catalog 資源權限。

### Response

```json
{
  "overall": "Blocked",
  "results": [
    {
      "ruleCode": "CPU_SOCKET",
      "severity": "Blocked",
      "messageKey": "compatibility.cpu_socket_mismatch",
      "subjectSkuPublicIds": ["019...", "019..."],
      "facts": { "cpuSocket": "AM5", "boardSocket": "LGA1700" }
    }
  ],
  "settingsVersion": 3,
  "evaluatedAtUtc": "2026-08-13T00:00:00Z"
}
```

`overall` 只允許 `Compatible`、`Warning`、`Blocked`、`InsufficientData`。`facts` 只包含白名單的結構化規格，不回傳內部 SQL Id、成本或未授權欄位。

## 設定 API 與併發

| Method／Route | 用途 | Policy |
|---|---|---|
| `GET /api/v1/admin/compatibility-rules` | 查詢規則與目前門檻 | `CompatibilityRule.View` |
| `PATCH /api/v1/admin/compatibility-rules/{ruleCode}/warning-settings` | 更新警告門檻 | `CompatibilityRule.ManageWarnings` |
| `POST /api/v1/admin/compatibility-rules/{ruleCode}/actions/set-activation` | 啟停整條規則 | `CompatibilityRule.ManageActivation`（SuperAdmin） |
| `POST /api/v1/admin/compatibility-rules/test` | 執行無寫入測試 | `CompatibilityRule.Test` |

更新命令必須包含 RowVersion；衝突回 `409 concurrency_conflict`。成功更新建立新 Settings Version，既有訂單與組裝快照不回寫。

## 稽核欄位

每次門檻或啟停異動至少保存 Actor PublicId、Rule Code、Setting Code、Before、After、Reason、Settings Version、OccurredAtUtc、IP、TraceId。規則測試保存 Actor、輸入 SKU PublicId 集合 Hash、結果摘要、設定版本與 TraceId，不保存完整商品內容副本。

## 驗收重點

- 邊界最小值、最大值可保存；超界與非數字拒絕。
- 無權限角色無法讀取或修改；未登入與越權不靠前端隱藏。
- 相同 RowVersion 的兩次更新只有一次成功。
- 停用規則後結果顯示 `RuleDisabled`，不得回 `Compatible`。
- 測試與正式購物流程使用同一 Application 規則服務及相同設定版本。
