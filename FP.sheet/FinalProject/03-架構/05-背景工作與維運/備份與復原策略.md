# 備份與復原策略

## 目標

| 項目 | 已確認目標 |
|---|---|
| SQL Server 完整備份 | 每日一次 |
| 額外備份 | 重大 Migration、重設 Demo 資料前 |
| RPO | 24 小時 |
| RTO | 2 小時 |
| Seed | 固定亂數種子，可重建基準 Demo 資料 |

## 備份範圍

- SQL Server 展示資料庫。
- 商品圖片、案件附件及必要檔案中繼資料對應的本機資料目錄。
- Rolling Log 不作為交易資料還原來源；若納入備份，只供問題追查且必須遵守 14 天保存與敏感資料規則。
- 不把 OpenAI Key、SMTP 密碼、連線字串或其他 Secret 複製進 Git 或一般備份紀錄。
- 本機 Secret 另依團隊安全方式保存；資料重設腳本不得覆寫。
- SQL 備份與檔案目錄快照使用同一個 Backup Set ID，避免還原到不同時間點的資料與檔案。

## 本機資料根目錄

- 使用 Repository／網站根目錄之外的單一資料根目錄，展示機固定為 `E:\FinalProjectData`，並依 Development／Demo 等環境分子目錄。
- 絕對路徑以未提交 Git 的本機設定注入，不寫死於 Application 或 Domain；其他成員若沒有 E 槽可覆寫自己的路徑。
- 子目錄至少區分商品原圖、公開衍生圖、私有案件附件、暫存掃描、Log 與 Backup，不混放可公開與私有檔案。

## 保留政策

| 備份層級 | 份數 |
|---|---:|
| 每日完整備份 | 7 份 |
| 每週完整備份 | 4 份 |

- 清理時必須以完整 Backup Set 為單位，同時處理 SQL 與對應檔案 Manifest。
- 刪除前驗證至少仍有一份通過還原檢查的 Demo 備份；清理失敗需告警，不得假裝成功。
- 可用空間低於磁碟容量 20% 或低於 20 GB 任一條件時告警；不得自動刪除未到期或唯一已驗證備份。

## 執行時點

1. 每日開發結束後建立完整備份。
2. 套用重大 Migration 前建立可識別版本的備份。
3. 執行 `reset-demo-data.ps1` 前建立展示前狀態備份。
4. Day 35 功能凍結及正式 Demo 前各建立一份已驗證備份。

## 還原驗證

- 還原至獨立驗證資料庫，不直接覆寫唯一可用 Demo 資料庫。
- 確認 Migration 版本、核心帳號、商品數、訂單特殊案例、庫存不變量與七個報表基準。
- 確認商品圖片可讀、私有附件仍需授權、孤兒檔沒有被錯誤恢復為公開內容。
- 執行五條核心 E2E 的必要 Smoke Check。
- 記錄開始／完成時間，證明能在 RTO 2 小時內完成。

## Backup Set Manifest

Manifest 使用 UTF-8 JSON，至少保存 `schemaVersion`、`backupSetId`、`environment`、`createdAtUtc`、Git Commit、Migration、資料庫備份檔名／大小／SHA-256、檔案封存檔名／大小／SHA-256、建立結果、最近還原驗證時間與結果。Manifest 不保存 Secret 或連線字串。
