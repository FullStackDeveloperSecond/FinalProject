# HR 行為題與 STAR

## 面試官評估什麼

不是只聽個性，而是找可驗證行為：Ownership、問題拆解、協作、溝通、學習、誠信、品質、面對失敗與動機。回答要具體可追問，不能把團隊成果全說成自己。

## STAR(R)

- Situation：兩句內交代背景與限制。
- Task：你的責任與成功標準。
- Action：篇幅最多，說你如何判斷、溝通、執行。
- Result：可驗證結果；可用測試、交付、風險降低與回饋，不硬編數字。
- Reflection：學到什麼，下次會改什麼。

準備 5～6 個故事，而非每題背一稿。同一故事可從不同能力回答。

## 六張故事卡

| 能力 | 可找素材 | 你的證據 |
|---|---|---|
| 最難問題 | 交易、安全、CORS/CSRF、競態 | [請填 issue/PR/commit/test] |
| 主動性 | 發現規格/實作漂移、補 guard/test | [請填] |
| 衝突 | 技術取捨、分工、review 意見 | [請填共識過程] |
| 失敗 | 漏測、錯估、regression | [請填修復/防再發] |
| 學習 | 首次使用 .NET/Vue/EF/AI 評測 | [請填證據] |
| 時間壓力 | Demo 前縮小範圍 | [請填取捨/結果] |

## 常見 HR 題

### 請自我介紹

現在定位 → 相關能力 → DoSelect 證據 → 為何符合職缺。60～90 秒，不從出生開始。

### 為何應徵？

連結職缺內容、你的證據與成長方向。不要只說公司有名或福利好；面試前另查公司產品與 JD。

### 優點？

選職務相關能力後立刻接行為證據。例如「把不確定性轉成可驗證條件」，再說 integration test 或 contract gate。

### 缺點？

選真實可改善的工作行為，說觸發、影響、改善機制、目前變化。不要以完美主義假裝優點，也別選核心能力且毫無改善。

### 說一次失敗

不推責。說判斷錯在哪、如何止損、補何種測試/流程、是否再發。Result 不必假裝漂亮，Reflection 更重要。

### 與隊友意見不合？

對齊成功標準，分離事實/偏好，用小實驗驗證，記錄決策/owner。最後若非採你的方案，也支持團隊決定；安全/資料完整性風險則清楚升級。

### 為何錄取你？

用職缺的 2～3 項能力與證據回答，不貶低別人。初階可強調端到端交付、接受 review、用測試/追蹤除錯、誠實處理未知。

### 期望薪資？

先理解職責、職等、總薪酬與市場，再給有依據範圍和彈性條件；沒有 JD/市場資料時不編數字。

### 五年後？

談能力與責任成長：先獨立負責端到端功能與營運品質，再承擔設計、review、跨角色溝通。

## 可以反問

1. 前三個月最重要的成功標準？
2. 團隊如何 code review、測試與從 production incident 學習？
3. 角色最常遇到的技術/協作挑戰？
4. 新人第一個任務類型與 feedback 來源？
5. 後續流程與預計時程？

## 不適當問題界線

台灣《就業服務法》第 5 條要求就業機會平等，也禁止要求非就業所需隱私。婚姻、年齡、星座、血型等不應作為歧視理由。遇到無關私密問題，可禮貌導回「是否與職務條件或出勤需求相關」；實際爭議向主管機關或專業人士確認。

## 練習

- 每題錄音 90～120 秒，Action 要比 Situation 長。
- 刪掉「我們就處理了」等看不出你行動的句子。
- 不背逐字稿，只記五節點。
- 請不熟專案的人追問兩次。
