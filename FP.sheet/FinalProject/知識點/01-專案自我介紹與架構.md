# 專案自我介紹與架構

## 60 秒版本

> DoSelect 是五人團隊開發的電腦零組件電商與智慧組裝平台，讓使用者從商品搜尋、相容性檢查、購物車一路完成結帳，也提供管理端處理商品、庫存、訂單、客服與報表。前端是 Vue 3 與 TypeScript，後端是 .NET 10 ASP.NET Core API，資料使用 EF Core 與 SQL Server。專案特別處理 Cookie 安全、結帳冪等與交易一致性、OpenAPI typed client、背景工作和 AI 失敗降級。我的主要負責範圍是「[請填模組]」，我解決的具體問題是「[請填]」，並用「[測試／CI／數據]」驗證。

最後三欄一定要換成真實內容，面試官通常會從這裡往下追問。

## 3 分鐘版本順序

1. 問題：一般使用者不容易判斷零件相容性，也要處理一般電商交易。
2. 產品：顧客端、管理端、API、SQL Server、AI 搜尋／客服與硬規則相容性。
3. 架構：Vue SPA 呼叫 API；Application 定義用例與介面，Domain 保存核心模型，Infrastructure 接 EF Core、郵件、AI 與背景工作。
4. 難題：挑一個自己真的做過的案例，優先選結帳一致性、安全、契約生成或測試。
5. 證據：測試層級、CI gate、錯誤碼或追蹤 ID。
6. 反思：展示版仍是單一 API 與 SQL Server，沒有正式 CD；若規模增加，再以量測決定拆分。

## 一條完整流程：建立訂單

```text
CheckoutPage
  -> typed openapi-fetch POST /api/v1/orders
  -> wrapper 加 Cookie、Antiforgery、Correlation ID
  -> OrdersController 解析會員/訪客並檢查 DB readiness
  -> CheckoutService 建立 actor scope 與 idempotency boundary
  -> EfCheckoutTransactionGateway 在同一 SQL transaction 重算價格、運費、優惠與庫存
  -> 建立訂單、快照、庫存保留、付款嘗試與 Outbox
  -> 回 201；同 key 同 payload 重播既有結果
```

這條流程能回答分層、DI、DTO、Authentication、交易、冪等、併發、Outbox、Problem Details、Typed Client 與整合測試。

## 常見追問

### 為什麼不直接做微服務？

展示版的團隊、部署與流量證據不足以支付分散式交易、網路失敗、服務觀測與部署複雜度。現階段以模組化單體和清楚依賴方向滿足需求；只有獨立擴展、故障隔離或團隊自治成為可量測瓶頸時才拆分。

### 四層各做什麼？

- Controller：HTTP 輸入、身分、狀態碼與錯誤格式。
- Application：編排用例、定義介面與交易語意。
- Domain：核心商業狀態與規則。
- Infrastructure：資料庫、SMTP、AI、檔案與背景工作實作。
