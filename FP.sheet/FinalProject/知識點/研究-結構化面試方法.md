# 研究：把 DoSelect 做成有效面試練習

## 研究問題

對準初階／畢業專題軟體工程職位，如何公平、可重複且可驗證地從 DoSelect 設計技術題、情境題與行為題？

研究日期：2026-09-09。範圍限面試方法與候選人練習，不替特定公司、職缺或面試官作法律判斷。

## 證據表

| 證據 | 來源 | 對教材的影響 |
|---|---|---|
| 結構化面試使用相同預定問題、共同尺度與可接受答案標準 | OPM 官方指南 | 固定題池與四級錨點，不憑聊得投緣評分 |
| 問題應由職務分析找關鍵 competency；情境/過往行為都貼近工作 | OPM assessment guidance | 依 API、安全、資料、前端、測試、協作分類 |
| Work simulation 讓候選人展示分析、排序、決策 | OPM hiring assessments | 加入結帳競態、provider 故障、CI 失敗情境 |
| STAR 聚焦情境、責任、行動、結果；Microsoft 建議 Reflection | Penn Career Services、Microsoft Careers | 行為題用 STAR(R)，要求個人行動與反思 |
| 台灣雇主不得以法定特徵歧視或要求非就業所需隱私 | 勞動部《就業服務法》第 5 條 | 題庫只問工作能力，提醒不適當問題界線 |

## 採用方法

1. 從 Repository 建 competency：端到端表達、後端/API、安全、資料、前端、測試交付、問題拆解、協作誠信。
2. 每項同時有知識題與工作情境，避免只背定義。
3. 行為題問真實事件；技術情境先釐清假設，再談 invariant、失敗、驗證。
4. 用 1～4 可觀察錨點；無 job analysis 支持加權時等權。
5. 模擬後只挑最低兩項重練，以錄音/筆記比較，不無限加題。

## 未採用方式

- 隨機「百大題庫」：與職缺、專案關聯弱，易變背誦。
- 只做自由聊天：自然但難比較進步，易受第一印象影響。
- 只考 LeetCode：能量部分演算法，不能單獨證明 Web 安全、資料一致性、除錯、協作；職缺若要求則另練。
- 只看 coverage/規模：數字不能證明個人貢獻與判斷。

## 專案推論

- 最有區辨力的工作樣本是建立訂單，橫跨 Vue、typed client、security、Application、EF transaction、庫存、冪等、Outbox。
- 安全題要把 CORS、Cookie credentials、CSRF、Antiforgery、authorization 串成流程。
- 目前沒有正式 CD，能指出限制本身是誠信與判斷證據。
- AI 題評估驗證、降級、evaluation、成本，不以會寫 prompt 當完整能力。
- Repository 無法推定個人 ownership，所以範本保留本人填寫欄位。
