# 30 天線性迴歸

## 用途

簡單線性迴歸可用最近一段時間的每日銷量估計趨勢，再外推短期需求。本專案第二批決策已確認「最近 30 天預測未來 7 天；不足 14 天不預測；負數歸零」。

它適合 Demo 與可解釋的基準模型，但無法自然處理週末效應、促銷、節慶、缺貨及突然爆量，不應描述成精準的 AI 預測。

## 資料定義

以單一 SKU 為例：

```text
x = 1..30                         // 日序
y = 每日有效淨銷售數量
觀察區間 = 報表時區中最近 30 個完整日
```

「有效淨銷售數量」必須與正式報表口徑一致，例如是否只算完成訂單、退款何時扣回。若商品當天已上架且沒有交易，該日通常應補 `0`；商品上架前或資料遺失的日期不能直接當成零銷量。

## 最小平方法

模型為：

```text
ŷ = a + bx
```

斜率與截距：

```text
b = Σ((xi - x̄)(yi - ȳ)) / Σ((xi - x̄)²)
a = ȳ - b x̄
```

未來第 `h` 天的預測：

```text
forecast(h) = max(0, a + b(n + h))
h = 1..7
```

每日預測可以保留小數供圖表及加總使用，最後呈現或補貨建議時才依明確規則取整，避免每天先四捨五入造成累積誤差。

## 建議計算流程

```text
查詢 SKU 的每日銷量
→ 依固定時區建立連續日期序列
→ 區分零銷量與無資料
→ 有效資料天數 < 14：回傳 InsufficientData
→ 取最近最多 30 天
→ 計算 a、b 與 7 日預測
→ 負數歸零
→ 保存模型輸入期間、口徑與產生時間
```

API 不應只回傳七個數字，可一併回傳：

```text
ForecastResult
├─ SkuId
├─ WindowStart / WindowEnd
├─ ObservedDays
├─ Slope / Intercept
├─ Forecast[7]
├─ GeneratedAt
├─ TimeZone
└─ Status / Warning
```

## 特殊情況

- 所有銷量相同時，斜率為 `0`，預測等於平均值。
- 新商品未滿 14 天時，不用零補滿 30 天來偽造資料量。
- 長期缺貨會壓低觀察銷量；預測的是「觀察到的銷售」，不是未受庫存限制的真實需求。
- 大型促銷會強烈影響直線；畫面應標示模型及觀察區間。
- 預測產生後若資料因退款或訂單狀態修正而變動，需重新計算或標記版本。

## 驗證方式

- 以固定小型資料集手算斜率、截距與預測值。
- 測試水平、上升、下降、全零、少於 14 天及缺日期資料。
- 驗證第 1～7 天索引沒有 off-by-one。
- 驗證負值只在輸出邊界歸零，不破壞原始模型參數。
- 用歷史資料回測：拿較早 30 天預測後 7 天，再量測 MAE 或 RMSE。

> [!warning] 專案決策邊界
> 30 天、7 天、14 天門檻及負數歸零目前來自 `drafting` 決策文件。銷量口徑、缺貨日與退款歸屬仍需在正式報表契約中明確定義。
