# 冪等性

## 它是什麼

冪等表示同一操作執行一次或重複執行，最終可見效果相同。網路逾時時，Client 往往不知道伺服器是「沒收到」還是「已完成但回應遺失」；沒有冪等設計，重試可能建立兩張訂單、扣兩次庫存或退款兩次。

HTTP 的 GET、PUT、DELETE 在協定語意上通常是冪等方法，但商業實作仍要遵守該語意。POST 建立或執行命令時，可用 `Idempotency-Key` 建立應用層防重。

## Key 不能單獨使用

伺服器應以「Actor Scope＋Operation＋Key」建立唯一範圍，並保存規範化 Request Hash：

- 同 Key、同 Hash：回放原結果。
- 同 Key、不同 Hash：409，拒絕誤用。
- 同 Key 尚在 Processing：回衝突及 `Retry-After`。
- Key 過期後：依契約視為新請求，Client 不應無限重用。

Actor Scope 必須由後端驗證的登入或訪客授權內容推導，不接受前端任意指定會員 ID。

## 回放與副作用

只保存「已見過 Key」不夠，還需保存安全的結果摘要或結果資源 PublicId，才能讓重送取得一致回應。外部副作用也需自己的去重鍵，例如金流 Provider Event ID、通知唯一工作鍵。

冪等不等於資料庫交易，也不等於樂觀併發：交易保證一組寫入一起提交；`rowversion` 偵測其他人修改；冪等性處理同一意圖的重複執行。

> [!note] 專案決策邊界
> 建立訂單與退款必須使用 `Idempotency-Key`，保存 24 小時；Processing 回 `409`＋`Retry-After: 3`，結果摘要上限 32 KB。完整欄位與 Actor Scope 見 [[03-架構/03-資料與一致性/資料一致性、Outbox與冪等設計]]。
