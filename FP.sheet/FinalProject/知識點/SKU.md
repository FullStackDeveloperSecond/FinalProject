# SKU（庫存單位）

## 什麼是 SKU

SKU 是 **Stock Keeping Unit** 的縮寫，是商家在自己系統內用來識別、定價及追蹤庫存的最小銷售單位。

以同一款記憶體為例：

```text
商品：KingFast Fury DDR5 記憶體
├─ SKU：16GB／黑色／單條
├─ SKU：32GB／黑色／雙條套件
└─ SKU：32GB／白色／雙條套件
```

「商品」承載共用名稱、品牌、描述及圖片；容量、顏色、套件數等會影響價格或庫存的組合，則各自成為 SKU。

## SKU Code、資料庫 ID 與條碼

三者用途不同，不應混為同一欄位：

| 欄位 | 用途 | 是否可對外顯示 |
|---|---|---|
| `SkuId` | 資料庫內部主鍵與關聯 | 通常不需要 |
| `SkuCode` | 商家自訂、可讀且穩定的業務識別碼 | 可以 |
| GTIN／EAN／UPC | 跨企業或掃碼使用的標準商品識別碼 | 視商品而定 |

SKU Code 是內部編碼，不等於全球唯一條碼。同一組織內應唯一，但不同商家可能使用相同文字。

## 編碼原則

好的 SKU Code 應符合：

- 唯一且不重複。
- 建立後原則上不可變，避免匯入、訂單及稽核失去對應。
- 不把售價、庫存數量或會頻繁改名的資訊編入代碼。
- 使用固定字元集合與長度限制，匯入時忽略前後空白並統一大小寫規則。
- 不回收已停用代碼給另一個 SKU。

例如 `RAM-KF-DDR5-32-BK-K2` 可以表達分類、品牌、世代、容量、顏色與套件，但實際規則應由團隊統一，不要讓每位管理員自由發明格式。

## 在本系統中的責任

SKU 是以下流程的共同邊界：

- 售價與特價。
- 實體在庫、保留庫存及可售庫存。
- 購物車項目與訂單明細。
- 組裝電腦中的個別零件。
- 退貨、退款、保固與銷售報表。

```text
AvailableQuantity = OnHandQuantity - ReservedQuantity
```

下單時應將 SKU Code、商品名稱、規格、成交價與成本等必要資訊複製到訂單快照。日後 SKU 改名、停售或刪除，不得改變歷史訂單的內容。

## 商品與 SKU 的狀態

商品可控制整體展示，SKU 則控制特定變體是否可買。常見判斷如下：

```text
商品已上架
AND SKU 已啟用
AND SKU 可售庫存 > 0
AND 沒有其他購買限制
→ 可以加入購物車
```

停售不等於刪除。已被訂單、庫存異動或退貨引用的 SKU 應停用並保留歷史，而不是實體刪除。

## 批次匯入注意事項

- 有 SKU Code 的資料可用來精確更新；空白代碼是否代表新增，須由匯入契約決定。
- 同一檔案出現重複代碼時應拒絕，不能以最後一列默默覆蓋。
- 先驗證整批資料，再依決策採整批交易或明確的部分成功策略。
- 匯出後再匯入時，SKU Code 應維持穩定。

> [!warning] 專案決策邊界
> 專案已確認 SKU Code 建立後不可變，Excel 以代碼精確比對；已被引用的 SKU 只能停用或下架，不能實體刪除。正式規則見 [[02-領域需求/商品、組裝與相容性]]。
