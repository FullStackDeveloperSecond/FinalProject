## 現行權威順序

1. 使用者後續明確確認且已寫入 [[05-規劃/03-需求與決策治理/決策紀錄]] 的覆寫決策。
2. [[00-專案概述/系統規格書總覽]] 指定的現行需求與架構文件。
3. [[05-規劃/03-需求與決策治理/需求追蹤矩陣]] 的需求、API、資料與測試回連。
4. `決策/02-已寫回`、凍結規格書及封存資料只供追溯，不單獨覆蓋現行規格。
5. 知識點、工程包、日誌、互動表單與外部原稿不構成新的產品規則。

## 文件維護原則

1. 每個主題只指定一份現行權威來源；其他文件使用摘要與連結，不複製整套規則。
2. 商業規則改變時，同步檢查需求、API、資料、測試與 Demo 影響。
3. 已寫回決策保留歷史；被取代時標示覆寫關係，不改寫當時紀錄。
4. 封存資料不得出現在現行進度或規格入口中。
5. 搬移或重新命名文件後，必須驗證 Obsidian Wiki Link 與程式內的規格來源引用。
