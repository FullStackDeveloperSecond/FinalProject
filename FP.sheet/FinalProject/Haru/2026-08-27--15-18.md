## 已裁定與外部依賴

### 1. A1：平行重寄 successor 識別碰撞（已裁定、已修正）

原 successor lookup 使用 `(EmailHash, OrderHash, ExpiresAtUtc)`；`ExpiresAtUtc` 在 SQL Server 為毫秒精度，相同訂單與 Email 若在同一毫秒建立兩條獨立 challenge chain，平行重寄輸家可能取到另一條 chain 的 Request ID。

- 2026-08-27 採用 A1：更新原 Challenge，並以同交易的獨立限流事件 Row 計數；successor lookup 已移除。
- API 與平行 HTTP 測試確認成功與 loser 回應都使用原 RequestPublicId，且只更新一次 Challenge／新增一筆限流事件。
- 無 Schema 或 Migration 影響。
