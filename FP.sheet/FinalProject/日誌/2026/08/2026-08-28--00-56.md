## 更改內容

補齊目前不依賴其他組員垂直功能的共用上游能力，並依 DEC-P322～P323 完成公開商品圖片內容定址與 Outbox 受控人工重送。沒有新增外部服務、付費項目或執行資料庫 Migration。

### 新增

- Backend、雙前端 Coverage 失敗門檻與 CI 收集。
- Customer Playwright 共用 API／身分／清理 fixture；前後台 Router Guard 與角色測試。
- Idempotency、Outbox、Audit、私有附件、商品圖片／暫存的批次清理 Job。
- SQL Backup／Verify、隔離 Restore、保留輪替與乾淨環境驗證腳本。
- `GET /media/products/{publicId}/{variant}/{contentHash}.webp`。
- `POST /api/v1/admin/outbox-messages/{publicId}/actions/retry`。
- Migration `20260828015922_AddProductImageVariantHashes`（以最新 `origin/dev` Snapshot 重新 Scaffold／Review，未套用）。

### 修改

- `ProductImage` 新增三個 Variant SHA-256 與發布前不變量。

- 正式 Endpoint、DTO、錯誤碼、權限、資料字典、背景工作、追蹤與決策文件同步。

### 刪除或淘汰

- 無。

## 定義與對外契約

| 項目 | 定義 |
|---|---|
| 公開圖片 Route | `GET /media/products/{publicId}/{variant}/{contentHash}.webp`；variant=`320/800/1600` |
| 圖片 Hash | 各 WebP 衍生檔自己的 SHA-256、URL 使用 64 字元 Hex；新圖三種 Hash 齊備後才能 Published |
| Outbox Route | `POST /api/v1/admin/outbox-messages/{publicId}/actions/retry` |
| Request／Response | `{reasonCode}` → `202 {publicId,status:"Pending",availableAtUtc}` |
| 必要 Policy | `Outbox.Retry`；完成 MFA 的 SuperAdmin |
| 可能錯誤碼 | `validation_failed`、`outbox_message_not_found`、`outbox_message_not_retryable`、`concurrency_conflict` |

### 必須維持的規則

- 公開圖片狀態、Hash 或實體檔任一不符都回 404。
- Outbox 只有 Failed 可人工重排；Payload 與 AttemptCount 不變。
- Outbox 狀態更新與 `outbox.retry` Audit 使用同一 DbContext／同次 SaveChanges。
- Hangfire Dashboard 持續唯讀，不可取代人工重送 API。
- Migration 由部署 Gate 明確套用，不得跟 API 啟動綁定。

## 相容性、風險與注意事項

- 既有資料保持相容；新程式部署前必須先依 Gate 套用 Migration。
- Migration `Down()` 會刪除新欄及部署後寫入的 Hash，因此事故回復優先停用新路徑或 roll forward。
- 本分支已 rebase 至 `origin/dev@5c31cd1`；重新產生的 `AddProductImageVariantHashes` 接在 `20260827153437_AddOrderShippingMethodBaseFeeSnapshot` 之後，Snapshot 保留上游運費快照欄位與檢查約束。定向 SQL 只有三個 nullable `binary(32)` 欄位加法；只在暫時測試資料庫驗證完整 Migration Chain，沒有更新開發資料庫。
- M-14B Provider-backed 測試不再使用共用 `DoSelectDb`；fixture 只建立唯一命名的暫時測試資料庫，套用目前 Migration Chain 以建立 `vw_CaseWorkbench`，結束時刪除。沒有對開發資料庫套用 Migration。
