## 更改內容

### 摘要

建立 `@doselect/web-shared` 單一共享來源，讓 customer-web 與 admin-web 使用一致的 HTTP、錯誤、TanStack Query 與非成功狀態規則；同時建立符合前台根路徑與後台 `/admin/` 基底的桌面 Layout 與 HTTP 狀態頁。未建立任何假商業 API Schema，也未加入資料庫或認證行為。

### 新增

- `frontend/shared` 本機 npm package。
- 共用 API Client、Correlation ID、Problem Details 與 Query Client。
- Loading、Empty、Error 與 HTTP 401／403／404／500 元件。
- 前後台 `.env.example` 與 generic API Client factory。
- 共用 API、狀態元件及後台 404 Router 測試。

### 修改

- 前後台 `main.ts` 使用明確 QueryClient。
- 前台加入 Header／Main／Footer 殼層；後台加入 Header／Sidebar／Main 殼層。
- 前後台 Router 加入非成功狀態路由與 Catch-all 404。
- Vite、Vitest 與 TypeScript 保留本機 package symlink，確保共用來源只維護一份。
- customer-web Lint 同時檢查 `frontend/shared`。

### 刪除或淘汰

- 無。

## 定義與對外契約

### 提供給其他模組的能力或資料

| 能力／資料 | 提供者 | 使用者 | 用途 |
|---|---|---|---|
| `createDoSelectClient<Paths>()` | `@doselect/web-shared/api` | 前後台各 feature API | 建立含 Credentials、Correlation、CSRF 邊界與錯誤處理的 typed client |
| `ApiError`／`ProblemDetails` | `@doselect/web-shared/api` | Page、Composable、Query | 使用 status、code、field errors 與 tracking ID 處理失敗 |
| `createDoSelectQueryClient()` | `@doselect/web-shared/query` | 前後台 `main.ts` | 統一查詢重試、stale time 與 Mutation 不重試規則 |
| 共用狀態元件 | `@doselect/web-shared/components` | 前後台頁面 | 顯示 Loading、Empty、Error 與 HTTP Status |

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | 本次未新增商業 API；API Base URL 由 `VITE_API_BASE_URL` 提供，預設 `http://localhost:5126` |
| Request DTO | 尚未產生；必須等待正式 OpenAPI `schema.d.ts` |
| Response DTO | 錯誤可解析 RFC Problem Details＋`code`／`traceId`／`correlationId`／`errors` |
| 後端介面／Application Service | 無 |
| 領域事件／整合事件 | 無 |
| 必要權限或 Policy | Router 與狀態頁不是授權邊界；正式權限仍由 API Policy 驗證 |
| 成功條件 | 2xx Response 交由 openapi-fetch 依正式 Schema 回傳 |
| 可能錯誤碼 | 未知狀態使用 `request_failed`；已知框架 Status 使用既定共通錯誤碼；正式領域 code 由 API 契約提供 |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `VITE_API_BASE_URL` | 絕對 HTTP／HTTPS URL | 是 | 缺少時使用 `http://localhost:5126`；不得含帳密、Query 或 Fragment |
| `X-Correlation-ID` | 1～64 ASCII 英數、`.`、`_`、`-` | 否 | 缺少或無效時前端產生 32 字元十六進位值 |
| `X-XSRF-TOKEN` | 記憶體 Token Provider 回傳字串 | 條件 | 只附加於 POST／PUT／PATCH／DELETE；不得持久化 |
| `ApiError.status` | number | 否 | 網路錯誤為 0，HTTP 錯誤使用 Response Status |

### 必須維持的規則

- 共用 wrapper 使用 `credentials: include`。
- Mutation 不自動重試；Query 只對網路或 5xx 失敗重試一次。
- `onApiError` 只提供一致錯誤事件，不負責 Router、Toast 或業務文案。
- 產生的 OpenAPI Schema 不可手改；目前尚未形成正式商業契約，因此不得手寫假 Paths。
- 401／403／404／500 元件不得顯示 Stack Trace、SQL 或內部例外。

### 禁止或不建議的取用方式

- 不得在 customer-web 或 admin-web 再建立另一套 Fetch／Problem Details／Correlation ID wrapper。
- 不得將 Cookie、Antiforgery Token 或個資存入 localStorage／sessionStorage。
- 不得以 Router Guard 或隱藏按鈕取代 API 授權。
- 不得對非冪等命令啟用自動重試。

## 相容性、風險與注意事項

- 相容性影響：兩個應用新增本機 file dependency；Fresh Clone 仍各自執行既有 `npm ci`，不新增第三次安裝。
- 已知風險：尚無正式商業 OpenAPI Schema，generic factory 尚未有業務路徑可呼叫；Antiforgery Token Provider 也等待 SH-05。
- 回復方式：移除兩個 package 的本機 dependency 與 shared 引用即可回到原始空殼；不涉及資料回復。
- 需要其他負責人配合：各 feature 必須重用 shared API／Query／狀態，不建立平行基礎；Identity 負責人後續提供 Session 與 Antiforgery 契約。
