## 更改內容

### 摘要

本 PR 原本同時帶著計算規則與一個 Schema 變更，導致 EF 模型漂移、CI 的「Apply database migrations」步驟失敗。依 `DEC-BATCH-022`／`DEC-P300` 把 Schema 變更抽離，讓本 PR 回到「計算規則與 Coupon 生命週期」的單一責任。

### 修改

- `DoSelect.Domain/Promotions/PromotionEntities.cs`
  - 移除 `OrderCoupon` 建構子的 `minimumSpendAmount` 參數、負值檢查、指派與 `MinimumSpendAmount` 屬性。
- `DoSelect.Infrastructure/Persistence/Configurations/Promotions/PromotionConfigurations.cs`
  - 移除 `MinimumSpendAmount` 的精度設定與 `CK_OrderCoupons_Amounts` 中的對應條件。本檔案現在與 `dev` 逐字相同。
- `tests/DoSelect.Domain.Tests/CouponLifecycleTests.cs`
  - 移除三條 `OrderCoupon.MinimumSpendAmount` 的快照測試，並在原處留下註解說明它們去了哪裡。

### 未修改

`Coupon.MinimumSpend`（優惠券本身的門檻規則）不受影響。那是既有欄位，與本次移除的 `OrderCoupon.MinimumSpendAmount`（套用當下的快照）是不同的東西。`CouponCalculator` 的門檻判斷邏輯完全保留。

## 必須維持的規則

- 功能 PR 不得夾帶 EF 模型變更。Entity、Configuration、Migration、ModelSnapshot 與 Provider-backed 驗證必須在同一支 Migration PR 一次交付（DEC-P300）。
- `dotnet ef migrations has-pending-model-changes` 必須回報無變更，否則 CI 的 migration 步驟會失敗。
