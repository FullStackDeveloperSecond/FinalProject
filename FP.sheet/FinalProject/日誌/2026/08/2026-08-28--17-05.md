## PR #29（購物車前端）第七輪修正

| 項目 | 問題 | 修正 |
|---|---|---|
| P1-1 | `BuildCartDto` 把 `AssemblyFee` 寫死 `0m`，`TotalEstimate` 只有商品小計，畫面總額必定少算每台 NT$300 | 新增 `DoSelect.Domain.Builds.AssemblyPricingPolicy.FeePerUnit` 單一定義供 BuildList 與 Cart 共用；改以「相異且非 null 的 `AssemblyGroupKey` 數量 × 300」計費並納入總額 |
| P1-2 | 組裝群組禁止逐項編輯後，沒有任何整組移除路徑，群組 SKU 一旦下架就永久卡住結帳 | 依 M 級自行定案最小 API（AUTO-DEC-015），新增 `DELETE /api/v1/cart/assembly-groups/{key}`，單一 `SaveChangesAsync` 內移除整組；Revalidate 對組裝品項改回 `["remove-group"]`；前端提供「整組移除」單次原子呼叫 |
| P1-3 | `sessionStore.refresh()` 失敗會把狀態設成 `anonymous`，與「確認未登入」無法區分，會員 Cart 可能被寫進 Guest cache | 新增 `'error'` 狀態與 `isIdentityConfirmed`，refresh 失敗 fail closed；Cart query 與所有 mutation 改以 `isIdentityConfirmed` 把關；三個頁面顯示「無法確認登入狀態」與重試入口 |

## PR #35（組裝清單與相容性前端）第三輪修正

| 項目 | 問題 | 修正 |
|---|---|---|
| P1-1 | 警告門檻草稿只存值，`rowVersion` 送出時才從畫面現值讀取——refetch 後會用「舊的值」配「新的 rowVersion」，樂觀鎖等於失效 | 草稿改記 `baseValue`／`baseRowVersion`；乾淨草稿靜默同步、已編輯草稿顯示衝突並停用送出，另提供「重新載入最新值」 |
| P1-2 | 前端未套用後端 `MergeAndValidateItems` 的同一組規則（同 SKU 合併、1–8、1–20） | 重複挑同一 SKU 改累加既有列；數量夾在 1–8；新增共用 `validateBuildItems` 供新增頁與編輯頁把關並顯示欄位錯誤；儲存成功後以 server response 重設 baseline |
| P2-3 | `/account/builds` 與 `/builds/:buildId` 未要求登入；admin 的 `/catalog/compatibility` 完全沒有 route meta | 兩處補 `requiresAuth`；admin route 補 `requiredRoles`，頁面內另依 SuperAdmin 隱藏啟停控制 |
| P2-4 | 測試工具草稿門檻無效時靜默丟棄，輸入框仍顯示原值，管理員拿到的是「以實際值跑出來」的結果卻以為是草稿結果 | 輸入改受控並顯示行內錯誤，無效時停用「執行測試」 |
| P2-5 | Vue Router 在只換路由參數時不重新掛載元件，`/builds/A→B`、分享連結互換都會殘留前一份狀態 | 兩頁分別監看 `buildId`／`shareToken` 重置本地狀態；分享頁的 sessionStorage key 改為 computed |
| P2-6 | 前後台直接把 `messageKey` 顯示給使用者 | 新增共用 `@doselect/web-shared/compatibility` 翻譯模組，兩邊都改顯示 zh-TW 敘述 |

## 送出前文件自我審查（本次新增的固定流程）

依指示，本輪起「送 PR 給組長」與「組長要求修正」兩種情況都必須先對照專案文件做整體自我審查，
而非只修改留言指到的行，目的是降低每個 PR 的往返輪次。兩支分支各跑一次，結果如下。

### 因此發現的程式碼缺陷（非組長留言項目）

- `messages.ts` 少了 `compatibility.cpu_socket_mismatch` 的 `PLAIN_LABELS` 退路：facts 缺漏或型別
  不符時會把 raw key 顯示給使用者，正是該模組要防的事，且發生在最主要的規則上。已補上並加一支
  涵蓋全部 24 個 key 的回歸測試，未來只加到其中一個 map 會直接失敗。
- 後台測試工具沒有實作文件明訂的 `items` 1～20 上限（只擋了 1–8 數量），與 customer-web 不對稱。
- `SharedBuildPage` 只顯示 `grandTotal`，未如文件把組裝費列為明確項目，改為三行拆解。

### 因此補齊的契約文件

| 文件 | 缺口 |
|---|---|
| `API Endpoint目錄.md` | 缺 PR #29 新增的 assembly-group 移除端點與 `remove-group` 語意 |
| `API DTO與Schema契約.md` | `CartWarningDto` 被引用卻無欄位定義；`RemoveCartItemRequest`／`RemoveAssemblyGroupRequest` 完全未記載 |
| `API共通規範.md` | `X-DoSelect-Guest-Cart-Key` 在任何文件都沒出現過 |
| `資料字典-購物交易與售後.md` | 30 天購物車存活期只是口頭裁定，從未寫進文件 |
| `相容性規則後台設計.md` | 全文只有一個 messageKey 範例，沒有目錄 |
| `商品、組裝與相容性.md` | 8 個 Category Code 與「可多選」未記載；規則清單漏列 `psu_form_factor_unsupported` 與五項警告級結果 |
