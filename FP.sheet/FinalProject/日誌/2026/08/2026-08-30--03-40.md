## 兩個把後端規則帶到介面上的地方

### 1｜百分比是比例，不是百分點

Domain 的 `RequireWellFormedRule` 限制百分比折扣的 `DiscountValue` 必須落在 0～1。
但表單讓管理員填「10」比填「0.1」自然得多，所以：

- **顯示**時乘 100（`0.1` → `10%`）
- **送出**前除以 100（填 `10` → 送 `0.1`）

兩個方向都有測試釘住。少做任一邊都會直接被 Domain 拒絕，或顯示成「一折」。

### 2｜不提供必然失敗的按鈕

`availableActions` 與後端 `EfAdminCouponService.ActivateAsync` 逐項對應：

| 狀態 | 可用動作 |
|---|---|
| `draft`、`paused` | 啟用、停用 |
| `active` | 暫停、停用 |
| `scheduled`、`exhausted` | **只有停用** |
| `expired`、`disabled` | 無（終態） |

`scheduled → active`（到達開始時間）與 `exhausted → active`（名額返還）是**系統事件**，
後端會以 `coupon_state_conflict` 拒絕管理員的 activate。介面上不提供那個按鈕，
但這**不是安全邊界** —— 後端仍然會擋，前端只是不要讓人按一個必然失敗的鍵。

## 測試抓到一個真的 bug

`converts the percentage input back to a fraction` 這條第一次跑就炸：

```
TypeError: value.trim is not a function
  at optionalNumber (AdminCouponsPage.vue:126)
```

原因是 **Vue 的 `v-model` 綁在 `<input type="number">` 上會自動把值轉成 number**，
而我把表單狀態全宣告成 `string` 並直接呼叫 `value.trim()`。

**這不是測試環境的問題** —— 使用者只要在最低消費、總名額等任何一個數值欄位填了東西，
按下儲存就會炸。型別宣告改成 `string | number`，`optionalNumber` 同時處理兩種。

## 必須維持的規則（新增）

- **`v-model` 在 `type="number"` 上會回 number。** 表單狀態不能一律宣告成 `string`。
- **單位換算要兩個方向都測。** 只測顯示或只測送出，另一邊壞掉不會被發現。
