依序處理組長對 PR #34、PR #28、PR #24 的最新靜態 re-review，三個 PR 都已推送修正並留言請組長複審。

### 新增

### 修改

- **PR #34**：`EfBuildListService.RequiredComponentCategoryCodes` 改為 `BuildComponentCategoryCodes.All`（原本只檢查 5 類，缺顯示卡／儲存裝置／散熱器）。
- **PR #28**：
  - `EfCartService.ResolveConflictsForSkuAsync` 排除 `cart_item_limit_exceeded` 這種 cart-level 衝突，避免被會員修改／移除該 SKU 誤解除。
  - `RejectMergeForItemLimitAsync` 的 `IdempotencyResponse.StatusCode` 改成 409；`ICartService.MergeAsync` 回傳型別改為完整 `IdempotencyExecutionResult<CartMergeResultDto>`，`CartController.Merge` 改用 `StatusCode(result.StatusCode, result.Body)`，讓拒絕合併真的回 409（原本狀態碼被丟棄，永遠回 200）。
  - `BuildItemsAsync` 對 `cart_item_limit_exceeded` 改用專屬 issue code 與「釋放空間後重新合併」指引，不再套用一般衝突的「調整數量」文字。
  - `git rebase origin/dev`（12 commit，零衝突，含已合併的 PR #23）。
- **PR #24**：
  - `feature/catalog-frontend` rebase 到最新 `dev`（PR #22／#23 皆已合併）。
  - `ProductEditPage.vue`：品牌／分類／標籤 lookup 拿掉 `isActive:true` 篩選、pageSize 拉高到 500，`watch` 改成同時監看四個查詢來源，儲存鈕在 lookup 未完成前停用。
  - `SkuEditorRow.vue`：`startEdit`／`cancelEdit` 改為每次都從最新 `props.sku` 重建表單狀態。
  - 前台 `ProductsPage.vue` 補價格區間與白名單規格篩選；`ProductDetailPage.vue` 補圖片／配送限制／保固月數；後台 `ProductsPage.vue` 補價格區間欄。
  - 品牌／分類／標籤管理頁補分頁狀態與控制；`CategoriesPage.vue` 的上層分類選單改用獨立完整清單查詢。
  - 路由調整為符合契約：`/products/:id/edit` → `/products/:productId`；`/brands`、`/categories`、`/tags` 合併為 `/catalog/lookups`。

| 項目 | 定義 |
|---|---|
| `cart_item_limit_exceeded`（merge 情境） | 409，`conflicts[0].reason` 帶此碼；訪客購物車維持 Active，需釋放會員購物車空間後以新 Idempotency-Key 重新合併才會解除 |
| Admin 路由 | 依 `M功能桌面UI與Route規格.md`：商品編輯 `/admin/products/:productId`；型錄管理 `/admin/catalog/lookups` |

- Admin 路由不可再自行拆回三個獨立頁面路由，需維持單一 `/catalog/lookups` 契約。
