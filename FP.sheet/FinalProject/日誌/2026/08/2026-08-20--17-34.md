# 開發日誌

實作 `DEC-BATCH-016`（`DEC-P283`～`DEC-P284`）定版的兩個後台授權 Policy。

決策文件的「實作 Gate」明確寫明該批**只完成規格，不代表 Policy 常數、註冊、Controller 套用或測試已完成**，
並把 `Coupon.Manage` 併入 `DES-21`、`Invoice.Manage` 併入 `DES-22`，負責人為 yinyin、alex 覆核。
因此本次由本模組實作，沿用 alex 既有的 `AddAdminPolicy`，不自建授權機制。

## 更改內容

### 修改

- `DoSelect.Api/Security/DoSelectSecurityConstants.cs`
  - `DoSelectPolicies` 新增 `InvoiceManage = "Invoice.Manage"`、`CouponManage = "Coupon.Manage"`。
- `DoSelect.Api/Security/SecurityServiceCollectionExtensions.cs`
  - `Invoice.Manage`：`FinanceManager`、`SuperAdmin`。
  - `Coupon.Manage`：`FinanceManager`、`MarketingAnalyst`、`SuperAdmin`。
  - 兩者都透過既有 `AddAdminPolicy`，因此自動繼承管理員 Scheme、`RequireAuthenticatedUser`、
    管理員帳號類型宣告與 **TOTP／MFA 宣告**。

### 新增

- `tests/DoSelect.Api.IntegrationTests/AdminPolicyTests.cs`：11 個測試。

## 必須維持的規則

- **Policy 只負責授權。** 狀態驗證、冪等、RowVersion、金額與名額規則、Audit 仍由各 Use Case 負責。
- `SuperAdmin` 不另設專屬 Policy，由兩個 Policy 各自包含。
- **`Coupon.Manage` 不適用於前台購物車套券。** 前台 `POST`／`DELETE /api/v1/cart/coupon` 不得套用此 Policy。
- V1 不拆分 View／Write／Lifecycle 或 View／Issue／Void／Allowance 粒度。

## 測試與驗證

| 驗證項目 | 結果 |
|---|---|
| 零警告建置 | 通過，0 警告 0 錯誤 |
| Solution Test | 通過 285／285 |
| API 整合測試 | 通過 53／53（含本次新增 11 項） |
| Format Verify | 通過 |

測試以 `IAuthorizationPolicyProvider` 直接檢查 Policy 契約，不需要端點：

- 兩個 Policy 皆已註冊。
- 使用管理員 Scheme 且拒絕匿名。
- 要求管理員帳號類型與 **MFA 宣告**。
- `Invoice.Manage` 只允許 `FinanceManager`、`SuperAdmin`。
- `Coupon.Manage` 另外允許 `MarketingAnalyst`。
- `SuperAdminIsCarriedByEachPolicyRatherThanADedicatedOne`：對應 DEC-P283／P284 的「不另設專屬 Policy」。
- `CouponManageDoesNotGrantTheStorefrontCartPolicy`：管理員 Policy 與會員 Scheme 互不重疊。
- `TheManagementPoliciesMatchTheRefundBaselineApartFromRoles`：與 `Refund.Execute` 除角色外契約一致，
  證明確實沿用同一基線而非另建。
