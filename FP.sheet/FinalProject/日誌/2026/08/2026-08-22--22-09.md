## 更改內容

### 摘要

依組長對 PR #28 的最新一輪 review，rebase `feature/cart-api`到已合併 PR #32（共用冪等基礎設施）的 `dev`，移除本分支自建、從未產生 migration 的 `IdempotencyRecord`，改用共用 `IIdempotencyExecutor`；合併衝突改為持久化並持續阻擋 Checkout；合併流程的 SKU／庫存查詢改成批次讀取。

### 新增

- `EfCartService.MergeAsync` 改為透過 `IIdempotencyExecutor.ExecuteAsync` 執行，商業邏輯移入 handler，在 Executor 自己的交易內完成。
- 合併衝突（數量超過 99）持久化為 `CartMergeConflict`；`GetCart`／`Revalidate` 之後每次讀取都會顯示（`warnings[]`／`issues[]`），`isCheckoutReady` 在未解決前維持 `false`。
- `ResolveConflictsForSkuAsync`：會員對衝突品項改數量或移除時，標記對應 `CartMergeConflict` 為已解決。
- `ExecuteMergeAsync` 迴圈前一次性批次查出所有訪客項目涉及的 `Sku`／`InventoryBalance`，取代逐項查詢。
- Service 層 3 個新測試（合併衝突持久化並持續阻擋 Checkout、改數量/移除品項後解除阻擋）；API 層 3 個新測試（重放快取結果、payload 衝突 409、HTTP 全流程的衝突持久化與 Checkout Gate）。
- `CartApiFixture` 新增 `Idempotency__ActorScopePepper` 環境變數覆蓋（沿用既有 env-var-only override 慣例）。

### 修改

- `EfCartService` 全面改寫：建構子改吃 `IIdempotencyExecutor`；Actor Scope 改用後端驗證後查出的 `User PublicId`（從已驗證 Identity Id 查資料庫，不接受前端傳入範圍值）。
- `global.json` SDK 沿用 rebase 帶入的 10.0.303 基準線。

### 刪除或淘汰

- `DoSelect.Domain.Idempotency.IdempotencyEntities.cs`、`Infrastructure/.../Idempotency/IdempotencyConfigurations.cs`（本分支自建、從未 migration 的舊版）。
- `ShoppingWriteException.ErrorCodes.IdempotencyPayloadConflict` 與其 Mapper 映射（改由 `GlobalExceptionHandler` 統一把 `IdempotencyConflictException` 轉 409）。
- `EfCartService` 內的 `HashUtf8`、`ReserveIdempotencySlotAsync`、`IdempotencyReservation`、`GetAvailabilityConcernAsync` 死代碼。

## 定義與對外契約

### 提供給其他模組的能力或資料

| 能力／資料 | 提供者 | 使用者 | 用途 |
|---|---|---|---|
| `ICartService.MergeAsync` | Infrastructure（本次改寫） | Checkout／登入流程（haru，尚未串接） | 訪客購物車登入合併進會員購物車，含衝突偵測 |

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `POST /api/v1/cart/actions/merge`（路由本身無變動，僅內部實作改寫） |
| 後端介面／Application Service | `IIdempotencyExecutor.ExecuteAsync<T>`（消費 PR #32 契約，非本次新增） |
| 必要權限或 Policy | 需已驗證會員身分；Actor Scope 用查資料庫取得的 User PublicId |
| 成功條件 | 冪等鍵重放回同一結果；同鍵不同 payload 回 409 `idempotency_payload_conflict` |
| 可能錯誤碼 | `idempotency_payload_conflict`、`idempotency_request_in_progress`（皆由 `IdempotencyConflictException` 觸發） |

### 必須維持的規則

- CartMergeConflict 在會員明確對該品項改數量或移除之前，必須持續顯示並阻擋 Checkout；轉換訪客購物車不得讓衝突靜默消失。
- Pepper 只能從 `Idempotency:ActorScopePepper` 設定讀取，不得寫死或由前端提供。
