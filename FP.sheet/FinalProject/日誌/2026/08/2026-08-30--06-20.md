## C1｜我的訪客雜湊是錯的，而且我寫測試把它釘住了

`DEC-P262` 與優惠券規則明定：訪客每人限制以伺服器 Secret 對**正規化訂單 Email**
計算 HMAC-SHA-256。我用的是 `SHA256(guestCartKey)`。

購物車預覽階段沒有訂單 Email，正確做法是 `GuestUsageKeyHash` 傳 `null`：
預覽只檢查總名額，每人次數由 Checkout 取得 Email 後權威重驗。
`CouponRuleReader` 在兩種身分皆為 null 時讓 owner count 維持 0，正好是這個語意。

**我的理由本身是錯的。** 我寫「必須與 Checkout 一致」，但 Checkout 目前用的就是
錯的做法 —— 那是既有上游偏差，alex 要另案修正。

我不只複製了那個錯誤，還加了一條測試把它固定下來。那條測試不是保護，是負債：
之後有人照規格改對，它會變紅，看起來像「改壞了」。

已移除，改成斷言預覽**不送任何訪客身分**。

## B1｜四種券有兩種在購物車試算是壞的

`CouponCalculator` 對 `FreeShipping`／`AssemblyFreeShipping` 回傳的
`DiscountAmount` **固定是 0**，真正結果在 `IsFreeShipping`／`IsAssemblyFreeShipping`。

我的服務只取 `DiscountAmount`，兩個旗標都丟掉 —— 免運券會顯示「套用成功」但折扣
0 元、總額不變，回應也沒有任何欄位能讓前端知道免運成立。

已擴充 `CouponAppliedDto`：

```csharp
public sealed record CouponAppliedDto(
    string Code,
    decimal DiscountAmount,
    bool IsFreeShipping,
    bool IsAssemblyFreeShipping);
```

同步更新 `API DTO與Schema契約`、重產 OpenAPI 與 typed client，並補四種券各自的測試。
購物車階段不一定有確切運費，所以免運券不改 `totalEstimate`，但資格必須表達出來。

## A1｜第二次讀取的競爭窗口

這個 Use Case 讀兩次：先用讀取埠取計算列，最後再用 `ICartService` 取回應用的
`CartDto`。兩次之間購物車若被另一分頁修改、合併或逾期重建，就會把**舊計算列算出的
折扣疊到新購物車的金額上**。

已在第二次讀取後比對 `PublicId` 與 `RowVersion`，任一不符回 `concurrency_conflict`。

兩個都要比：合併或逾期重建會換掉整個購物車，那時 RowVersion 來自另一列，比它沒有意義。

alex 也指出 `CartPublicId` 已經在讀取埠契約裡卻一直沒被用到 ——
**契約裡有一個沒人用的欄位，本身就是個訊號。**

## D1｜請求驗證漏了

`[Required, StringLength(64, MinimumLength = 1)]` 與 `[RowVersionRequired]`
我確實寫了，但寫在**留在本機、沒進這支 PR 的 Controller** 裡。Application 層的
`ApplyCartCouponRequest` 完全沒有驗證。

已加到 Application 層的 record 上。缺漏或畸形的 RowVersion 現在會在 transport
邊界回 400 `validation_failed`，不會被 Application 誤判成 409。

## 測試

由 10 條增為 16 條，新增：

| 測試 | 證明 |
|---|---|
| `DoesNotIdentifyAGuestForThePerPersonLimit` | 預覽不送訪客身分（取代先前釘住錯誤做法的那條） |
| `SurfacesAFreeShippingCouponAsAnEntitlementNotAZeroDiscount` | 一般免運與組裝免運各自的旗標 |
| `LeavesTheFreeShippingFlagsOffForAnAmountCoupon` | 固定金額與百分比不會誤設旗標 |
| `RejectsACartThatChangedBetweenTheTwoReads` | RowVersion 變動回 409 |
| `RejectsADifferentCartEvenWhenTheRowVersionMatches` | PublicId 變動也回 409 |

寫測試時踩到一個 Domain 規則：**百分比折扣必須設 `MaximumDiscount`**，
否則 `ResolvePercentageAmount` 回 null、整張券被判 `coupon_invalid`。
