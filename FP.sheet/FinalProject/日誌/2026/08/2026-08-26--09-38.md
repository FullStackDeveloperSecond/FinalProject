## 更改內容

### 摘要

補上 Orders 模組中唯一還沒有人做的缺口——後台訂單管理：新增 `AdminOrdersController`（列表／詳情／收件資料／狀態轉移 Action）與對應 Application／Infrastructure 實作，以及 admin-web 的訂單列表／詳情頁面。Domain Entity 與 EF Schema 沿用既有基線，未新增 Migration。

- `DoSelect.Application/Orders/AdminOrderContracts.cs`：`AdminOrderSummaryDto`／`AdminOrderDto`／`OrderStatusHistoryDto`／`OrderRecipientDto`／`AdminOrderQuery`／`IAdminOrderService` 等。
- `DoSelect.Application/Orders/AdminOrderWriteException.cs`。
- `DoSelect.Infrastructure/Orders/EfAdminOrderService.cs`、`AdminOrdersServiceCollectionExtensions.cs`。

- 前端：`frontend/admin-web/src/features/orders/`（`api.ts`、`queries/useAdminOrders.ts`、`pages/OrderListPage.vue`、`pages/OrderDetailPage.vue`），`router/index.ts` 新增 `/orders`、`/orders/:publicId`，`HomePage.vue` 加入導覽連結。

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `GET /api/v1/admin/orders`、`GET /api/v1/admin/orders/{id}`、`GET /api/v1/admin/orders/{id}/recipient`、`POST /api/v1/admin/orders/{id}/actions/{actionName}` |
| Request DTO | `AdminOrderActionRequest{ reasonCode?, note?, rowVersion }`；查詢用 `summaryStatus[]`、`badge[]`、`cursor`、`pageSize` |
| Response DTO | `CursorPage<AdminOrderSummaryDto>`、`AdminOrderDto`、`OrderRecipientDto` |
| 後端介面／Application Service | `IAdminOrderService`（`DoSelect.Application.Orders`） |
| 領域事件／整合事件 | 無（狀態轉移寫入既有 `OrderStatusHistories`，未新增 Outbox 事件） |
| 必要權限或 Policy | `DoSelectPolicies.OrderManage`（`OrderManager`／`SuperAdmin`，需 MFA） |
| 成功條件 | 200／202 依端點；Action 成功回傳更新後的 `AdminOrderDto` |
| 可能錯誤碼 | `validation_failed`(400)、`authentication_required`(401)、`authorization_forbidden`(403)、`resource_not_found`(404)、`order_state_conflict`(409)、`order_cancellation_not_allowed`(409)、`concurrency_conflict`(409) |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `actionName` route 參數 | string | 否 | **不要叫 `action`**——ASP.NET Core 對此有隱性 Action 選取衝突，實測會靜默 404，已改名並在 Controller 留下註解 |
| `summaryStatus` | `awaitingShipment/shipped/completed/cancelled` | 可空（不篩選） | 由既有五狀態衍生，未落地新欄位 |
| `badge` | `partiallyRefunded/refunded/paymentOverdue` | 可空 | 同上 |
| `AdminOrderActions` | `startProcessing/cancel` | — | 只開放狀態機文件確認由管理員直接觸發的兩個轉移，見下方「待確認」 |

### 必須維持的規則

- Cancel Action 目前只更新 `Order.OrderStatus` 與寫入 `OrderStatusHistories`，**不釋放庫存、不建立退款交易**（見下方「未完成與後續工作」）。
- 收件資料需另呼叫 `GET .../recipient`，不內嵌在列表／詳情主體中（依 UC-ADM-ORDER-02）。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- Cursor 只編碼 `CreatedAtUtc`，不要假設它可還原成排序用的穩定鍵以外的用途。
