## 更改內容

- Customer Web 與 Admin Web 的 `package.json` 使用精確 `"vue-demi@0.14.10": true` 核准必要腳本，並以名稱型 `"fsevents": false` 明確拒絕 macOS 選擇性相依腳本。
- 初版 Repository 根 `.npmrc` 不會被兩個子專案的 `npm ci` 讀取；依組長採用的修正，改由 Customer Web 與 Admin Web 各自保存專案層級 `.npmrc`，兩端有效 `strict-allow-scripts` 均為 `true`。
- Package 來源驗證器要求兩份專案層級設定都存在，拒絕其他位置的 `.npmrc`、關閉嚴格模式與 `dangerously-allow-all-scripts=true`，並要求每個核准鍵為精確 `package@version` 且值為 `true`。
- 自我測試涵蓋非官方 NuGet、非官方 npm Lock、必要 `.npmrc` 缺少、額外 `.npmrc`、關閉嚴格模式、危險全域允許、非版本化核准及版本限定拒絕八類拒絕路徑。
- Windows PowerShell 5 執行拒絕 Fixture 時暫時以 `Continue` 收集子程序的預期 stderr，仍以非零 Exit Code 判定拒絕成功；完成後立即恢復原 `ErrorActionPreference`，不忽略驗證失敗。
- `glob@10.5.0` 目前只存在於開發測試相依鏈，依 DEC-P303 保留並設定重評條件，不使用跨主要版本 Override。
- PR #41 依 DEC-P306 維持目前基底；Review 完成且準備合併時才依既定流程 Rebase 最新 `origin/dev`、重跑 CI、Squash Merge，不 Bypass。
