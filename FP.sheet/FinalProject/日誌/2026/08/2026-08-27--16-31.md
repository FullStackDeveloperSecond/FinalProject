## 更改內容

### 摘要

延續 PR #34 round 4 剩餘工作並推送後，Backend CI 因分支終於變成 `MERGEABLE` 而首次真正跑完，隨即失敗；追查後發現是 3 個測試 fixture 把 CI 提供的 SQL Server 連線字串清成 `null`（而非還原原值），導致同一測試流程中後面的 fixture 連不到 CI 的容器化 SQL Server。同一時間組長也給出 round 5 的完整 review（3 項 P1/P2 finding，另有 1 項 Audit 邊界問題留待他自己裁定），一併處理：Product 分類變更保護擴及新的相容性資料表、Retention 查詢補上日期前導索引。過程中 `dev` 前進兩次（PR #38、PR #42 M-12 退貨），共 rebase 兩次，最終 Backend／CI Required 全綠，這是本 PR 自建立以來第一次 CI 真正跑完且全數通過。

### 新增

- `Sku.Touch(DateTime)`（Domain，比照既有 `Product.Touch`）
- `EnvironmentOverrideScope`（測試共用 `IDisposable`，取代 5 個 fixture 各自複製貼上的環境變數存取邏輯）＋ 3 個單元測試證明還原行為
- `ProductCategoryChangeCompatibilityGuardTests.cs`（3 個 SQL Server 測試：既有 attributes/storage ports 時拒絕改分類、併發競速時只有一方成功）
- Migration `20260827075322_AddCompatibilityCheckRunsEvaluatedAtUtcIndex`（新增索引 `IX_CompatibilityCheckRuns_EvaluatedAtUtc_Id`）
- `PurgeExpiredRunsAsync` 相關 2 個新測試（索引對應的 SQL 斷言、同時間戳多筆的批次穩定性）
- `GET /api/v1/admin/compatibility-rules/skus/{skuPublicId}/attributes`（round 4 收尾項目）

### 修改

- `EfSkuCompatibilityAttributeAdminService`：併發控制改用 Sku＋Product 共用 RowVersion 邊界；新增分類白名單、系統代碼正規化、長度與重複值驗證

- `contracts/openapi.v1.json`、`frontend/shared/src/api/generated/schema.d.ts`：用真實跑起來的後端重新產生 2 次

## 定義與對外契約

| 能力／資料 | 提供者 | 使用者 | 用途 |
|---|---|---|---|
| `GET/PUT /api/v1/admin/compatibility-rules/skus/{skuPublicId}/attributes` | Builds 模組 | 後台管理介面（尚無前端頁面消費） | SKU 相容性屬性／儲存介面埠的正式管理讀寫路徑 |

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `GET`/`PUT /api/v1/admin/compatibility-rules/skus/{skuPublicId}/attributes` |
| Request DTO | `SetSkuCompatibilityAttributesRequest`（`attributes`、`storagePorts`、`rowVersion`） |
| Response DTO | `SkuCompatibilityAttributesDto`（含 `rowVersion`） |
| 必要權限或 Policy | `CompatibilityRuleView`（GET）／`CompatibilityRuleManageWarnings`（PUT） |
| 成功條件 | 分類白名單、正規化、長度、重複值皆通過，且 Sku／Product RowVersion 未過期 |
| 可能錯誤碼 | `validation_failed`、`concurrency_conflict`、`resource_not_found` |

### 必須維持的規則

- 寫入前必須先 `GET` 取得最新 `rowVersion`，`PUT` 為全量替換語意，不是差異合併。
- attribute key／storage ports 只能寫到各自對應的單一 `BuildComponentCategoryCodes`，跨分類寫入一律拒絕。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：無

## 相容性、風險與注意事項

- 相容性影響：`PUT .../attributes` 回應型別變更（204→200+DTO），但尚無前端消費，無實際相容性風險。
- 已知風險：本輪修正的 CI 環境變數洩漏問題（fixture 把連線字串清成 `null`）在本機完全無法重現——因為本機 `.\SQL2025` 剛好是真實存在的 named instance，退回預設值也連得上；只有 Linux CI runner 上才會真正炸開。往後新增 `WebApplicationFactory` fixture 若需要覆寫環境變數，務必用共用的 `EnvironmentOverrideScope`，不要自己重新實作還原邏輯。
- 回復方式：兩個 Migration 皆為新增（表／索引），如需回復可用各自的 `Down()`。
