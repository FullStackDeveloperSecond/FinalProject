## 更改內容

### 摘要

PATH 原先解析到 ODBC 17 的舊 `sqlcmd.exe`，在受限程序及目前環境回報加密／SSPI 失敗。系統已安裝 ODBC Driver 18 與新版 sqlcmd；共用腳本現優先使用其固定工具路徑，並以 `-C` 對齊本機 `TrustServerCertificate=True` 基線。

### 修改

- `common.ps1` 新增 `Get-SqlCmdCommand`，優先解析 ODBC 18，再回退 PATH。
- `Test-SqlServerConnection` 使用解析後工具及 `-C` 執行唯讀 `SELECT 1`。
- `start-all.ps1` 改用同一工具解析，不再只檢查 PATH 中第一個 sqlcmd。
- 更新開發 README、環境基線與追蹤狀態。

## 定義與對外契約

| 項目 | 定義 |
|---|---|
| SQL Instance | `.\SQL2025` |
| 驗證 | Windows Authentication |
| 首選工具 | `C:\Program Files\Microsoft SQL Server\Client SDK\ODBC\180\Tools\Binn\SQLCMD.EXE` |
| 回退 | PATH 中的 `sqlcmd.exe` |
| 本機憑證 | sqlcmd `-C`，對齊連線字串 `TrustServerCertificate=True` |

### 必須維持的規則

- 不啟用 Mixed Mode，不保存 SQL 帳密。
- 腳本只做連線前置檢查，不建立或修改資料庫。
- 找不到 ODBC 18 時才允許回退 PATH；連線失敗必須回報 Unavailable。
