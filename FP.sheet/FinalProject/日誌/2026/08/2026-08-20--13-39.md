# 開發日誌

`dev` 的 `d9bd95c`（SH-05 身分與 antiforgery 基礎建設）帶來了第一支 Controller 與授權 Policy，
因此退款執行端點的前置條件全部到位，本次補上。

## 為什麼現在做得了

先前擋住端點的三件事，這一筆解決了兩件：

- **Controller 專案慣例**：`SecurityController` 示範了 `[ApiController]`、路由、`ProducesResponseType`、
  DTO record 同檔宣告、`ApiProblemDetailsFactory` 的用法。
- **授權與 TOTP**：`DoSelectPolicies.RefundExecute` 已定義為 `FinanceManager`／`SuperAdmin`，
  且 `AddAdminPolicy` 本身就要求 `amr = mfa` 宣告。
  **工程包第 85 行的「退款執行需要 TOTP 二次確認」由授權層保證，Controller 不自行檢查。**

## 新增

- `DoSelect.Api/Refunds/RefundsController.cs`
  - `POST /api/v1/admin/refunds/{refundPublicId:guid}/actions/execute`
  - `[Authorize(Policy = DoSelectPolicies.RefundExecute)]`
  - 必填 `Idempotency-Key` Header，缺漏回 400 驗證錯誤且**不呼叫執行器**。
  - 執行者取自 `ClaimTypes.NameIdentifier`。
  - `RefundExecutionResponse(RefundPublicId, SettledAmount, Replayed)`。
- `tests/DoSelect.Api.IntegrationTests/RefundEndpointTests.cs`：10 個測試。

## 錯誤碼對應

| 錯誤碼 | HTTP |
|---|---|
| `resource_not_found` | 404 |
| `refund_state_conflict` | 409 |
| `refund_amount_exceeded` | 409 |
| `idempotency_payload_conflict` | 409 |

重播與首次執行都回 200，以 `Replayed` 旗標區分，呼叫端不需要分辨兩者。
