## 本次完成

- 新增 `POST /api/v1/ai/product-search/recommendations` 與 `/ai-search` RWD 頁面。
- SearchIntent 與推薦理由使用 strict Responses JSON Schema；模型只解析需求及解釋後端核准候選。
- 公開商品、上架、價格、庫存及相容性由後端／SQL 再驗證；AI 不可放行。
- 訪客／會員每日額度、IP＋Browser ID 匿名鍵、成本保護及互動保存採 Fail Closed。
- 既有零件接受站內 SKU 或使用者確認的結構化手填資料；部分零件組合沿用正式相容性引擎。
- 自然語言既有零件只形成 `ProposedExistingPart`。後端強制回補問，確認前不查商品、不做相容性；前端點選確認後才形成 `confirmedByUser=true` 的手填輸入。
- 依 DEC-BATCH-035 補齊 CustomBuild：固定回傳 CPU、主機板、記憶體、顯示卡、儲存、電源、機殼與 CPU 散熱器八類完整清單；最高預算計新購零件與 NT$300 組裝費，既有零件不重複計價但仍參與正式相容性。
- SQL 候選組合採有界搜尋並逐一執行正式確定性規則；Blocked、InsufficientData、缺類或超預算不回傳。OpenAI 只解釋後端核准的新購 SKU，全為既有零件時不送出空候選呼叫。
- OpenAI、Schema、理由或服務失敗時明確降級為一般關鍵字搜尋，不冒充 AI 推薦。
- 測試專用 Data Protection Key Ring 改用獨立路徑，避免讀取其他 Windows 帳號的金鑰。

## 提供其他組員使用的契約

- Request：`message`、`locale`、最多 12 筆已確認 `existingParts`；既有零件 Union 為 `catalogSku` 或 `structuredManual`。
- Response：`resultType`、`intent.proposedExistingParts`、`clarifications`、後端核准 `recommendations`、`fallbackProducts`、`usage`。
- CustomBuild Response 另含 `customBuild.components`、`purchaseSubtotal`、`assemblyFee`、`purchaseTotal`、`compatibilityStatus` 與警示鍵；此欄為加法契約，既有單品／套裝推薦仍使用 `recommendations`。
- `ProposedExistingPart` 不是正式既有零件，不得直接傳入相容性或 Checkout；必須由使用者確認並補齊該分類硬規格。
- 商品與相容性資料只能由後端可信 Query／規則引擎提供；不得使用 AI 文字覆寫價格、庫存或相容性。
- 搜尋互動沿用既有 `AiInteractions.SearchPublicId`／`IntentJson`，本次沒有 Migration。
