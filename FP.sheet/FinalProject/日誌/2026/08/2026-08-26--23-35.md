### 摘要

PR #24 合併後，依組長給的依賴順序逐一處理 #29、#34、#35、#36、#37：先各自 rebase 到最新 `dev`，過程中發現並修正三類真正的問題（不只是機械式 rebase）：(1) PR #34 在功能分支自行 scaffold 了一支 Migration，依新版工程包規則補記日誌正式提給 alex 走 Migration Gate；(2) PR #34／#36 新增的後端端點沒有跟著重新產生共用 OpenAPI schema，CI 的 `api:check` 卡住；(3) PR #34／#36 共 7 支測試 fixture 寫死本機 `.\SQL2025` 連線字串，在 CI 的容器化 SQL Server（SQL 帳密、localhost:1433）下必定連線失敗，改用既有的 `SqlServerTestConnection.Build(...)` 共用 helper。另外盤點 M-11 物流發現三支分歧分支，依官方 API 目錄與最新的核心交易整合協調文件選定 `shipping-core-api`＋`shipping-admin-api` 為正式版，批次出貨延後到 #36 合併後再移植。過程中也發現 `dev` 本身最近兩次 CI 都有 SQL Server 連線池耗盡的既有問題，與本次改動無關，記錄待回報。
