## P2｜只改名稱時 Audit 誤記 ruleVersion 已異動

Domain 明確區分兩件事：名稱異動要記進 Audit，但**不推進 RuleVersion**
（`UpdateRules` 裡 `Rule(...)` 才會設 `ruleChanged`，`NameZhTw` 不走那條）。

我的實作只要 `change.HasChanges` 就無條件加一筆
`ruleVersion: null → 現值`。兩個後果：

1. **只改名稱時留下一筆根本沒發生的版本異動。** 事後追查會以為規則被改過。
2. **真正推進版本時沒有保存原版本**，寫成 `null → 2` 而不是 `1 → 2`。

已改為只有 `change.RuleVersionAdvanced` 為 `true` 時才寫，且在 `UpdateRules`
之前先留下 `ruleVersionBefore`，記正確的前後值。

### 我的第一版測試又是「為了錯誤理由變綠」

三條測試寫完跑，只有 `ARuleUpdate...` 那條在缺陷還在時會紅，
`ANameOnlyUpdate...` 照樣綠。

原因是我寫的 helper `ReadAuditedFieldsAsync` **把 `ruleVersion` 濾掉了** ——
而那條測試要驗的正是「`ruleVersion` 不該出現」。**要驗某個欄位不該出現，
就不能先把它濾掉。**

改成不過濾之後，三條裡有兩條在缺陷還在時會紅。

這是這幾輪第三次犯同一類錯（PR #16 的並行測試、#50 的狀態機測試、這次）。
共通點都是：測試是綠的，但綠的原因不是我以為的那個。

## P3｜狀態機的過期註解

`AdminCouponsController.cs` 的 action 註解還寫著「正式 Action 白名單沒有
`schedule`，若在此拒絕，`Scheduled` 會缺少 API 可達路徑」。

那個理由已被 alex 否掉：**`Scheduled` 的進入路徑就是未開始 Draft 的 activate（B1）**，
本來就到得了。已改寫，並補上「`Scheduled → Active` 與 `Exhausted → Active` 是系統
事件，管理員 activate 一律回 409」的說明，避免後續維護者依舊理由重新放寬。

## update Audit 的五種路徑（alex 要求的完整比對）

| 路徑 | 稽核欄位 | 測試 |
|---|---|---|
| `no-op` | 不寫 Audit | `AnUpdateThatChangesNothingWritesNoAudit` |
| `name-only` | 只有 `nameZhTw`，**不含 `ruleVersion`** | `ANameOnlyUpdateRecordsTheNameWithoutClaimingTheRuleVersionMoved` |
| `rule-only` | 欄位 + `ruleVersion` 正確前後值 | `ARuleUpdateRecordsTheRuleVersionItActuallyMovedFromAndTo` |
| `scope-only` | 只有 `scope`，版本與 RowVersion 都推進 | `AScopeOnlyUpdateStillRecordsScopeAndAdvancesBothVersions` |
| `mixed` | `nameZhTw` + `minimumSpend` + `ruleVersion` | `AMixedUpdateRecordsBothTheNameAndTheAdvancedRuleVersion` |

先前缺的就是 `name-only` 的 Audit 斷言，所以這個語意缺口能通過全綠 CI。

## 必須維持的規則（新增）

- **要驗某個欄位不該出現，就不能在讀取 helper 裡先把它濾掉。**
- **稽核只能記真的發生過的事。** 版本沒推進就不能寫版本異動。
