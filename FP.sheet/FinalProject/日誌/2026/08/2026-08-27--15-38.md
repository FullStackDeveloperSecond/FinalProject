# 2026-08-27 15:38｜零元訂單最低應付政策

## 更改內容

- alex 選擇方案 B：DoSelect V1 不接受零元訂單，成立訂單的整數 TWD `GrandTotal` 至少為 NT$1。
- 新增 append-only 穩定錯誤碼 `order_total_below_minimum`，HTTP Status 固定 409。
- Checkout Gateway 在可信優惠、運費、組裝費及整數化完成後、任何核心資料寫入前檢查最低金額。
- 新增 SQL Server Provider-backed 回歸案例，涵蓋全額折抵且運費為 0 的情境。
- 寫回 DEC-BATCH-028、領域需求、Endpoint／DTO／錯誤碼、交易資料字典、M 功能矩陣、核心交易協調及 DOM-15。

## 定義與取用規則

| 項目 | 定義／其他分工取用方式 |
|---|---|
| 最低應付 | `GrandTotal = Round(RawPayableAmount, 0, AwayFromZero)` 後必須 `>= 1m`。不得用未四捨五入金額或前端預估判斷。 |
| 拒絕契約 | 回 `409 order_total_below_minimum`；前端提示移除優惠券或調整購物車，不自動把折扣截短。 |
| 資料副作用 | Order、Item、Reservation、Movement、CouponRedemption、OrderCoupon、PaymentAttempt 均不得建立；Cart 維持 Active，庫存不變。 |
| 付款模型 | 保留 `PaymentAttempt.Amount > 0`；不新增 `NotRequired`／零元付款狀態，不改成功 DTO 或 Schema。 |
