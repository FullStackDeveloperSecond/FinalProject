## 定義內容

| ID | 組員必須證明的結果 |
|---|---|
| SEC-ACC-01 | 其他使用者不能從明細、列表、搜尋、匯出、附件、AI、快取或背景結果取得私人內容。 |
| SEC-ACC-02 | 其他使用者替換路由、Body、Parent、批次或 Action 參數後仍不能修改資源，拒絕後無副作用。 |
| SEC-ACC-03 | 所有 Hard／Soft／附件／批次刪除在伺服器端異動前逐筆驗證角色、Actor Scope、所有權及狀態。 |
| SUP-ACC-01 | Package 由正式 Registry 解析，名稱版本與官方來源一致，乾淨 Restore／Install、Lock File 及漏洞掃描通過。 |
| SEC-ACC-04 | 工作樹、Commit、PR、設定、測試、Log、文件與 Build Artifact 不含真實 Secret。 |

公開商品、已核准評價與正式分享內容不算「其他使用者私人內容」，但只能使用公開 DTO。具有正式 Policy 與業務目的的管理員可依 Actor Scope 存取；知道 PublicId 不代表取得授權。

## 組員取用方式

- 新增任何私人資源 Endpoint 時，在同一 PR 準備 User A、User B、未登入者及必要管理角色案例。
- 寫入或刪除被拒絕後，除了檢查 HTTP 結果，還要檢查資料、檔案、Outbox、通知、庫存與其他副作用沒有改變。
- 新增直接 Package 時，在 PR 記錄 Registry 頁面、官方來源、用途與版本；提交中央版本或 Lock File。
- 自動 Secret Scanner 尚未定版前，PR 必須附人工 Diff、Repository 搜尋及前端 Production Artifact 搜尋結果。
