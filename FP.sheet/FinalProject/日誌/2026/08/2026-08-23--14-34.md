## 更改內容

### 摘要

處理組長對 PR #22、#28 的最新回覆，並把切片 3（自由組裝與相容性）rebase 到最新分支狀態後開 PR 送審。過程中發現 `feature/build-compat-api` 沿用了 cart-api 舊版（rebase 前）的自建冪等寫法，一併修正為共用 `IIdempotencyExecutor`。

### 新增

- PR [#34](https://github.com/FullStackDeveloperSecond/FinalProject/pull/34)：`feature/build-compat-api` → `dev`。
- PR [#35](https://github.com/FullStackDeveloperSecond/FinalProject/pull/35)：`feature/build-compat-frontend` → `feature/build-compat-api`（堆疊 PR，非對 `dev`，因前端分支的 git 歷史本身是接在後端分支之後）。
- `BuildListsApiFixture` 新增 `Idempotency__ActorScopePepper` 環境變數覆蓋（沿用 `CartApiFixture` 慣例）。
- `EfBuildListServiceTests`／`EfBuildListService` 相關測試補上共用 `IIdempotencyExecutor` 的建構方式。

### 修改

- `feature/catalog-search-api`（PR #22）：`git rebase origin/dev`（`2d64d50`），零衝突，force-push（`8650aff`），CI 重新觸發。
- `feature/build-compat-api`：`git rebase --onto feature/cart-api 8fd1b78`，丟棄舊版（rebase 前）cart-api 的重複歷史。
- `EfBuildListService.AddToCartAsync`：原本自建 reserve-then-execute 的 `IdempotencyRecord` 寫法（複製自 cart-api 第一輪修正、已被淘汰的版本）改為透過共用 `IIdempotencyExecutor.ExecuteAsync`，與 `EfCartService.MergeAsync` 同一模式；Actor Scope 改用後端驗證後查出的 User PublicId。
- `feature/build-compat-frontend`：rebase 到修正後的 `feature/build-compat-api`（`825bb5f`），零衝突，前端檔案內容與 rebase 前逐位元組相同。

### 刪除或淘汰

- `EfBuildListService` 內的 `AddToCartIdempotencyReservation`、`ReserveAddToCartIdempotencySlotAsync`、`HashUtf8` 死代碼。
- `BuildWriteException.ErrorCodes.IdempotencyPayloadConflict` 與其 Mapper 映射（改由 `GlobalExceptionHandler` 統一處理 `IdempotencyConflictException`）。
