## 更改內容

### 摘要

修正組長對 PR #22、PR #23 的正式 review 共 13 項意見（原子性、DB 層過濾、刪除引用檢查、排序／驗證、rebase 整理），並把切片 2 購物車依指示從 3 條分支合併為 2 條、推送後開出 PR #28、#29。過程中額外修了兩個既有的環境性問題：`dev` 進度推進造成的 `Program.cs` DI 註冊衝突，以及 `dev` 尚未帶有的 `ci.yml` SQL Server 測試 filter。

### 新增

- `AdminCatalogQueryValidator`（`sort`／`stockState`／`statuses` 驗證，含穩定錯誤碼）
- Admin 商品列表新增 6 個測試：排序各選項、`stockState` 分頁正確性、三種非法輸入驗證
- PR #28（`feature/cart-api`）、PR #29（`feature/cart-frontend`）

### 修改

- `EfProductAdminService.ListAsync`：`stockState` 改成 Count／Skip／Take **之前**在 DB 層用關聯子查詢過濾（原本在記憶體、分頁後才過濾，會造成 totalCount 錯誤與短頁）；`sort` 接上驗證器與實際排序邏輯（原本完全沒生效）
- `EfSkuAdminService.DeleteAsync`：補齊 5 個遺漏的 Restrict FK 引用檢查（`OrderItems`、`InventoryReconciliationCases`、`ProductImages`、`SkuTranslations`、`SalePrices`），避免原始 SQL 例外外洩成 500
- `AdminProductsController.List`：補上 `try/catch (CatalogWriteException)`
- `feature/catalog-search-api`、`feature/catalog-admin-crud`：rebase 到最新 `dev`，解掉 `Program.cs` 的 DI 註冊衝突（純粹保留雙方註冊行，無邏輯變更）
- `feature/cart-api`、`feature/cart-frontend`：`ci.yml` 補上 `--filter "Category!=RequiresSqlServer"`（比照先前 catalog 分支用過的同一個修正）
- 切片 2 分支結構整理：原本 `feature/cart-api`（CRUD＋併發修復）＋`feature/cart-merge`（登入合併）兩條分支的內容合併成一條 `feature/cart-api`；`feature/cart-frontend` 疊在其上不變

### 刪除或淘汰

- `feature/cart-merge` 分支名稱（內容已併入 `feature/cart-api`，不是刪內容，是刪多餘的分支標籤）
