## alex 回答了目錄參考資料的權限問題

我上一輪問「要不要放寬 `CatalogManager`」，他的裁定是：

> **不要放寬** —— 那會把 FinanceManager／MarketingAnalyst 的權限擴張到目錄管理邊界。
> 建立受 `Coupon.Manage` 保護、用途限定的**批次**目錄參考端點。

他同時指出我那套公開端點方案的實際成本，而且說得對：分類樹每個節點各打一次
`/catalog/filter-options`（上限 100 次），而那個端點每次還會順便算品牌、價格區間、
規格篩選；`resolveProductOptions` 又對每個已選商品逐筆查明細，兩個 picker 各最多 50 次。

**我當時只想到「哪個端點權限過得去」，沒有算過它會放大成多少次查詢。**
選一個公開端點來繞過權限問題，代價是把一次編輯變成上百次 HTTP 與 SQL。

這一項是後端、而且落在 Catalog 模組，已在 PR 問他歸屬（我做／指派 Catalog owner／他自己接），
連同端點路徑與「能不能選草稿／停用項目」一起確認。

## P2#2：測試又一次證明不了它看起來在證明的事

百分比券後端要求 `maximumDiscount > 0`，前端沒把它設成必填。管理員照介面正常填完，
按下儲存會直接吃一句英文 400。

而**現有那條百分比測試是綠的** —— 因為它 mock 掉 API，套不到後端的 `RequireValidRule`。
它送出的正是一組真實 API 會拒絕的輸入。

補上前端規則後，那條測試第一次跑就變紅了。這是它應該有的行為 —— 我把它改成填上最高折抵，
並補了「未填會擋下且不呼叫 API」與「填了會帶進 payload」兩條。

**要記的是**：mock 掉 API 的元件測試，證明的是「前端送了什麼」，不是「後端會不會收」。
凡是有後端驗證規則的欄位，前端測試至少要有一條對著那條規則寫。

## P2#1：停用要先確認

`disabled` 是終態，誤觸後沒有任何方式重新啟用。加確認對話框，顯示優惠碼、名稱、
目前狀態、使用量、停用影響與不可逆性，並明講「需要暫時停售請改用暫停」。

只對 `disable` 擋一層：`activate` 與 `pause` 都可以再切回來。

測試三條：出現對話框且**不呼叫 API**、取消後仍**不呼叫 API**、確認後才送出。
中間那條是重點 —— 對話框存在的理由就是取消時什麼都不做。

## P3#4／P3#5

側欄的優惠券入口改成依角色顯示（與 router 的 `requiredRoles` 同一份清單）。
只動新加入的那一個入口，不順便重構整個側欄 —— alex 明講不必。

列表條件（q／statuses／pageNumber）同步進 Router Query，照 `ProductsPage.vue` 的既有寫法。
兩個細節：

- 用 `replace` 不用 `push`，否則每打一個字就堆一筆瀏覽記錄，返回鍵變成一次退一個字元
- 還原的順序有意義：先填 `q` 再 `search()`（立即套用但會把頁碼重設為 1），最後才寫回頁碼。
  反過來的話還原出來永遠是第 1 頁
