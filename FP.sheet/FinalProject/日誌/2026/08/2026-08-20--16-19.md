## 更改內容

### 摘要

建立客服、檢舉與退貨附件可共用的安全檔案基礎，以及商品原圖與三尺寸衍生圖的本機儲存核心。上傳內容先寫入專案外隔離區，只有大小、格式與 Microsoft Defender 掃描均明確通過後才處理；未知掃描結果採 Fail Closed。商品圖再經 ImageSharp 安全解碼、方向校正與 Staging 全成才移入正式目錄。

### 新增

- Application `IPrivateFileStorage`、`IFileScanner`、上傳結果與掃描結果契約。
- Application `IImageStorage`、商品圖片上傳／儲存結果、Variant 與安全限制契約。
- Infrastructure `LocalPrivateFileStorage`、`PrivateFileFormatValidator`、`MicrosoftDefenderFileScanner` 與 DI 註冊。
- Infrastructure `LocalImageStorage`、`ProductImageFormatValidator` 與共用串流限制／雜湊／清理工具。
- API `FileUploadProblemDetailsFactory`，將儲存失敗對應到正式 `file_*` 錯誤碼。
- 私有儲存、商品圖片三尺寸／不放大／WebP／失敗清理、格式、安全掃描分類及錯誤契約測試。

### 修改

- API 啟動時註冊 SH-06 檔案儲存服務。
- `ApiErrorCodes` 補入已定版的五個檔案錯誤碼常數。
- `ApiErrorCodes` 補入 `image_processing_failed`；Problem Details 加入商品圖 413／415／422／503 映射。
- Central Package Management 精確加入 `SixLabors.ImageSharp 3.1.12`；未採用需要建置授權金鑰的 4.x。
- 未完成項目追蹤表加入本階段實作證據與剩餘範圍。

| 能力／資料 | 提供者 | 使用者 | 用途 |
|---|---|---|---|
| `IPrivateFileStorage` | Infrastructure | 客服、檢舉、退貨 Application Use Case | 安全保存、讀取及刪除私有附件 |
| `IImageStorage` | Infrastructure | 商品圖片 Application Use Case | 安全保存原圖、產生三種 WebP、讀取指定 Variant 及刪除整組圖片 |
| `IFileScanner` | Infrastructure | 檔案儲存流程 | 將隔離檔交由 Defender 掃描並回傳明確結果 |
| `StoredPrivateFile` | Application | 三個附件領域 | 建立附件 Entity 所需 Storage Key、顯示檔名、格式、大小與 SHA-256 |
| `StoredProductImage` | Application | 商品圖片領域 | 建立 ProductImage 中繼資料所需 Storage Key、原圖尺寸／雜湊與三種衍生圖結果 |
| `FileUploadProblemDetailsFactory` | API | 三個附件 Controller | 統一 413／415／422／503 Problem Details |

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | 本階段不新增 Route；由客服、檢舉與退貨 Owner Endpoint 後續接用 |
| Request DTO | Controller 以固定 multipart 欄位 `file` 轉為 `PrivateFileUpload`；不得把 `IFormFile` 傳入 Domain |
| Response DTO | `StoredPrivateFile` 僅供伺服器內部建立附件資料；不得把 `StorageKey` 對外回傳 |
| 後端介面／Application Service | `IPrivateFileStorage.StoreAsync`、`OpenReadAsync`、`DeleteAsync`；`IImageStorage.StoreAsync`、`OpenReadAsync`、`DeleteAsync`；`IFileScanner.ScanAsync` |
| 領域事件／整合事件 | 本階段無；交易失敗後的孤兒清理由 SH-08／清理工作承接 |
| 必要權限或 Policy | 儲存服務不判斷 Actor；Controller／Use Case 必須先完成案件 Owner 或授權角色檢查 |
| 成功條件 | 實際串流不超過 10 MB，PNG／JPG／PDF 的副檔名、MIME、簽章一致，且 Scanner 回 `Clean` |
| 可能錯誤碼 | `file_count_exceeded`、`file_size_exceeded`、`file_format_invalid`、`file_malware_detected`、`file_scan_unavailable`、`image_processing_failed` |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `StorageKey` | 相對、不可猜字串 | 否 | `private-files/{shard}/{random}.blob`；不可作公開 URL |
| `Sha256` | `byte[32]` | 否 | 由實際寫入內容計算，不信任 Client |
| `PrivateFileStoreStatus` | Enum | 否 | `Stored`、`SizeExceeded`、`FormatInvalid`、`MalwareDetected`、`ScanUnavailable` |
| `FileScanOutcome` | Enum | 否 | `Clean`、`MalwareDetected`、`Unavailable`；未知不得視為 Clean |
| `ProductImageVariant` | Enum | 否 | `Original`、`Small320`、`Medium800`、`Large1600` |

### 必須維持的規則

- 每檔上限以伺服器實際讀取串流計算，不信任 Content-Length。
- 使用者檔名只作清理後顯示資訊，不可組成磁碟路徑或 Storage Key。
- 正式檔案位於 `{Storage:DataRoot}/private-files`；隔離檔位於 `{Storage:DataRoot}/quarantine`，兩者均不在 `wwwroot`。
- 格式驗證必須同時符合副檔名、MIME 與檔案簽章。
- Defender 不存在、逾時、錯誤或輸出不明時回 `ScanUnavailable`，不得保存。
- `OpenReadAsync`／`DeleteAsync` 只接受服務產生的相對 Storage Key，路徑穿越回不存在且不得產生副作用。
- Controller 必須先做資源授權及每案三檔限制；儲存服務不是授權邊界。
- 商品圖只接受 JPG／PNG／WebP；原圖不超過 10 MB、10,000 px 與 25,000,000 pixels，且只接受單 Frame。
- 商品圖經 EXIF 方向校正後產生 320／800／1600 WebP Q80，不放大；衍生圖移除 Metadata，三檔全部完成後才能移入正式目錄。

### 禁止或不建議的取用方式

- 不得把檔案放入 `wwwroot` 或把實體路徑／Storage Key 回傳前端。
- 不得跳過 `IPrivateFileStorage` 直接將未掃描串流寫入正式目錄。
- 不得只依副檔名、Content-Type 或 Client 宣告大小判定安全。
- 不得因 Defender 無法使用而降級成免掃描。
