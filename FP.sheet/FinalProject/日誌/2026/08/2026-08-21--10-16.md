## 更改內容

- 建立 `AiSupportOrchestrator`、`IAiSupportAccessReader` 與 `IAiSupportModelClient`，所有外部模型呼叫只能在登入、同意、額度及內容安全檢查通過後執行。
- 建立 `POST /api/v1/ai/support/messages`，套用 Member Policy、全域 Antiforgery、DTO 長度／語系／訂單參照數量驗證與標準 Problem Details。
- Controller 只從 `NameIdentifier` Claim 取得可信 Member ID；Request 不接受 Member ID。
- 預設 Access Reader 採 Fail Closed；正式同意資料來源尚未接線時不會呼叫預設模型 Adapter。
- 敏感內容定版為 `400 validation_failed`，回應不包含輸入原文；Result Code 定版為 `answered`、`safe_rejection`、`degraded`。
- 建立 6 項 Application Orchestrator 測試與 7 項 API Integration，Fake Model Client 可直接驗證呼叫次數。

## 定義與跨模組取用

| 取用者 | 必須使用的能力 | 規則 |
|---|---|---|
| 正式 OpenAI Adapter | `IAiSupportModelClient` | 不得由 Controller 直接呼叫 OpenAI；Adapter 只接收已完成安全檢查的 `AiPromptEnvelope` |
| 會員／AI 同意模組 | `IAiSupportAccessReader` | 回傳目前有效同意、剩餘每日訊息及重設時間；未完成時必須 Fail Closed |
| 訂單與客服 Query | `AiSupportExecutionRequest.DataItems` 的上游投影 | 必須先驗證 Owner 並去識別化；不得把前端提供的 Member ID 當成授權依據 |
| 消費者前台 | `AiSupportAnswerDto` 與 Problem Details | 敏感輸入處理 `400 validation_failed`；成功碼只使用三個已定版值 |
