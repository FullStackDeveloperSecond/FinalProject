## 更改內容

### 摘要

新增會員自助「訂單取消」與「退貨入口」查詢的後端 API 與前台頁面骨架（C-18 `/orders/:orderId`）。這是 `M-02` 的後半段（`訪客取消與退貨入口`），但依組長裁定先只做「不依賴 GuestOrderAccessToken Cookie」的會員自助部分；訪客路徑待 `haru/feature/guest-ordertracking`（尚未合併進 dev、也還沒 rebase）帶著限單 Cookie 驗證機制合併後再補上，避免現在先手刻一條會被取代的平行驗證邏輯。

### 新增

- 後端：`OrdersController`（`GET /api/v1/orders`、`GET /api/v1/orders/{id}`、`POST /api/v1/orders/{id}/actions/cancel`），僅 `DoSelectPolicies.Member` 授權（Owner 比對 `MemberUserId`）。
- 後端：`IOrderService`／`EfOrderService`、`OrderContracts.cs`（DTO）、`OrderWriteException`（錯誤碼）、`OrderWriteExceptionMapper`、`OrdersServiceCollectionExtensions`。
- 後端測試：`EfOrderServiceTests`（`DoSelect.Infrastructure.Tests/Orders`），涵蓋 Owner／非 Owner、取消成功與狀態不允許、理由碼驗證、RowVersion 併發衝突、退貨入口欄位。
- 前台：`features/orders/api.ts`（手寫 Paths，比照 `admin-web/features/auth/api/paths.ts` 慣例）、`OrderDetailPage.vue`（C-18）、對應 `OrderDetailPage.spec.ts`、`/orders/:orderId` 路由。

### 修改

- `Program.cs`：註冊 `AddDoSelectOrderServices()`。

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `GET /api/v1/orders`、`GET /api/v1/orders/{id}`、`POST /api/v1/orders/{id}/actions/cancel` |
| Request DTO | `OrderQuery`（`pageNumber`、`pageSize`）、`CancelOrderRequest`（`reasonCode`、`note?`、`orderRowVersion`） |
| Response DTO | `PageResult<OrderSummaryDto>`、`OrderDto`（含 `AvailableActions`：`cancel`／`requestReturn`） |
| 後端介面／Application Service | `DoSelect.Application.Orders.IOrderService`（實作 `DoSelect.Infrastructure.Orders.EfOrderService`） |
| 領域事件／整合事件 | 無（本切片沒有 Outbox／Domain Event 基礎設施可用） |
| 必要權限或 Policy | `DoSelectPolicies.Member`（僅會員本人訂單；找不到或非本人一律回 404 `resource_not_found`，不區分） |
| 成功條件 | 取消：訂單狀態為 `PendingPayment`、理由碼在 `OrderCancellationReasonCodes.All`、RowVersion 相符 |
| 可能錯誤碼 | `resource_not_found`、`validation_failed`、`order_state_conflict`、`order_cancellation_not_allowed`、`concurrency_conflict` |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `OrderCancellationReasonCodes` | `string` 常數集合 | 否 | `changed_mind`／`ordered_by_mistake`／`found_better_price`／`shipping_too_slow`／`other`；規格只定義「顧客可選理由」限制、沒有正式代碼表，這是本切片的範圍界定，待與 alex／yinyin 對齊正式清單 |
| `OrderDto.AvailableActions` | `string[]` | 否 | `cancel`（僅 `PendingPayment`）、`requestReturn`（已送達且有可退數量） |
| `OrderDto.ReturnRequestDeadlineUtc` | `DateTime?` | 是 | `DeliveredAtUtc + 7 天`，只代表猶豫期退貨期限提示；瑕疵／寄錯／運損／保固不受此期限限制，不用來擋 `requestReturn` |

### 必須維持的規則

- 訂單擁有權查詢一律先過濾 `MemberUserId`，不得先撈出他人訂單再由 DTO／前端隱藏。
- 取消只允許 `PendingPayment`：`Confirmed` 狀態依狀態機設計文件雖然「允許取消」，但已付款者必須走退款流程，目前沒有顧客自助可呼叫的退款發起 Use Case（`ExecuteRefundService` 是後台核准後執行），所以先擋在 `order_cancellation_not_allowed`，不得靜默放行。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：本切片刻意不建立 `ReturnRequest`（沒有任何模組已實作 Return 的 Application／API 層），不要在此基礎上繼續加寫入邏輯，先跟 kafen 對齊 `UC-RETURN-01` 的正式界面。
