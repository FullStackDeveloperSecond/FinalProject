## 更改內容

### 摘要

三個問題都是同一種漏洞：門檻只在發布那一刻檢查，之後的資料（PATCH、既有 Published 列、URL 內容）可以繞過。修正把門檻變成狀態不變量，並依裁定 B 讓四個動作都留中央稽核。

### 新增

- 中央稽核 `product_image.upload`／`update`／`publish`／`delete`（Resource `ProductImage`）：記 `productPublicId`、`status` 前後、`sortOrder`、`hasCompleteMetadata`、`metadata`（只記「改過」），不記 URL 與檔案內容；與資料異動同一次 SaveChanges，`IProductImageAdminService` 四個方法多 `actorUserId`／`AuditRequestContext`，actor 角色快照從 UserRoles 讀（CatalogManager／SuperAdmin）。
- 測試：Domain `Publish_RequiresReady`、`UpdateMetadata_OnAPublishedImage_RejectsClearingTheAttribution`；Provider-backed `UpdateAsync_OnAPublishedImage_RejectsClearingTheAttributionAndLeavesItUntouched`、`LegacyPublishedImagesWithoutVariantHashesAreNotProjectedToTheStorefront`、`UploadAsync_WhenTheMetadataIsInvalid_RejectsBeforeStoringAnything`（alt 超長、`ftp://`、無 scheme、`javascript:`）、`DeleteAsync_WhenTheAuditInsertFails_DoesNotDeleteTheImage`，並在既有測試補稽核內容斷言；API `Patch_OnAPublishedImage_ClearingTheLicense_Returns422AndKeepsItPublished`、`UploadAndPatch_WithANonHttpUrl_Return400ValidationFailed`、`EveryImageActionWritesACentralAuditEntry`。

### 修改

- item 1：`ProductImage.UpdateMetadata` 在 Published 時拒絕讓來源／授權變不完整（Domain）；服務層先擋成 422 `image_metadata_incomplete`，資料不動、不留稽核。
- item 2：`ProductImageProjection` 的兩個公開投影查詢排除任一衍生圖雜湊為 null 的列；`ToSummary` 不再用全零雜湊 fallback（真的遇到就丟例外，不輸出一定 404 的 URL）。後台仍列出該圖，只是缺雜湊的變體 `publicUrl` 為 null。
- item 3／裁定 D：`sourceUrl`／`licenseUrl` 上傳與 PATCH 都以 `Uri.TryCreate(Absolute)`＋scheme http／https＋有 host 驗證，否則 `validation_failed`；存檔前就擋，不留孤兒檔。
- 裁定 C：`ProductImage.Publish` 只允許 Ready → Published；alex 的 `ProductMediaApiTests` 種資料時補 `MarkReady`。
- 建議：四個排序查詢加 `ThenBy(Id)`；刪除確認文案改為「商品頁會立即移除；已快取的公開網址可能仍會顯示一段時間」。
- 文件：DTO 契約三列補 URL 規則、Published 規則與稽核動作碼。
- API 測試改用 `CreateAuthenticatedAdminClientWithIdentityAsync`（稽核 actor 要真的 Roles／UserRoles 列）。

### 必須維持的規則

- Published 的圖片任何時刻都滿足發布門檻（Alt＋來源 URL＋授權名稱＋授權 URL）。
- 公開投影只輸出「媒體端點一定讀得到」的 URL：Published 且三個雜湊齊備。
- 只有 Ready → Published 一條邊。
- 稽核與圖片那一列同一次 SaveChanges。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：不得用假網址繞過來源／授權門檻（裁定 A）。
