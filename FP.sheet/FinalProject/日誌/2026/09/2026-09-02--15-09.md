# WP-A04／WP-H05 核心交易 E2E

## 更改內容

- 新增固定 Guest Cart、八類相容組裝 SKU＋一件獨立 GPU 與 `CREATOR10` 最小 Seed，不建立 Migration，也不修改正式資料；額外獨立 GPU 讓優惠適用小計達門檻，不改動既有 AI 組裝 Seed 單價基準。
- 新增 Cart → Checkout → 同請求 replay → Guest Email／訂單編號驗證 → 信用卡模擬付款成功 → Invoice 顯示的 Playwright 旅程。
- Checkout 成功頁補顯示商品小計、優惠、運費、組裝費與總計，以支援 Demo 與金額驗收。
- 新增兩個 SQL Server Provider-backed 案例：同一 Checkout request 零重複，以及兩個 Guest Cart 競爭最後一件只成功一筆。
- CI 與本機 E2E runner 可顯式選用 `E2E` Environment、背景工作與模擬端點；本機測試資料庫使用 `DoSelectE2E_<GUID>` 並刪除，CI 使用 Job 專屬且隨 service container 銷毀的 `DoSelectE2e`。
- 寫回 DEC-BATCH-046／DEC-P356 與相關安全、測試、進度、工程包及實作矩陣文件。

## 定義內容

- 產品的模擬付款完成端點仍只屬 Demo Profile；`E2E` 是不可部署的測試例外，且必須顯式設定 `Demo:SimulationEndpointsEnabled=true`。
- Development、Production 與其他 Environment 開啟模擬端點時必須啟動失敗。
- E2E 只可使用非敏感固定測試 HMAC；不得讀取、記錄或提交真實 Secret。
- 固定組裝旅程金額：商品小計 NT$45,000、優惠 NT$2,000、運費 NT$300、組裝費 NT$300、總計 NT$43,600。
- 免運門檻依優惠後適用小計計算；本旅程的 CPU／GPU／Memory 適用小計為 NT$20,000，折扣後 NT$18,000，低於組裝宅配 NT$30,000 免運門檻，因此運費為 NT$300。
- 相同 Idempotency-Key 與相同 Payload 必須回傳同一訂單，不能新增第二筆 Order、Reservation、PaymentAttempt 或 IdempotencyRecord。
- 最後一件商品並行競爭只允許一筆成功；失敗方為 `inventory_insufficient`，庫存維持 Available 0、Reserved 1。
- 預付核心主旅程完成不代表 COD 完成；COD 仍等待物流 Delivered／PickedUp 正式命令接線。
