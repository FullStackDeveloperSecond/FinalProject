# AI 商品搜尋低延遲推理設定

## 更改內容

- 依 DEC-BATCH-054 保留 `gpt-5.6-luna`、單次 Responses 呼叫、5 秒逾時、零同步重試與預設 service tier。
- 商品 SearchIntent payload 新增 `reasoning.effort: none` 與 `text.verbosity: low`。
- 先建立會失敗的 payload contract，再完成最小實作；同時驗證未送出 `service_tier`。
- 更新 AI 正式設計、驗收規格、評估規格、結果報告、README、追蹤表、M 功能矩陣、個人工程包與決策索引。
- 本批只執行零成本測試與 Dry Run，沒有呼叫 OpenAI Provider。
- 驗證結果：`OpenAiProductSearchClientTests` 12／12、`LiveEvaluationPlanTests` 12／12、後端 Solution Build 與 `dotnet format --verify-no-changes` 通過；資料集產物一致且 120／120 驗證通過。
- 固定 6 案單輪 Dry Run 為 `PlannedModelRequests=6`、`AnnotationsApproved=true`、`IsLiveReady=true`，沒有使用 `--execute`。

## 定義內容

- 低推理量與低 verbosity 只用於商品 SearchIntent；AI 客服設定不變。
- strict JSON Schema、語意白名單、後端驗證與關鍵字降級仍是安全及正確性邊界，不得因 `reasoning.effort: none` 而移除。
- `service_tier` 不出現在 payload，代表維持 API 預設層級，不購買優先處理。
- 目前證據只證明 payload 與 deterministic 契約；Live 完成率、P95、Token 與成本尚未重新量測。
- 任何新付費 Smoke 或 66 次 Release baseline 必須另行取得組長授權。
