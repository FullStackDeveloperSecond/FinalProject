## 更改內容

### 摘要

實作規格「每筆訂單獨立驗證、獨立交易及獨立回傳結果；一筆失敗不回滾其他已成功出貨的訂單」。這與匯入、批次調價那些「整批單一交易」的流程正好相反，是刻意的：出貨是不可逆的實體動作。影響後台 OrderManager／SuperAdmin 的出貨作業與訂單列表。

### 新增

- `DoSelect.Application/Shipping/BatchShipmentContracts.cs`：`BatchShipmentRequest`／`BatchShipmentOrderInput`／`BatchShipmentActions`（`createLabel`、`markShipped`）／`BatchShipmentItemResultDto`／`BatchShipmentResultDto`／`IBatchShipmentService`。
- `DoSelect.Infrastructure/Shipping/EfBatchShipmentService.cs`：整批前置驗證（>100 筆回 `shipping_batch_limit_exceeded`；空批次、未知動作、缺冪等鍵、同批重複訂單回 `validation_failed`，一筆都不開始）；逐筆 `ChangeTracker.Clear()`＋自己的交易；逐筆 readiness（Confirmed／Processing、履約 Pending、已付款或 COD、組裝 NotRequired／ReadyToShip、仍有 Active 保留、配送方式有效、尚無出貨、超商門市仍啟用）全部以列錯誤碼回傳，不拋例外。
- `DoSelect.Api/Shipping/AdminShipmentsController.cs`：`POST api/v1/admin/shipments/batches`，Policy `Shipping.Manage`。

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `POST /api/v1/admin/shipments/batches` |
| Request DTO | `AdminBatchShipmentRequest { orders: { orderPublicId: uuid, rowVersion: base64 }[], shippingAction: "createLabel" \| "markShipped", idempotencyKey: string(1..128) }`；`rowVersion` 取自 `AdminOrderSummaryDto.rowVersion` |
| Response DTO | `BatchShipmentResultDto { batchPublicId, total, succeeded, failed, items: BatchShipmentItemResultDto[], createdAtUtc }`；`items[]` 含 `sourceRowNumber`（輸入列號，1 起算）、`orderPublicId`、`orderNumber`、`status`、`trackingNumber`、`errorCode`、`message` |
| 後端介面／Application Service | `IBatchShipmentService`（`ShippingServiceCollectionExtensions` 已註冊 Scoped） |
| 領域事件／整合事件 | 無新增；`markShipped` 寫入既有 `EmailNotificationRequestedV1`／`InAppNotificationRequestedV1` |
| 必要權限或 Policy | `DoSelectPolicies.ShippingManage`（OrderManager／SuperAdmin） |
| 成功條件 | HTTP 200 且 `items[i].errorCode == null`；**整批全失敗仍是 200**，逐筆結果在 `items` |
| 可能錯誤碼 | 整批：`shipping_batch_limit_exceeded`（400）、`validation_failed`（400）。逐筆：`shipping_order_not_ready`、`shipping_tracking_duplicate`、`shipping_method_not_allowed`、`concurrency_conflict`、`resource_not_found` |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `Shipment.ShipmentNumber` | `SH{yyyyMMdd}{OrderId:D10}` | 否 | 唯一索引 `UX_Shipments_ShipmentNumber`；同一訂單同日第二次出貨在此撞回 `shipping_tracking_duplicate` |
| `Shipment.TrackingNumber` | `SIM{yyyyMMddHHmmss}{OrderId:D8}` | 是 | 模擬單號；**無唯一索引**，重複由服務先查後擋 |
| `OrderStatusHistory.ReasonCode` | `batch_shipment` | 否 | 履約維度 Pending→Preparing／Shipped |
| `ShipmentStatusHistory` | 每步一列 | 否 | `markShipped` 留 Pending→Preparing、Preparing→Shipped 兩列 |

### 必須維持的規則

- `Shipment` 狀態機只允許單步邊；`markShipped` 必須走 Pending→Preparing→Shipped，不得直接跳。
- 呼叫端的 `rowVersion` 必須在**第一次寫 Order 的 SaveChanges 之前**設為 OriginalValue；`ConsumeAllForOrderAsync` 內部會自己 SaveChanges，先讓它沖出去就失去併發仲裁。
- 業務拒絕一律回列錯誤碼、不拋例外；服務的 `catch (Exception)` 只留給真正的缺陷（會記 Error）。測試以 CapturingLogger 斷言健康批次不留 Error。
- 送出成功後前端清空選取：那些 RowVersion 已被推進，再送只會整批 `concurrency_conflict`。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：不得把整批包成單一交易（規格明文禁止）；控制器不得用 `[MaxLength(100)]` 擋筆數（模型驗證會先回 `validation_failed`，目錄要求 `shipping_batch_limit_exceeded`）。
