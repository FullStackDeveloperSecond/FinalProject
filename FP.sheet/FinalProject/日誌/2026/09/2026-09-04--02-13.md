## 更改內容

### 摘要

驗收規格 UC-ADM-INV-01「手動釋放成功 → 保存 InventoryMovement 與 Audit Log」在 dev 上一直沒有成立：服務層 `ReleaseAsync` 與 A-12 的釋放 UI 都在，但端點自 PR #36 round 3 撤回後沒補，理由是中央 Audit 未落地。Audit 早已在 dev，本篇把兩者接起來並補回路由。

### 新增

- `AuditActions.InventoryReservationRelease = "inventory_reservation.release"`、`AuditResourceTypes.InventoryReservation`，`AuditWritePolicy` 定義允許 note，欄位 `status`／`reasonCode`／`orderPublicId`／`skuPublicId`／`quantity`／`reservedQuantity`。
- `AdminInventoryController.ReleaseReservation`：`POST /api/v1/admin/inventory/reservations/{id:guid}/actions/release` → 204；`ReleaseReservationRequest`（`reasonCode` 1..32、`note` 1..500、`rowVersion`）。
- `InventoryReservationActions`（`release`）：列表只在 Active 保留列出 `availableActions:["release"]`。
- Provider-backed 測試五支：稽核內容（actor PublicId／角色快照／reason／Correlation／Trace／changes 前後值／note）、AuditLogs INSERT 失敗時釋放整筆不落地、空白備註、備註違反稽核字元規則、管理員缺 InventoryManager 角色。API 測試六支：成功 204 並落 Movement 與 Audit、同 RowVersion 重送 409 且只減一次、缺原因／備註／白名單外 reasonCode 400 且庫存不變、403、404、`availableActions` 只在 Active 出現。

### 修改

- `IInventoryReservationService.ReleaseAsync` 增加 `AuditRequestContext`；`EfInventoryReservationService` 注入 `IAuditWriter`，先從 `Users`／`UserRoles` 解析 InventoryManager／SuperAdmin 角色快照，把稽核先加進 ChangeTracker，再由 `ReleaseCoreAsync` 的那一次 `SaveChangesAsync` 與 Balance／Reservation／Movement 一起寫。`AuditWriteRequest.Create` 對 note 的字元／長度拒絕翻成 `validation_failed`（此時尚未送任何東西到資料庫）。
- `ReleaseCoreAsync` 移除從未落地的 `note` 參數；自由文字 note 只落在稽核。
- admin-web `features/inventory/types.ts`／`api.ts`：移除撤回期間的手寫 `ReleaseReservationRequest`／`InventoryReleaseApiPaths` 與局部 client，改用產生的契約型別與共用 `apiClient`。
- 測試夾具：`InventoryReservationServiceFixture.SeedAdminUserIdAsync` 與 `AdminInventoryApiFixture.CreateAuthenticatedInventoryManagerClientAsync` 改為種真的 Roles／UserRoles 列（稽核角色快照從資料庫讀，不信任登入 claims）。
- 文件：Endpoint 目錄「UC-ADM-INV-01 保留」列補稽核與錯誤碼；DTO 契約 `ReleaseReservationRequest` 列補白名單與 note 落點；M 矩陣 M-10 註記端點補回。

### 刪除或淘汰

- `AdminInventoryApiTests.ReleaseReservation_EndpointIsWithdrawn_ReturnsNotFound`（撤回守門測試）由上述六支取代。

## 定義與對外契約

### 提供給其他模組的能力或資料

| 能力／資料 | 提供者 | 使用者 | 用途 |
|---|---|---|---|
| `inventory_reservation.release` 中央稽核列 | M-10 | 稽核查詢（A-27）、稽核保留 | 誰、為什麼、從哪個狀態、哪張訂單、哪個 SKU、幾件釋放了保留 |

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `POST /api/v1/admin/inventory/reservations/{id}/actions/release` |
| Request DTO | `ReleaseReservationRequest { reasonCode, note, rowVersion }` |
| Response DTO | 204 No Content |
| 後端介面／Application Service | `IInventoryReservationService.ReleaseAsync(reservationPublicId, reasonCode, note, adminUserId, expectedRowVersion, auditContext, now, ct)` |
| 領域事件／整合事件 | 無 |
| 必要權限或 Policy | `InventoryManager`（InventoryManager／SuperAdmin）；稽核角色快照另從 UserRoles 驗同一組角色 |
| 成功條件 | 保留 Active→Released、Balance.Reserved 減一次、Release Movement 一列、稽核一列，四者同一次提交 |
| 可能錯誤碼 | `validation_failed`、`resource_not_found`、`inventory_reservation_not_active`、`inventory_reservation_already_processed`、`concurrency_conflict`、`authorization_forbidden` |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `reasonCode` | `InventoryReleaseReasonCodes.All` 白名單 | 否 | `customer_cancelled`、`duplicate_order`、`risk_rejected`、`inventory_correction`、`other` |
| `note` | string 1..500 | 否 | 進稽核 note；不收 `@ < > & \ " '` 與控制字元 |
| `rowVersion` | base64 | 否 | 列表回傳的 RowVersion；釋放後即失效 |
| `availableActions` | `string[]` | 否 | Active 為 `["release"]`，其餘為空 |

### 必須維持的規則

- 稽核與釋放必須同一次 SaveChanges；`ReleaseAsync` 不自己開交易，也不得把稽核移到第二次 SaveChanges（`ReleaseAsync_WhenTheAuditInsertFails_ReleasesNothing` 守著這條，反向驗證會轉紅）。
- 只有 Active 保留列出 `release`；前端不得自行依狀態推斷按鈕。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：不得直接改 `ReservedQuantity`（庫存規則.md）——人工釋放與逾時釋放共用同一個領域操作。
