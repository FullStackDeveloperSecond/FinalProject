## 更改內容

- 新增公開 `/checkout` Route 與 C-14 頁面，整合既有 Cart revalidate、Checkout policy versions、Shipping Options、Convenience Store、Orders 與 Guest Access 流程。
- 結帳表單涵蓋聯絡資料、宅配地址／示範門市互斥、配送備註、具體付款方式、優惠碼、個人／公司模擬發票、手機條碼載具，以及 Terms／Return／Privacy 目前版本確認。
- 送單只包含 Cart PublicId／RowVersion、後端提供的識別值及顧客輸入；不提交價格、折扣、運費、庫存或快照。
- 同一份失敗 Payload 重試會沿用同一 `Idempotency-Key`；內容改變才產生新鍵。
- 會員預付建單成功導向付款頁，會員 COD 導向訂單頁；訪客顯示訂單編號並導向既有 Email 限單驗證，不直接進入會被 401 的受保護頁。
- 購物車結帳按鈕移除「開發中」並只在目前 RowVersion 已通過重驗時導向 C-14。
- 依使用者選擇 B／DEC-P351，把 `ShippingOptionDto.allowedPaymentMethods` 從 `string[]` 改為具體 `PaymentMethod[]`；六種預付由 `PaymentMethodPolicy.PrepaidMethods` 單一提供，COD 仍由既有 Policy 決定是否追加。
- 重新匯出 OpenAPI 並產生 TypeScript Schema；生成檔不再接受任意字串或 `prepaid`。
- 同步正式 DTO／Route 規格、決策索引、個人工作包、M 功能矩陣、核心交易協調與未完成追蹤紀錄。

## 定義與取用方式

- 結帳 API wrapper：`frontend/customer-web/src/features/checkout/api.ts`。
- 結帳頁：`frontend/customer-web/src/pages/CheckoutPage.vue`；Route name 為 `checkout`、Path 為 `/checkout`。
- Shipping 付款欄位：`ShippingOptionDto.allowedPaymentMethods: PaymentMethod[]`，camelCase 值為 `creditCard`、`atm`、`convenienceCode`、`linePay`、`applePay`、`googlePay`，後端資格通過時另含 `cashOnDelivery`。
- 前端不得展開 `prepaid`、自行推算 COD，或把 Cart 預覽金額送回 Orders API。
- 訪客建單後以回應中的 `orderNumber` 搭配結帳 Email 進入 `/guest-orders/access`；完成一次性驗證後才可進付款／訂單頁。
- 聚焦前端測試：`npm test -- --run src/pages/CheckoutPage.spec.ts src/pages/CartPage.spec.ts`。
- Shipping SQL 測試需由系統 PowerShell 執行；沙盒 Windows 身分無法使用本機 SQL2025 強制加密，不能把該環境錯誤當成程式失敗，也不得為此降低 SQL 加密。
