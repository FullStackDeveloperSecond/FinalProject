## 更改內容

### 摘要

對帳案件到 #107 為止只有 API，管理員沒有畫面可操作。本支照 A-12 保留佇列頁的形狀新增 A-29：分頁列表（`PageResult`，與 A-11 相同的草稿→套用篩選）、三個動作按鈕依案件狀態顯示，dismiss／resolve 共用一張內嵌表單，原因白名單依動作切換、說明必填、送出前 `confirm`；錯誤碼對照補兩條。

### 新增

- `pages/InventoryReconciliationCasesPage.vue`（A-29，`/inventory/reconciliation-cases`，InventoryManager／SuperAdmin）＋ `InventoryReconciliationCasesPage.spec.ts` 7 支。
- `features/inventory/api.ts`：`listReconciliationCases`、`acknowledgeReconciliationCase`、`closeReconciliationCase(publicId, action, request)`（dismiss／resolve 各走自己的 openapi-fetch 路徑型別）；`types.ts` 四個產生契約型別的 re-export。
- `features/inventory/useInventory.ts`：`useInventoryReconciliationCaseList`（useQuery＋placeholderData）、`useAcknowledgeReconciliationCase`、`useCloseReconciliationCase`（成功後同時失效案件、餘額與異動查詢——resolve 會改 Balance 並寫一筆 Adjustment）。
- `features/shared/errorMessages.ts`：`inventory_reconciliation_case_not_open`、`inventory_reconciliation_ledger_inconsistent`。
- 路由 `inventory-reconciliation-cases`；App 側欄「庫存對帳案件」入口——組長 round 1 裁定 B1：只向 InventoryManager／SuperAdmin 顯示（`canReconcileInventory`），Route guard 才是邊界。
- 文件：M功能桌面UI與Route規格 新增 A-29 列。

### 正確取用方式

| 項目 | 定義 |
|---|---|
| 前端 API 路由與 HTTP Method | `GET …/reconciliation-cases`、`POST …/{id}/actions/acknowledge`／`dismiss`／`resolve` |
| Request DTO | acknowledge `{ rowVersion }`；dismiss／resolve `ReconciliationCaseResolutionRequest { reasonCode, note, rowVersion }` |
| Response DTO | `PageResult<InventoryReconciliationCaseDto>`；動作 204 |
| 必要權限或 Policy | InventoryManager／SuperAdmin（route meta 與後端 Policy 一致） |
| 成功條件 | 動作成功後列表重抓，案件狀態與處理人更新；resolve 後餘額頁與異動明細也失效重抓 |
| 可能錯誤碼 | `validation_failed`、`resource_not_found`、`inventory_reconciliation_case_not_open`、`concurrency_conflict`、`inventory_reconciliation_ledger_inconsistent`——皆以 `describeApiError` 顯示在表單下方 |

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| 駁回原因 | `false_positive`／`system_error`／`other` | 否 | 鏡射後端 `InventoryReconciliationReasonCodes.ForDismiss` |
| 修正原因 | `count_verified`／`system_error`／`other` | 否 | 鏡射 `ForResolve` |
| 說明 | string 1..500 | 否 | 進案件 `ResolutionReason` 與稽核 note；trim 後空白不可送出 |
| 可用動作 | 由 `status` 推導 | — | DTO 沒有 `availableActions`：Open→確認受理／駁回／修正；Acknowledged→駁回／修正；已結案無 |

### 必須維持的規則

- 白名單與狀態規則只是前端不給錯選項，後端仍會擋；不要把它當成授權。
- 每次動作都帶該列當下的 `rowVersion`；成功後靠查詢失效拿新值，不自行改本地狀態。

### 禁止或不建議的取用方式

- 不要把 `inventory_reconciliation_ledger_inconsistent` 當可重試錯誤自動重送。
