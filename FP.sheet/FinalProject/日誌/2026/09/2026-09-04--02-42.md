## 更改內容

### 摘要

檔案與圖片儲存設計.md 已把儲存、掃描、三種 WebP 衍生圖、Staging→正式目錄的原子發布與清理全部做完，並明寫「商品圖片上傳、後台預覽、發布及中繼資料寫入 Endpoint 屬 M-03 商品功能垂直切片」。本篇只補「一張圖片那一列的生命週期」：Processing→Ready→Published→Deleted，以及讓已發布的圖片真的出現在前台。

### 新增

- `ProductImage.MarkReady`／`UpdateMetadata`／`HasCompleteMetadata`／`EnsureNotDeleted`（Domain）；`Publish`、`MarkDeleted` 對已刪除圖片拒絕。
- `IProductImageAdminService`／`EfProductImageAdminService`：Upload（存檔→建列→記三個雜湊→Ready→中繼資料→下一個 SortOrder；DB 寫失敗立即刪剛存的檔）、OpenPreview（original／320／800／1600；不存在或已刪除回 null）、Update（RowVersion）、Publish（Alt／來源／授權齊備才可，已發布為 no-op，仍驗 RowVersion）、Delete（只轉 Deleted，實體檔交 30 天清理）。
- `ProductImageProjection`：公開主圖（320）、詳情圖庫（800）、後台列表主圖（預覽路由 320）、後台詳情清單（未刪除全部）四種投影集中一處。
- `AdminProductImagesController`：`POST products/{productId}/images`（multipart，10 MB＋64 KB 上限）、`GET product-images/{imageId}/preview/{variant}`（不掛 `[Authorize]`，自己跑 `CatalogImage.ViewDraft`，未登入／無權限／不存在一律 404，`Cache-Control: private,no-store`）、`PATCH product-images/{imageId}`、`POST …/actions/publish`、`DELETE product-images/{imageId}`。
- `DoSelectPolicies.CatalogImageManage／ViewDraft／Publish` → CatalogManager／SuperAdmin；`DomainErrorCodes.ImageProcessingFailed／ImageMetadataIncomplete`。
- 契約：`AdminProductImageDto`、`AdminProductImageVariantDto`、`UpdateProductImageRequest`、`ProductImageActionRequest`、multipart 上傳 schema。
- admin-web：`ProductImagesPanel.vue`（縮圖走預覽路由、上傳表單、逐列編輯／發布／刪除、公開網址連結）、`features/products` 四個 API 函式與四個 mutation hook、`errorMessages` 補六個檔案／圖片錯誤碼；A-06 `ProductEditPage` 於編輯模式掛上區塊。
- 測試：Domain 5 支；Provider-backed 10 支（真 `LocalImageStorage`＋假掃描器＋ImageSharp 產圖：三種 WebP 雜湊與磁碟一致、掃描不可用 503 且無列無檔、非圖片 415、存檔前驗中繼資料不留檔、發布門檻與公開 URL 對得上檔案、前台只看得到已發布、後台列表主圖走預覽、刪除留檔給清理、預覽串流、RowVersion）；API 6 支（上傳→預覽→PATCH→發布→公開路由讀到同一份 bytes、缺檔 400、非圖片 415、商品不存在 404、預覽未授權 404、刪除後隱藏）；授權矩陣加四條寫入路由；`AdminPolicyTests` 加三個 Policy；admin-web 6＋3 支 spec。

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `status` | `Processing`／`Ready`／`Published`／`Deleted` | 否 | 後台看得到的只有 Ready／Published |
| `previewPathBase` | string | 否 | `/api/v1/admin/product-images/{id}/preview`，接 `/original`／`/320`／`/800`／`/1600` |
| `variants[].publicUrl` | string | 是 | 只有 Published 有值 |
| `hasCompleteMetadata` | bool | 否 | Alt＋來源 URL＋授權名稱＋授權 URL 全有才 true，前端據此決定發布鈕 |
| `sortOrder` | int 0..9999 | 否 | 上傳自動取「未刪除最大值＋1」 |

### 必須維持的規則

- 公開路由只投影 Published；後台預覽只回 200／404，不回 401／403。
- 發布前三個衍生圖雜湊必須齊備（Domain 不變量），中繼資料必須齊備（服務層門檻）。
- 刪除不直接刪檔；清理由 `StorageMaintenanceJob` 依 30 天規則執行。
- 圖片是獨立 Aggregate：四個動作都不動商品的 RowVersion。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：不得自建第二套檔案服務；不得由後台以外的路徑讀未發布圖片。
