# AI v6 根因修正與 v7 零成本回歸

## 更改內容

- 依 Alex 對 v6 顧客輸出與失敗原因的審查，將修正定版為 DEC-BATCH-059／DEC-P399～DEC-P402。
- Live Runner 改為忠實模擬正式流程：模型要求補問或確認既有零件時，不再呼叫 Explanation 或產生推薦。
- 新增大寫 `STORAGE_CAPACITY_GB`、分類對 Semantic Key 白名單與 TB→GB 正規化；Storage 使用 RAM Key 或非法單位時 Fail Closed。
- 商品 Prompt 升為 `product-search-v7`，補強口語最高預算、用途／偏好分離、資訊完整不補問，以及不追問未提及周邊的泛化規則。

- 同步更新 AI 詳細設計、測試規格、README、Manifest、AI-09 追蹤、M 功能矩陣、Alex 交付計畫與決策索引／紀錄。

## 定義內容

- `STORAGE_CAPACITY_GB` 表示儲存裝置容量；`MEMORY_*` 只表示 RAM。`1 TB = 1024 GB` 由後端正規化。
- 分類與 Semantic Key 必須同時通過正式 SQL Metadata 白名單；不相符時不查詢、不推薦。
- 儲存容量屬搜尋／顯示規格，不加入 CPU／主機板／RAM／GPU／PSU／機殼的相容性硬規則。
- `AiProductSearchMetadata.SemanticKeysByCategory` 是內部選填契約；既有測試替身可不提供，但正式 SQL 型錄必須提供。
- Live Runner 只有在意圖完整、無補問、無既有零件確認且有預期候選時才執行推薦理由階段。
- v6 Smoke 與原始輸出維持歷史 `FAIL`，不得因 v7 修正而改寫；v7 的零成本通過不代表真實模型品質通過。
