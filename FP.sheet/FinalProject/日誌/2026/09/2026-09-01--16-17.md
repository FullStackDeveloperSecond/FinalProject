## 更改內容

- 以正式 Cart、Checkout、Guest Access、Order Detail 與 Cancel API 建立兩張真實訪客訂單的 Playwright journey。
- 驗證錯誤 OTP 不核發 Guest Cookie；正確 OTP 只能取得對應訂單的 30 分鐘限單 Cookie。
- 驗證跨單 GET 與取消皆回 404，隨後用另一張訂單自己的驗證流程比較狀態與 RowVersion，證明零副作用。
- 驗證目標訂單可由既有 UI 選擇正式原因碼並成功取消。
- 在 E2E fixture 登錄固定最小 SKU PublicId；驗證碼只由 E2E pepper 與 requestPublicId 在測試記憶體內推導。
- 補齊 `--seed-minimal` 主 SKU 的固定包材重量與尺寸；既有 Seed 資料缺值時會修復，讓真實 Checkout 可通過既有配送限制檢查。
- Git Gate 前刷新 `origin/dev`，將工作分支由 `e7a20f58` 無衝突 rebase 至 `eb5ca4a1`（PR #74）。

## 定義與取用方式

- 旅程標題：`a guest can verify, view and cancel only the matching order without cross-order effects`。
- 聚焦執行：`./scripts/test-customer-e2e.ps1 -Project customer-chromium -JourneyTitle '<title>'`。
- customer 全套執行：`./scripts/test-customer-e2e.ps1 -Project customer-chromium -JourneyTitle '.*'`。
- 測試只使用腳本建立的 `DoSelectE2E_<32 位 hex>` 隔離 SQL Server 資料庫，成功或失敗皆由腳本清理。
- E2E 驗證碼推導只適用固定 E2E pepper，不新增讀信、測試後門、公開 Endpoint 或正式環境能力。
- `--seed-minimal` 主 SKU 固定包材資料：1.2 kg、35 × 20 × 8 cm；用途是虛構開發商品的 Checkout／物流整合測試。
