## 更改內容

### 摘要

PR #89 是 M-04 匯入的收尾（A-07 前台＋模板下載、A-13 庫存匯入 API＋頁）。組長 round 1 指出庫存匯入的核心一致性與預覽契約有六項問題，本次一併修正並補測試。影響後台 CatalogManager（商品匯入）與 InventoryManager（庫存匯入）。

### 新增

- `DoSelect.Domain/Inventory/InventoryMovement.AdjustmentNote`（nullable，500 字）：庫存調整說明；非 Adjustment 的 Movement 固定 null，建構子會擋。
- Migration `20260902073750_AddInventoryMovementAdjustmentNote`：只新增 `InventoryMovements.AdjustmentNote nvarchar(500) NULL`，無資料搬移。**依組長 PR #89 review 裁定附上**（「在 InventoryMovement 增加 nullable 的調整說明欄位並附 EF Migration」）。
- `DoSelect.Application/Imports/InventoryImportRowDto`：庫存預覽列的明確型別（SourceRowNumber、SkuCode、Action、ErrorCodes、BeforeOnHand、ReservedQuantity、TargetOnHand、Delta、ReasonCode、Note）。
- `DoSelect.Infrastructure/Imports/ImportRetentionJob`：maintenance Queue 的清理工作，`maintenance:import-retention`，每日 03:00（Asia/Taipei）。
- `DoSelect.Infrastructure/Imports/XlsxWorkbookReader`：以 ClosedXML 讀固定名稱的三張工作表成與 CSV 相同的 `string[]` 列；含 ZIP 簽章檢查、公式儲存格拒絕。
- 測試：`EfInventoryImportServiceTests`（5）、`ImportRetentionJobTests`（3）、`EfProductImportXlsxTests`（5）、`InventoryImportsApiTests`（3）、`ProductImportsApiTests` XLSX（1）、admin-web spec（+3）。

### 修改

- `EfInventoryImportService.ApplyAsync`：**每一列**（含 NoChange）都呼叫 `InventoryBalance.ApplyQuantities` 並留一筆 Adjustment `InventoryMovement`。原本 NoChange 列 `continue`，只設 EF `OriginalValue` 不會產生 UPDATE，SQL 端的 RowVersion 條件根本沒送出去；Preview 之後被改到剛好等於目標值的 SKU 會靜靜通過。
- `EfInventoryImportService.ResolveRowsAsync`：Preview 時把 Balance 的 `OnHandQuantity`／`ReservedQuantity` 快照存進暫存 payload；`GetRowsAsync` 改回 `CursorPage<InventoryImportRowDto>`。
- `ImportBatchStaging.GetRowsAsync` 改成泛型投影（商品仍回 `ImportRowDto`，庫存回明確型別）；新增 `ParseRows`／`ReadWorkbookSheets`。
- `PreviewProductImportRequest` 多一個可選的 `WorkbookFile`；`EfProductImportService.PreviewAsync` 依此分流；控制器多收 `workbookFile` part（`ValueCountLimit` 4→5）。
- `BackgroundJobServiceCollectionExtensions`：註冊與排程 `ImportRetentionJob`。
- admin-web：`useImportRows` 改 `useInfiniteQuery`，`ImportBatchPanel` 攤平所有頁、庫存模式顯示調整前／已保留／目標／調整量／原因／說明；`ProductImportPage` 新增「三個 CSV／單一 XLSX」上傳格式切換。
- 契約重新產生：`/api/v1/admin/inventory-imports/{id}/rows` 回應型別改為 `CursorPageOfInventoryImportRowDto`；新增 `InventoryImportRowDto`、`CursorPageOfInventoryImportRowDto` 兩個 schema 節點；路徑集合無異動。

### 刪除或淘汰

### 命名與型別

| 名稱 | 型別／格式 | 是否可為空 | 說明／範例 |
|---|---|---|---|
| `InventoryMovements.AdjustmentNote` | nvarchar(500) | 是 | 只有 `MovementType = Adjustment` 會有值 |
| `InventoryImportRowDto.Delta` | int? | 是 | `+3`／`0`／`-2`；錯誤列 null |
| XLSX 工作表名稱 | `Products`、`Skus`、`Specifications` | 否 | 少任一張整批拒絕；欄從 A 欄起算，標題列與 CSV 相同 |
| XLSX 儲存格轉字串 | 數字 Invariant 無科學記號、布林 `true`／`false`、日期 ISO 8601 | — | 與 CSV 契約的 Token 相同 |

### 必須維持的規則

- 庫存匯入 Confirm 時每一列都要真的寫 Balance（`ApplyQuantities`），RowVersion 條件才會送到 SQL；不得再用「值沒變就跳過」。
- XLSX 與 CSV 只能有一條驗證路徑：工作表讀成字串列後走同一組 Parser，不得為 XLSX 另寫驗證。
- 清理只刪暫存列與逾期摘要；套用進去的商品、庫存 Movement 與 AuditLog 是長期稽核來源，不在清理範圍。

### 禁止或不建議的取用方式

- 不可由前端直接存取資料庫。
- 不可跨模組直接操作其他模組的 Repository 或資料表。
- 不可對外暴露資料庫內部 `bigint Id`；對外識別使用 `PublicId`。
- 其他：前台不得自行解析庫存預覽列的 Raw JSON——用 `InventoryImportRowDto`。

## 相容性、風險與注意事項

- 相容性影響：rows 端點回應型別改變只影響本 PR 自己的前端；`PreviewProductImportRequest` 的新參數有預設值，既有呼叫端不受影響。
- 已知風險：**商品匯入的 NoChange 列**與庫存匯入原本是同一類問題——Confirm 只對 Update 列送 RowVersion，NoChange 列不寫、不驗。商品那邊的語意是「Preview 說沒變就不動」，沒有 Movement 要留，所以本次未改；若組長認為商品側也應驗，另開一輪。
- 已知風險：由清理工作翻成 Expired 的批次，其列從翻的那一刻再算 24 小時（比規格保守），不會提早清掉管理員還能下載的錯誤列。
- 回復方式：`git revert 5d38040f`；Migration 以 `dotnet ef database update 20260902031406_WidenCouponDiscountTypeColumns` 退回（該欄可為 null，無資料損失）。
- 需要其他負責人配合：alex 覆核 Migration（review 已裁定附上）；kafen 覆核。
