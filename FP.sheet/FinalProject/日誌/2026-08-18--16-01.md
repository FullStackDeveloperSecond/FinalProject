## 定義的內容與取用方式

| 契約 | 提供者 | 取用者 | 定義 |
|---|---|---|---|
| `GuestOrderAccessRequests` | Haru | Auth／Email／Guest Order API | SQL Server Challenge；10 分鐘、錯 5 次、最多 3 封、60 秒冷卻及三 Scope 限流 |
| `GuestOrderAccessTokens` | Haru | Order／Shipment／Return Query 與 Command | HttpOnly、限單、30 分鐘內可多次使用；以到期／撤銷失效 |
| `AddressInput` 與 Order 地址快照 | Haru／Checkout | 前台結帳、訂單顯示、物流 | PostalCode／City／District／AddressLine 結構化；Label 不進訂單 |
| `AssemblyJobStatusHistories` | Haru | 組裝後台、訂單投影 | 以 AssemblyJobId 關聯的 append-only 歷程；Job 狀態與歷程同交易 |
| 差異化 Lockout | Haru Auth Application Service | 會員／管理員登入入口 | 第五次失敗依 AccountType 設 LockoutEnd 15／30 分鐘 |

### 禁止事項

- 不得直接讀寫其他模組 Repository／DbContext；跨模組使用公開 Query／DTO／Command／Event。
- 不得保存明文驗證碼、Guest Token、TOTP Secret、Recovery Code 或 Cookie。
- 不得把地址簿 Label 複製到 Orders；不得漏掉 RecipientCity／RecipientDistrict。
- 不得把 AssemblyJob 個別歷程塞入沒有 Job 關聯的 OrderStatusHistories。
- 不得只設定單一 `DefaultLockoutTimeSpan` 卻宣稱會員／管理員有不同期限。
- yinyin 覆核完成前不得建立或套用 Haru 工作包 Migration。

## 資料與安全參數

| 項目 | 定版值 |
|---|---|
| Guest 驗證碼期限 | 10 分鐘、單次使用 |
| 錯誤上限 | 每 Challenge 5 次 |
| 寄送上限 | 初次寄送計入，共 3 封 |
| 重寄冷卻 | 60 秒 |
| 15 分鐘建立限制 | IP Hash 10、Email HMAC 5、訂單 Lookup Hash 5 |
| Guest Access Cookie | 30 分鐘、限單、期限內可多次使用 |
| Guest 資料清理 | 到期後 30 天；每日、每批最多 500 筆 |
| 會員／管理員 Lockout | 5 次後 15／30 分鐘 |
