## 定義與對外契約

### Workflow 觸發

| 項目 | 定義 |
|---|---|
| Pull Request | 目標為 `main` 或 `dev` 時執行 |
| Push | Push 至 `main` 或 `dev` 時執行 |
| 手動 | 支援 `workflow_dispatch` |
| 併發 | 同 Workflow、同 Git Ref 只保留最新執行 |
| Repository 權限 | `contents: read`；Checkout 設定 `persist-credentials: false` |

### Job 與必要 Check

| Job／Check | 負責內容 |
|---|---|
| `Backend` | Restore、零警告 Build、Format Verify、Solution Test、NuGet 直接／間接弱點報告 |
| `Frontend (customer-web)` | 鎖檔安裝、Typecheck、零警告 Lint、Vitest、Production Build、正式相依 Audit |
| `Frontend (admin-web)` | 鎖檔安裝、Typecheck、零警告 Lint、Vitest、Production Build、正式相依 Audit |
| `CI Required` | 彙總上述 Job；任一失敗或取消即失敗，供 Branch Protection 固定要求 |

### 組員正確取用方式

- 組員不需在功能分支複製 Workflow；所有 PR 自動使用同一份 `.github/workflows/ci.yml`。
- 本機提交前使用 `FP.dev/README.md` 的等價命令；CI 不會自動修改或 Commit 程式碼。
- 不得重新命名 `CI Required`，除非同步修改 `main`／`dev` Repository Rules 與正式文件。
- 官方 Action 以完整 Commit SHA 固定；升級時必須確認官方來源、Review Diff 並重跑全部 Job。
- CI 不提供 OpenAI、Brevo、SQL Credential 或其他 Secret；第一段也不需要這些 Secret。
