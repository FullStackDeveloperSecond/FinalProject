# 開發日誌

依 PR #7 Review 修正書處理 P1：Entity 只限制狀態名稱，未限制正式必要條件。

## 問題

同一個 `Activate` 同時允許 `Draft`、`Scheduled`、`Paused`、`Exhausted`，卻不驗證有效期間、
規則完整或名額。`Schedule`、`MarkExhausted`、`MarkExpired` 也沒有各自的條件，
因此**已過期的 Exhausted 券可以重新 Active**，或**未到開始時間就 Active**。

## 修正

把管理員操作與排程／名額事件拆成不同的具名方法，各自傳入必要快照並守住狀態機表的條件。

### 管理員操作

| 方法 | 必要條件 |
|---|---|
| `ScheduleForLaterStart` | 開始時間晚於目前時間，且折扣規則完整 |
| `ActivateNow(usage, at)` | 已進入有效期間、折扣規則完整、總名額仍有剩餘 |
| `Pause` | 只有 `Active` 能暫停 |
| `Disable` | 任何非終態皆可 |

### 排程與名額事件

| 方法 | 必要條件 |
|---|---|
| `MarkExhausted(usage, at)` | 有設定總名額，且使用量已達上限 |
| `MarkExpired(at)` | 已到達結束時間 |

### 新增的判定屬性

- `HasCompleteDiscountRule`：百分比券必須同時有折扣率與最高折抵；定額券必須有折扣金額。
  適用範圍是否完整仍由 `CouponCalculator` 判定並回 `coupon_invalid`，因為範圍資料不在 Entity 上。
- `IsWithinUsagePeriod(at)`
- `HasRemainingQuota(usage)`

非法轉移仍丟 `InvalidOperationException`，由 API 層映射為 `coupon_state_conflict`；
該代碼已加入 `CouponCalculationErrorCodes` 常數。

Review 點名的兩個情境都有專屬測試：

- `AnExhaustedCouponCannotBeRevivedAfterItsEndTime`：已過期的 Exhausted 券不得 Active。
- `ActivatingBeforeTheStartTimeIsRejected`：未到開始時間不得 Active。

另補：

- `ExhaustedReturnsToActiveOnlyWhenQuotaIsGivenBackInsideThePeriod`：名額沒真的返還就不能恢復。
- `ACouponWithoutATotalLimitIsNeverExhausted`：無上限的券不得被標成耗盡。
- `AScheduledCouponThatPassesItsEndTimeExpiresDirectly`：`Scheduled` 超過 `EndsAt` 直接 `Expired`。
- `ExpiryRequiresTheEndTimeToHavePassed`、`SchedulingAfterTheStartTimeIsRejected`、
  `ActivatingAnIncompletePercentageRuleIsRejected`。
