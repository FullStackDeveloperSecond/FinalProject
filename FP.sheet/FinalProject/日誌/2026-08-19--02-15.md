## 更改內容

- 建立 Coupons、三張範圍 Junction、CouponRedemptions 與不可變 OrderCoupons 快照。
- 優惠碼採 Trim、NFKC 與大寫正規化；訪客使用鍵只保存 `binary(32)` HMAC。
- 依較高權威資料字典把兌換唯一鍵固定為 `UX_CouponRedemptions_CouponId_OrderId`，不把 OrderId 單獨設為唯一。
- 建立 PaymentAttempts／PaymentEvents，保存付款冪等鍵、Filtered Provider Reference、事件 Hash 與正式狀態。
- 建立 Refunds／RefundAllocations，分離退款核准者與實際執行者，並保留部分退款分攤來源。
- 建立模擬發票、明細、折讓與折讓明細；固定 `DEMO-NOT-A-TAX-INVOICE`，不形成真實稅務憑證。
- 所有目前可建立的跨模組 FK 均採 Restrict；`Refunds.ReturnRequestId` 等 Kafen `ReturnRequests` 形成後補實體 FK。

## 定義與對外契約

| 項目 | 定義 |
|---|---|
| Entity 封裝 | 公開 getter／private setter；狀態轉移經具名方法 |
| 優惠券名額 | Redemption 只在 Checkout Transaction 建立；最後名額仍須由 Application 使用 Serializable 或等價原子條件取得 |
| 付款重試 | 每次重試建立新的 PaymentAttempt；PaymentEvent 以 ExternalEventId 冪等 |
| 退款流程 | PendingReview→Approved→Processing→Succeeded／Failed；核准與執行為不同操作 |
| 發票性質 | 僅供 Demo，固定 Marker 且金額／折讓歷史不可刪除或覆寫 |
