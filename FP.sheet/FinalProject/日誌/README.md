# 開發日誌使用規範

此資料夾保存團隊在開發期間的異動與跨模組交接紀錄。模板本體是 [[日誌/日誌]]；每次記錄先複製模板，再依建立時間重新命名，不直接覆寫模板。實際日誌按 `日誌/YYYY/MM/` 歸檔，README 與模板固定保留在本層。

## 檔名規則

格式：

```text
YYYY-MM-DD--HH-mm.md
```

例如：`2026-08-13--10-47.md`

- 使用 24 小時制及開發電腦當地時間（Asia/Taipei）。
- 日期與時間之間固定兩個連字號 `--`；小時與分鐘使用一個連字號。
- 同一分鐘需要第二份日誌時，在分鐘後加 `--02`、`--03`，例如 `2026-08-13--10-47--02.md`。
- 不把作者或功能名稱放入檔名；作者與範圍寫在文件欄位，避免日後重新命名造成連結失效。

## 建立方式

1. 複製 `日誌.md`。
2. 立即依目前日期時間重新命名，並放入對應的 `YYYY/MM` 資料夾。
3. 填完所有「必填」欄位；不適用時寫「不適用」並說明原因，不留空白。
4. 在 PR 前更新一次，確保 Commit、API、資料庫與未完成事項是最新狀態。
5. 若同一工作跨多天且契約沒有改變，可更新原日誌；若契約、方向或交接範圍改變，建立新日誌並互相連結。

## 撰寫標準

- 「更改內容」回答這次實際新增、修改或刪除了什麼。
- 「定義與對外契約」回答其他分工如何取得資料、使用哪些名稱與遵守哪些規則。
- 路由、DTO、Entity、欄位、Enum、Event、錯誤碼及設定 Key 使用程式中的精確名稱。
- 不在日誌貼密碼、Token、TOTP Seed、連線字串、API Key、完整會員個資或真實 Secret。
- 若變更尚未完成或無法安全給別人使用，必須標示狀態與阻塞，不得寫成已可取用。

## 提交規則

- 日誌與對應程式碼放在同一個 PR；若只有設計決定，則與正式契約文件同一個 PR。
- PR 描述需連回日誌路徑。
- Code Reviewer 檢查日誌是否足以讓備援人接手；不足時不可視為完成交接。
