# 2026-08-21 16:34 PR #10 CI 修正日誌

## 問題原因

- Admin Web CI 以零 warning 為必要條件；`queries.spec.ts` 在同一檔案宣告多個 Vue Harness，產生兩個 lint warning。
- Backend CI 使用 Ubuntu，但原流程未啟動 SQL Server，也未覆寫 Windows named instance `Server=.\\SQL2025`，造成 31 項 SQL 整合測試無法連線。

## 修正內容

- Admin query 測試改為共用單一 Harness，不關閉 lint 規則。
- Backend CI 新增 SQL Server 2022 service、TCP 測試連線字串與健康檢查。
- CI 在執行測試前還原本機 EF Tool 並套用現有 Migration。
- 首次推送後確認 SQL container、Restore、Build、Format 均成功；Migration 因誤用 `DoSelect.Api` 作 startup project 而失敗。
- 依組長工程包改用 `DoSelect.Infrastructure` 作 project 與 startup project，並明確指定 `InitialCreate`／`DoSelectDbContext`。
- Migration 修正後 CI 已進入完整測試；系統環境重跑確認 132 項只剩 M14B SLA 測試受第一頁 100 筆限制影響。
- SLA SQL 驗收改用正式 keyset cursor 逐頁讀取，避免共用或平行測試資料將本次 fixture 擠出第一頁；保留 terminal 排除與精確欄位斷言。
- 本機 API 132/132 通過後，GitHub Linux runner 仍在 test step 失敗；因公開 API 不提供完整 log，CI 僅將 Repository 已公開的失敗測試名稱寫入 annotation，不輸出堆疊、資料值或連線內容，也不跳過或放寬測試。
- 使用全新 `DoSelectCiDiagnostic_20260821` 套用 `InitialCreate`，同一 controller class 在 SQL Server 2025 為 8/8 通過；確認 GitHub 的 SQL Server 2022 image 偏離組長 2025 基線。
- CI image 改為 Microsoft 官方 `mcr.microsoft.com/mssql/server:2025-latest`，其餘 Migration 與測試流程不變。
- SQL2025 runner 仍只失敗於 7 項先取 Antiforgery token 再 POST 的 controller 測試；共同 client 使用預設 `http://localhost`，Linux 不會在 HTTP 傳送 Secure antiforgery cookie。
- 測試 client 改用 `https://localhost` 且禁止 redirect，對齊正式 Secure cookie 與既有安全測試，不降低 Antiforgery 設定。
- 未修改客服正式行為、授權規則、Schema 或 Migration。

## PR #10 CI 後續修正（09:10）

- 最新 CI #86 的前端、AI contract 均通過，後端只剩 `SupportTicketsControllerTests` 7 項失敗。
- GitHub 公開註解顯示所有失敗都發生在建立案件後讀取 `publicId`，判定為防偽 token 與 cookie 在 Linux TestServer 未穩定成對送出的跨平台測試問題。
- 修正共用測試 helper：從防偽 token 回應的 `Set-Cookie` 精確取出 ASP.NET Core antiforgery cookie，並於 unsafe request 明確帶回；不更動正式 API 行為。
- 本機在目前預設 SQL 連線仍受「SQL Server 要求加密但此電腦不支援」環境限制；專案可正常編譯，最終結果交由與正式 CI 相同的 Linux + SQL Server 2025 runner 驗證。
- CI #87 顯示 Linux handler 會先消化 `Set-Cookie`，helper 因而在擷取 cookie 時失敗；將此測試 client 設為 `HandleCookies = false`，讓 helper 統一負責明確傳遞 token/cookie 配對。
- CI #88 顯示案件測試已跨過原失敗點，但其他 policy 測試仍採自動 Cookie 管理；共用 helper 改為相容兩種模式：有可見 `Set-Cookie` 才明確回送，否則由 handler 自動保存與回送。
- 再核對正式安全設定後確認 cookie 名稱是專案自訂的 `.DoSelect.Antiforgery`，不是 ASP.NET Core 預設前綴；helper 改以正式設定的精確名稱擷取。
