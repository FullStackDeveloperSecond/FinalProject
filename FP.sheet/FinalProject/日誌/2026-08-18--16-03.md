## 更改內容

### 摘要

Brevo 已驗證寄件者、SMTP User Secrets 與真實測試信收件皆完成。正式應用新增單次 Email 傳輸邊界：Email 關閉時明確抑制，啟用時使用 MailKit 連線 Brevo；結果只回固定狀態與安全錯誤碼，不回傳地址、內容、憑證或 Provider 原始例外。

### 新增

- Application `IEmailSender`、`EmailMessage`、`EmailDeliveryResult`、`EmailDeliveryStatus` 與固定錯誤碼。
- Infrastructure `SmtpEmailSender`、`LocalEmailSender`、`SmtpEmailOptions` 與 MailKit transport。
- 6 個 Infrastructure focused tests及 API 的 Disabled／Enabled DI 測試。

### 修改

- API 啟動依 `Features:EmailEnabled` 選擇 Local 或 SMTP Adapter。
- Email 設定新增 `SenderName` 與 `TimeoutMilliseconds`，並以啟動驗證限制必填欄位與 1～60 秒逾時。
- Central Package Management 固定 `MailKit 4.17.0`。

### 刪除或淘汰

- API 專案內重複的 `EmailOptions`；正式設定型別移至 Infrastructure。
- 淘汰「測試腳本等同正式 Email 實作」的可能誤解；腳本只負責帳號診斷。

## 定義與對外契約

### 提供給其他模組的能力或資料

| 能力／資料 | 提供者 | 使用者 | 用途 |
|---|---|---|---|
| `IEmailSender.SendAsync` | Application／Infrastructure | 未來 Notification Consumer | 單次傳輸已完成渲染的 Email |
| `EmailDeliveryResult` | Application | Hangfire Job／Consumer | 依狀態保存成功、抑制、暫時失敗或永久失敗 |
| `SmtpEmailOptions` | Infrastructure | API 設定與 SMTP Adapter | 綁定 Host、Port、帳密、寄件者及逾時 |

### 正確取用方式

| 項目 | 定義 |
|---|---|
| Application 介面 | 注入 `DoSelect.Application.Notifications.IEmailSender` |
| 輸入 | `EmailMessage(RecipientAddress, Subject, TextBody, HtmlBody?)` |
| 成功 | `Status=Sent`、`WasDelivered=true`、包含應用產生的 RFC Message ID |
| 本機停用 | `Status=Suppressed`、`ErrorCode=email_delivery_suppressed`，不得當成真實送達 |
| 暫時失敗 | `TransientFailure`＋`email_transport_unavailable`；未來由 Hangfire 依三次遞增退避處理 |
| 永久失敗 | `PermanentFailure`＋`email_invalid_message`／`email_authentication_failed`／`email_rejected` |
| 取消 | 呼叫端取消時拋出 `OperationCanceledException`，不轉成一般失敗 |

### 必須維持的規則

- SMTP Adapter 每次只嘗試一次；三次遞增退避只由 Hangfire Job 負責，避免雙重重試與重複寄信。
- 商業交易只寫 Outbox，不得同步等待或直接呼叫 SMTP。
- Email 關閉時不得假裝成功；必須保留 `Suppressed` 狀態。
- SMTP 結果與 Log 不保存完整收件地址、Body、Token、驗證碼、Password 或原始 Provider 例外。
- 只接受含 `@` 且 MailKit 可解析的網際網路 Email 地址。
- Brevo 使用 STARTTLS 587、憑證撤銷檢查與 15 秒逾時。

### 禁止或不建議的取用方式

- 不得在 Controller、Domain 或商業 Transaction 中直接建立 MailKit Client。
- 不得由各模組自行加入 SMTP 重試。
- 不得將 User Secrets 搬入 `appsettings.json`、測試、Log、文件或 Git。
- 不得把 `Suppressed` 當作 `Sent` 寫入 Notification 狀態。

## 相容性、風險與注意事項

- 相容性影響：Email 功能預設仍關閉，Fresh Clone 無 Secret 可啟動；啟用但缺少設定會安全 Fail Fast。
- 已知風險：正式 MailKit Adapter 尚未由應用流程實際寄送；目前真實投遞證據來自獨立 SMTP 診斷腳本。
- 回復方式：移除 DI、Adapter、Application 契約與 MailKit PackageReference；無資料庫回復。
- 需要其他負責人配合：Haru 後續會員流程只產生通知要求；alex／SH-08 建立 Outbox／Hangfire Consumer 與防重複重送。
