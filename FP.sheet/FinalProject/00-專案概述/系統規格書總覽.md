# DoSelect 懂選｜系統規格書總覽

## 1. 文件目的

本文件是 DoSelect 開發前規格的權威入口，用來固定 `v1.0` M 功能開發基線、指出各類正式規格的唯一來源，並說明規格變更與追蹤方式。

本文件不複製每個 Endpoint、DTO、資料欄位或驗收步驟。實作與 Review 必須沿本頁連結閱讀所屬正式文件；只閱讀本頁不足以實作單一功能。

需要單檔閱讀或交付 2026-08-20 凍結的 v1.0 內容時，使用 [[00-專案概述/DoSelect完整系統規格書-v1.0|DoSelect 完整系統規格書 v1.0]]。該文件是版本快照，不再隨後續決策更新；開發與 Review 必須以本頁導向的現行詳細規格及後續決策為準。

`v1.0 開發基線`代表 M 功能的產品需求、商業規則、權限、API 設計、資料設計及驗收入口可供開發。它不代表程式、Migration、自動化測試、Demo 資料或部署成果已完成。

## 4. 產品與商業目標

DoSelect 是台灣單一商家 B2C 電腦及周邊電商，主要服務知道預算與用途、但不熟悉硬體規格的電腦組裝新手，次要客群為專業創作者。

核心價值是讓使用者以自然語言說明需求，取得可解釋、有庫存且通過確定性相容性規則的商品或電腦組合，降低事前研究時間與錯配風險。完整背景與展示定位以 [[00-專案概述/專案概述]] 為準。

- 客服案件、附件、共用佇列、自領／指派／轉派、SLA 與統一案件工作台。

- S：收藏、評價與審核、檢舉、前台日文／韓文、消費者前台手機與平板 RWD、AI 客服案件摘要、AI 報表分析。

## 7. 系統與技術邊界

```text
Vue customer-web ─┐
                  ├─ ASP.NET Core 10 Controller Web API
Vue admin-web ────┘              ↓
                         Application → Domain
                              ↑
                        Infrastructure
                              ↓
                    EF Core / SQL Server 2025
```

- 採前後端分離與模組化單體，不拆微服務。
- Solution 使用 `DoSelect.slnx`，.NET SDK 基準為 `10.0.302`。
- API 使用 Controller、`Microsoft.AspNetCore.OpenApi` 與 Scalar；OpenAPI／Scalar 只在 `Development` 啟用。
- 前後台均為 Vue 3＋TypeScript＋Vite；M 先完成桌面介面。
- 第一版由一台 Windows 展示電腦執行，不使用 Docker、不正式部署公網。
- 金流與物流使用保留真實生命週期與非同步概念的模擬 Provider。
- OpenAI 只能透過後端受控 Adapter 與唯讀工具使用最小化、去識別化資料；基本電商不得依賴 AI 才能運作。

專案責任、依賴方向與建置基線以 [[03-架構/01-系統與環境/系統架構]]、[[03-架構/01-系統與環境/本機開發環境與版本基線]] 為準。

## 9. 資料、API 與安全不變量

- 交易資料以 3NF 為基線；必要快照、Balance、工作台 View 與未來投影必須有真實來源及重建／核對規則。
- 對外資源使用 UUID v7 PublicId，不暴露內部 `bigint identity`。
- 訂單保存商品、規格、價格、折扣、運費、組裝費、收件與規則快照，不以日後主檔回推歷史交易。
- 庫存保留、釋放、出貨與退款副作用必須具交易、冪等及併發保護。
- API 使用穩定 DTO、Problem Details、錯誤碼、分頁及 Cursor 例外，不直接暴露 Entity。
- 會員與管理員使用不同 Cookie Scheme；管理員強制 TOTP，寫入請求驗證 CORS、Credentials 與 Anti-forgery Token。
- AI 不直接連線資料庫、不執行取消／退貨／修改等寫入操作，也不得取得其他顧客資料或完整會員個資。
- 完整個資存取、退款、角色與高風險庫存操作必須留下 Audit Log。

## 10. 驗收與完成證據

- 每個 M 功能必須符合所屬使用案例的成功、失敗、授權、冪等、併發、快照與降級條件。
- PR 合併前執行 .NET Build／Test、受影響 API 整合測試、Vue Lint／Typecheck／Test、格式與契約差異檢查。
- 高風險資料庫、權限、金額、退款、庫存及 AI 隱私變更必須附對應測試。
- 合併至 `dev` 後執行五條核心 E2E；Demo 依 15～20 分鐘操作腳本完成彩排。
- AI 不可用、Email／背景工作失敗及展示環境異常時，必須符合已定降級與備援流程。

驗收門檻與證據形式以 [[03-架構/08-測試與驗收/測試策略]]、[[03-架構/01-系統與環境/非功能需求]]、[[04-展示/02-備援與復原/故障降級與復原手冊]] 為準。

1. 提出變更時指出原因、影響的 M／S／O 範圍與正式文件。
2. 核心或高影響變更由組長確認；不得只在程式碼、PR 留言或口頭討論中定案。
3. 同一批更新所屬正式文件與 [[05-規劃/03-需求與決策治理/決策紀錄]]。
