# 專案名詞表

本文件整理需求、畫面、API、程式碼、資料庫與測試使用的標準語彙。DEC-P85 已確認「建議英文名稱」為第一版唯一正式名稱；不得由各模組自行使用同義別名。

## 命名原則

1. 中文文件以本表「中文名稱」為準；程式碼與 API 以「建議英文名稱」為準。
2. Entity、Value Object、Enum 與 DTO 使用單數 PascalCase；資料集合可使用複數。
3. 狀態名稱只描述目前狀態，不把操作名稱當狀態，例如使用 `Paid`，不使用 `PayOrder`。
4. 「取消、退貨、退款」是三件不同的事，不得混用。
5. 「實體在庫、保留庫存、可售庫存、已售數量」是不同概念，不建立含義不明的 `Stock` 欄位。
6. 所有時間資料庫以 UTC 保存，API 使用含時區的 ISO 8601；前台以台灣時區顯示。
7. 所有新台幣金額使用精確十進位型別，畫面可顯示整數，程式不得使用浮點數計算。

## 參與者、帳號與權限

|---|---|---|---|

| 已驗證訪客購買者 | VerifiedGuestPurchaser | 通過訂單 Email 一次性驗證，取得單筆訂單短效存取權的訪客 | 不是會員，只能存取 Token 指定的訂單 |
| 會員 | Member | 已註冊並完成 Email 驗證的前台使用者 | 基本前台角色為 `Member` |
| 已購買會員 | VerifiedPurchaser | 具有符合評價資格之已完成訂單的會員 | 是動態資格，不是持久化角色 |
| 停權會員 | SuspendedMember | 帳號狀態受到限制的會員 | 是帳號狀態，不是角色 |
| 管理員 | Administrator | 可登入管理後台的帳號 | 權限由一個或多個後台角色組成 |
| 角色 | Role | 一組可指派給管理員的權限集合 | 第一版採角色層級 RBAC |
| 權限 | Permission | 對特定資源執行 View/Create/Edit/Approve 等操作的能力 | 待精確權限矩陣定義 |
| 訂單訪客存取權杖 | GuestOrderAccessToken | 訂單 Email 驗證成功後核發的短效、限單權杖 | 不可存取其他訂單或 AI 客服 |
| 雙因素驗證 | Two-Factor Authentication, 2FA | 密碼之外的第二種管理員驗證因素 | 本專案使用 TOTP |
| 一次性時間密碼 | Time-based One-Time Password, TOTP | 由 Google Authenticator 等 App 產生的短效驗證碼 | 不等同 Email OTP |
| 復原碼 | RecoveryCode | 管理員無法使用 TOTP 時的一次性備援碼 | 使用後必須失效並留下稽核紀錄 |

## 商品、SKU 與組裝

| 中文名稱 | 建議英文名稱 | 定義 | 不包含／備註 |
|---|---|---|---|
| 商品 | Product | 顧客看到的共用商品資訊，例如名稱、品牌、分類、描述及圖片 | 不直接代表唯一售價與庫存 |
| SKU | StockKeepingUnit, SKU | 可被定價、庫存、加入購物車及下單的最小銷售單位 | 同一商品可有多個 SKU |
| 預設 SKU | DefaultSku | 非變體商品唯一承載售價、庫存與下單識別的 SKU | 不是 Product 上的第二套價格／庫存欄位 |
| 商品變體 | ProductVariant | 同商品內以容量、顏色或其他選項區分的銷售變化 | 第一版可直接以 SKU 表達 |
| 品牌 | Brand | 商品製造商或品牌歸屬 | 真實與虛構品牌的展示規則待確認 |
| 分類 | Category | 具階層或業務意義的商品歸類 | 例如 CPU、主機板、記憶體 |
| 標籤 | Tag | 可跨分類使用的輕量標記 | 不承擔相容性判斷 |
| 商品規格 | ProductSpecification | 用於展示或搜尋的商品屬性 | 相容性必要規格必須使用結構化欄位 |
| 規格語意鍵 | SpecificationSemanticKey | 讓固定相容性程式穩定識別 Socket、功耗、尺寸等規格意義的不可變 Key | 被規則引用後不可刪除或改變資料型別；顯示名稱與排序仍可調整 |
| 上架 | Published | 商品或 SKU 可在前台被找到及購買的狀態 | 仍須同時檢查可售庫存與其他限制 |
| 下架 | Unpublished | 商品或 SKU 不接受新的購買行為 | 舊訂單快照仍可顯示 |
| 組裝清單 | BuildConfiguration | 使用者選擇的一組電腦零件與組裝設定 | 不是訂單，也不保留庫存 |
| 組裝清單項目 | BuildConfigurationItem | 組裝清單內的一個 SKU 與數量 | 結帳時仍需重新驗證 |
| 相容性檢查結果 | CompatibilityCheckResult | 確定性規則針對組裝清單產生的通過、警告或失敗結果 | AI 說明不能取代此結果 |
| 組裝服務費 | AssemblyFee | 每台實際組裝電腦收取的固定 NT$300 服務費 | 不參與一般商品折扣 |
| 組裝工作 | AssemblyJob | 訂單內單一台客製組裝電腦的獨立作業與進度紀錄 | 同一組裝清單購買多台時，每台各建立一筆 |
| 套裝電腦 | PrebuiltComputer | 商家或品牌預先定義好固定規格的整機商品 | 不當然等同顧客客製組裝商品 |
| 客製組裝電腦 | CustomBuiltComputer | 依顧客選定零件提供組裝服務的電腦 | `AssemblyStarted` 後有不同取消規則 |

## 庫存

| 中文名稱 | 建議英文名稱 | 定義 | 不包含／備註 |
|---|---|---|---|
| 實體在庫 | OnHandQuantity | 單一倉庫內目前實際存在的 SKU 數量 | 出貨時減少，訂單完成時不再減少 |
| 保留庫存 | ReservedQuantity | 已被有效訂單保留、尚未出貨的 SKU 數量 | 購物車不會增加此數量 |
| 可售庫存 | AvailableQuantity | 目前還能被新訂單保留的數量 | `OnHandQuantity - ReservedQuantity`，建議計算而非獨立真實來源 |
| 補貨水位 | ReorderLevel | 用於判斷低庫存提示的門檻 | 不會自動建立採購單 |
| 庫存保留 | InventoryReservation | 訂單建立時對特定 SKU 數量及到期時間的保留紀錄 | 必須可消耗、釋放或逾時 |
| 庫存異動 | InventoryMovement | 保留、釋放、出貨、退回及人工調整的不可變歷程 | 不以直接刪除修改歷史 |
| 已售數量 | SoldQuantity | 由訂單與出貨資料統計的銷售量 | 不是第三個實體庫存桶 |
| 併發權杖 | RowVersion | 用於偵測同一筆庫存被同時修改的資料庫版本 | 最後防線仍需正確交易與條件更新 |
| 超賣 | Overselling | 接受超過可售數量的訂單 | 本專案不允許 |

## 購物、訂單與金額

| 中文名稱 | 建議英文名稱 | 定義 | 不包含／備註 |
|---|---|---|---|
| 購物車 | Cart | 下單前暫存 SKU、數量與組裝群組的集合 | 價格為預覽，不保留庫存 |
| 結帳 | Checkout | 重新驗證商品、價格、折扣、庫存、配送及相容性並嘗試建立訂單的流程 | 不等同付款成功 |
| 訂單 | Order | 結帳成功後建立、具有固定編號與交易快照的商業交易 | 訂單與付款、物流、退貨狀態分開 |
| 訂單明細 | OrderItem | 訂單中一個 SKU 的數量、成交單價、單位成本與商品快照 | 可成為單項退貨標的；單位成本用於歷史毛利 |
| 交易快照 | TransactionSnapshot | 訂單成立時保存的商品、價格、折扣、收件資料與政策版本 | 日後來源資料變動不得回寫舊快照 |
| 訂單收件快照 | OrderRecipientSnapshot | 訂單成立時保存的收件人、電話、地址、配送及必要聯絡資料 | 與會員目前個資分開；履約角色只能在該筆訂單範圍使用 |
| 商品小計 | MerchandiseSubtotal | 商品特價後、訂單級優惠券前的符合定義商品金額合計 | 不含運費與組裝費 |
| 折扣分攤 | DiscountAllocation | 將訂單級優惠按規則分配至各訂單明細的金額 | 用於部分退貨與退款重算 |
| 應付總額 | GrandTotal | 後端依固定計算順序產生的訂單最終應付金額 | 前端傳入值不可信任 |
| 取消訂單 | OrderCancellation | 商品尚未依限制履行時終止整筆訂單 | 只支援整筆取消，不等同退貨 |
| 訂單到期 | OrderExpiration | 未在付款期限內完成付款而由系統終止訂單 | 需釋放庫存並按規則返還優惠券次數 |
| 訂單完成 | OrderCompletion | 商品已交付且必要付款完成後的訂單終態 | 不在此時再次扣實體庫存 |

|---|---|---|---|

## 付款、物流、退貨與退款

| 中文名稱 | 建議英文名稱 | 定義 | 不包含／備註 |
|---|---|---|---|
| 付款 | Payment | 一次付款嘗試或付款紀錄，包含方式、金額、期限與狀態 | 退款不得混入付款狀態 |
| 貨到付款 | CashOnDelivery, COD | 宅配送達或超商取貨完成時才確認收款的付款方式 | 第一版一般宅配與超取可用，上限 NT$20,000，排除組裝電腦與限制品 |
| 付款閘道 | PaymentGateway | 系統用來建立付款、查詢及接收回呼的抽象介面 | 第一版實作為模擬服務 |
| 付款回呼 | PaymentCallback | 付款服務通知結果的請求 | 必須驗證並具冪等性 |
| 冪等 | Idempotency | 同一請求或回呼重複處理不會重複產生副作用 | 付款、退款、釋放庫存特別重要 |
| 配送方式 | ShippingMethod | 超商取貨、一般宅配或組裝電腦宅配等履約選項 | 各自具有費用、免運與限制 |
| 物流／履約 | Fulfillment | 從備貨、出貨到送達或取貨完成的履行流程 | 不用訂單狀態取代完整物流狀態 |
| 物流單 | Shipment | 一次實際或模擬配送的紀錄 | 第一版一張訂單只有一種配送方式與一張主要物流單 |
| 包裹限制版本 | ShippingConstraintPolicyVersion | 一組可追溯的超商尺寸與重量限制設定 | 修改只影響生效後的新交易；訂單保存成立時版本快照 |
| 送達時間 | DeliveredAt | 宅配交付完成或超商取貨完成的時間 | 一般退貨期限以到貨翌日起算 |
| 退貨申請 | ReturnRequest | 顧客針對一或多個訂單明細提出的售後申請 | 訂單只能整筆取消，但可單項退貨 |
| 退貨項目 | ReturnItem | 退貨申請中指定的訂單明細、數量、原因及證據 | 不直接代表退款成功 |
| 退貨檢查 | ReturnInspection | 商家收回商品後記錄完整度、使用狀況、瑕疵與處置的流程 | 結果決定回補庫存與退款金額 |
| 退款 | Refund | 將已收款項依審核結果退回的財務處理 | 可部分退款，需人工審核與歷程 |
| 退款項目 | RefundItem | 退款金額對應的退貨商品、折扣、運費、組裝費或調整項 | 支援可解釋的退款明細 |
| 部分退款 | PartialRefund | 只退回訂單總付款的一部分 | 不代表部分取消訂單 |
| 政策版本 | PolicyVersion | 結帳時適用的退貨、運費或其他商業規則版本 | 訂單須保存當時版本或快照 |

## 容易混淆的概念

| 不可混用 | 正確區分 |
|---|---|
| Product 與 SKU | Product 管共用展示；SKU 才是可定價、可庫存、可下單單位 |
| Cart 與 Order | Cart 可隨時重算且不保留庫存；Order 是成立後的交易與快照 |
| OrderStatus 與 PaymentStatus | 訂單生命週期與付款結果獨立保存 |
| PaymentStatus 與 RefundStatus | 付款成功後才可能退款；退款有自己的申請與交易狀態 |
| FulfillmentStatus 與 OrderStatus | 配送失敗不應直接覆蓋整體訂單歷程 |
| Cancel 與 Return | 履約前終止是取消；交付後把商品送回是退貨 |
| Return 與 Refund | 收回或檢查商品是退貨；退回金錢是退款 |
| ReservedQuantity 與 SoldQuantity | 前者是尚未出貨的保留；後者是報表統計值 |
| Application Log 與 AuditLog | 前者診斷系統；後者追蹤誰修改重要商業資料 |
| AI 推薦與相容性判定 | AI 解讀需求與解釋；後端確定性規則負責最終判定 |

## 維護規則

- 新增 Entity、狀態 Enum、核心 DTO 或報表指標前，先檢查本表是否已有對應語彙。
- 若同一概念出現第二個英文名稱，必須在 Code Review 前統一。
- 已發布名稱如需變更，必須同時更新名詞表、API 契約、資料模型、測試與受影響文件，不可只改單一程式專案。
- 狀態機確認後，本表的狀態名稱需同步以 [[03-架構/狀態機設計]] 為準。
- 報表公式完成後，另將指標定義補入本表或專用報表字典。
