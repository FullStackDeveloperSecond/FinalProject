# 角色與權限

狀態：已確認

## 前台參與者

前台的「參與者」不一定都是資料庫 RBAC 角色。

| 參與者 | 說明 |
|---|---|
| 匿名訪客 | 未登入，可瀏覽、AI 搜尋、購物車及訪客結帳 |
| 已驗證訪客購買者 | 以訂單 Email 一次性驗證取得單筆訂單的短效存取權 |
| 會員 | 已驗證 Email 的註冊使用者 |
| 已購買會員 | 具有已完成訂單的會員，符合條件時可評價商品 |
| 停權會員 | 帳號狀態受限，不是獨立角色 |

實際前台帳號的基本角色為 `Member`。訪客沒有帳號；已購買資格由訂單動態判斷；停權使用帳號狀態表達。

## 訪客訂單授權

流程：

```text
輸入訂單編號與購買 Email
→ 寄送一次性驗證碼或驗證連結
→ 驗證成功
→ 核發短效 GuestOrderAccessToken
→ 僅能操作該筆訂單
```

要求：

- Token 只能存取指定訂單。
- 建議有效時間 30 分鐘。
- 限制驗證碼發送與輸入次數。
- 錯誤訊息不得洩漏訂單是否存在。
- 重要操作可以要求再次確認。
- 訪客不能使用 AI 客服或存取其他訂單。

## 後台角色

一位管理員可以擁有多個角色，第一版以角色層級控制權限。

- 多角色權限使用各角色允許權限的聯集，不設顯式 Deny。
- 敏感操作不只檢查角色名稱，需使用明確 Authorization Policy 驗證角色、資源範圍及業務前置條件。
- `SuperAdmin` 具有全域允許權限，但仍必須完成管理員 2FA，且個資、高風險庫存、退款、權限及設定操作仍需稽核。

| 角色 | 負責範圍 |
|---|---|
| `SuperAdmin` | 所有功能、角色及系統設定 |
| `CatalogManager` | 商品、SKU、分類、品牌、規格、圖片及上下架 |
| `InventoryManager` | 庫存、保留庫存、手動釋放、庫存異動及低庫存管理 |
| `OrderManager` | 訂單、取消、出貨、物流、退貨流程及包裹限制維護 |
| `FinanceManager` | 付款、退款、優惠券及財務報表 |
| `CustomerService` | 客服案件、評價審核及檢舉處理 |
| `CustomerServiceSupervisor` | 具一般客服權限，另可指派、轉派、覆核優先級、處理 SLA 升級及查看客服報表 |
| `MarketingAnalyst` | 優惠活動、優惠券及一般營運報表 |
| `PrivacyAdmin` | 查看完整會員個資及個資處理 |

### 客服工作台權限

- 一般客服案件進入自領佇列，`CustomerService` 可以領取未指派的一般客服案件。
- `CustomerServiceSupervisor` 可以指派及轉派一般客服案件，並覆核客服調整的優先級。
- 統一工作台會顯示客服、檢舉及退貨摘要，但不因此授予跨領域處理權限。
- 檢舉及退貨保留各自佇列，只有具該領域權限的角色可以承接及處理。
- 所有自領、指派、轉派、優先級異動及 SLA 升級都必須留下歷程與稽核紀錄。

## 個資存取

- 一般客服只看得到遮蔽後的 Email、電話及必要訂單資訊。
- `OrderManager` 可以查看完成履約所需的訂單收件快照，包括收件人、電話、地址、配送方式及必要聯絡資料；此權限不延伸到會員完整檔案或其他訂單。
- 訂單收件快照與會員目前資料分開保存；會員日後修改個資不改變既有訂單。
- `PrivacyAdmin` 與 `SuperAdmin` 才能查看完整會員檔案。
- 查看完整個資本身也必須留下稽核紀錄。

## 庫存與物流高風險操作

- `InventoryManager` 與 `SuperAdmin` 可以手動釋放仍為 `Active` 的庫存保留；必須二次確認、填寫原因並稽核。
- `OrderManager` 與 `SuperAdmin` 可以修改超商包裹限制；修改必須建立設定版本。
- `OrderManager` 與 `SuperAdmin` 可以新增、編輯或停用示範門市；`CatalogManager` 只有檢視權限。已被訂單引用的門市不得實體刪除，所有異動使用 RowVersion 並寫入 AuditLog。
- `OrderManager` 可以執行批次出貨，但每筆訂單仍需獨立通過狀態、付款、組裝、庫存及物流驗證。

## 管理員登入安全

- 管理員強制啟用 TOTP 雙因素驗證。
- 支援 Google Authenticator 與其他標準 TOTP App。
- 支援 QR Code 綁定、Recovery Codes、重新綁定與解除流程。
- Recovery Code 使用及 2FA 設定異動必須稽核。

## 稽核紀錄

重要商業操作應寫入資料庫 `AuditLog`，不能只依賴一般文字 Log。

至少記錄：

```text
ActorUserId
ActorRole
Action
EntityType
EntityId
BeforeValue
AfterValue
OccurredAt
IpAddress
TraceId
```

涵蓋商品、庫存、訂單、出貨、退貨、退款、完整個資存取及角色變更。
