# 商品搜尋、組裝、客服與報表驗收規格

本文件補齊目前可由正式規則直接產生的 M 功能使用案例。CSV 三資料集封裝、客服完整資料模型及報表全部公式仍按追蹤項目保留。

## UC-SEARCH-01｜一般商品搜尋與篩選

**角色**：匿名訪客、會員

**驗收條件**：

- Given 使用者輸入關鍵字，When 搜尋，Then 預設依相關度、上架時間、SKU Code 穩定排序。
- Given 沒有關鍵字，When 瀏覽商品，Then 預設依近期銷售熱度、上架時間、SKU Code 排序。
- Given 同時選擇分類、價格及品牌，Then 不同群組使用 AND；同一品牌多選使用 OR。
- Given 使用分類規格篩選，Then 只能使用該分類公開白名單欄位。
- Given 商品下架、SKU 停用或不可售，Then 不出現在可購買結果。
- Given 無結果，Then 保留條件並顯示可移除的限制，不產生虛構商品。
- Given 排序或篩選欄位不在白名單，Then API 回傳 400 與穩定錯誤碼。

## UC-IMPORT-01｜預覽並提交商品批次匯入

**角色**：`CatalogManager`、`SuperAdmin`

**驗收條件**：

- Given 管理員上傳支援的 XLSX 或 CSV 資料，Then 系統辨識 Product、SKU、Specification 三個邏輯資料集。
- Given 分類、品牌或規格語意鍵不存在，Then 預覽回傳 `import_lookup_not_found`，不得隱式建立 Lookup。
- Given 空白 SKU Code，Then 視為新增；Given 既有 Code，Then 精確更新且不得改寫 Code。
- Given 同批重複 SKU Code 或更新目標不存在，Then 列出資料集、列、欄位、錯誤碼及訊息。
- Given 預覽有任一錯誤，Then 禁止提交整批；合法列也不得先寫入。
- Given 預覽全部合法且管理員確認，Then 在單一資料庫交易內寫入，任一失敗整批回滾。
- Given 來源檔或資料在預覽後失效，Then 提交回傳 `import_preview_expired`，要求重新預覽。

CSV 三資料集使用三檔、ZIP 或分開入口仍待 DOM-10 決策。

## UC-BUILD-01｜建立、保存、分享與購買組裝清單

**角色**：匿名訪客、會員

**驗收條件**：

- Given 訪客建立清單，Then 保存於瀏覽器本地；Given 會員建立清單，Then 可保存至伺服器並跨裝置存取。
- Given 訪客登入，Then 可將本地清單匯入會員帳號，不覆蓋既有組裝清單。
- Given 會員建立分享，Then 產生不可預測、唯讀連結，且不包含建立者個資。
- Given 建立者撤銷、刪除清單或帳號停權，Then 分享連結立即失效。
- Given 分享頁重新開啟，Then 重新驗證價格、庫存、上架與相容性。
- Given 同一清單購買多台，Then 依總數原子保留零件，每台建立獨立 `AssemblyJob`，組裝費為每台 NT$300。

## UC-COMPAT-01｜確定性零件相容性檢查

**角色**：匿名訪客、會員、具規則查看權限的管理員

**驗收條件**：

- Given CPU 與主機板 Socket 不同、DDR 世代不符或零件尺寸超限，Then 結果為不相容並阻止組裝結帳。
- Given 主機板晶片組與 CPU 世代可能需要 BIOS 更新，Then 顯示警告，不把未知 BIOS 最低版本假定為通過保證。
- Given PSU 功率不足，Then 使用結構化功耗加 30% 向上取級距，並與 GPU 建議值取較高者。
- Given AI 宣稱組合相容但後端規則不通過，Then 以後端 `CompatibilityCheckResult` 為準。
- Given 管理員停用規則或調整允許門檻，Then 需通過權限、範圍、rowversion 與 Audit Log。

PSU 實際級距、規則門檻上下限仍由 DOM-02、DOM-12 追蹤。

## UC-SUPPORT-01｜建立、承接與處理客服案件

**角色**：會員、`CustomerService`、`CustomerServiceSupervisor`

**驗收條件**：

- Given 未登入訪客，When 建立人工客服案件，Then API 拒絕。
- Given 會員建立案件，Then 保存分類、主旨、公開訊息、可選訂單關聯及最多 3 個合法附件。
- Given 案件未指派，Then 進入共用佇列；兩位客服同時自領時只有一位成功。
- Given 主管指派或轉派，Then 保存原負責人、新負責人、操作者、時間與原因。
- Given 內部備註，Then 只回傳後台，不出現在顧客端或外部 AI Context。
- Given 顧客於 Open／Assigned 且尚無人工公開回覆，Then 可取消；超過邊界回傳 `support_ticket_cancel_not_allowed`。
- Given 承辦客服於 InProgress 取消，Then 必須填寫原因並保存歷程。

## UC-SUPPORT-02｜客服附件安全處理

**角色**：會員、具案件存取權限的客服

**驗收條件**：

- Given 每案超過 3 個、單檔超過 10 MB 或格式不是 PNG／JPG／PDF，Then 上傳被拒絕。
- Given 副檔名、MIME 與檔案簽章不一致，Then 回傳 `attachment_format_invalid`。
- Given Defender 不可用、逾時或結果不明，Then採 Fail Closed，不保存檔案。
- Given 掃描確認安全，Then 以伺服器產生的私有名稱保存於網站根目錄外。
- Given 未登入、非案件參與者或其他領域角色，When 下載，Then 授權 API 拒絕且不洩漏實體路徑。

## UC-SLA-01｜客服 SLA 計時、提醒與結案

**角色**：客服、客服主管

**驗收條件**：

- Given 案件建立，Then 依 Low／Normal／High／Urgent 的首回與結案期限，以 UTC 及 24×7 日曆時間計算。
- Given AI 回答或內部備註，Then 不計為首次人工公開回覆。
- Given 進入 `WaitingForCustomer`，Then 結案 SLA 最多暫停 3 天；`WaitingForInternal` 不暫停。
- Given 使用 80% 時間，Then 通知負責人；Given 達 100%，Then 標記 Overdue、通知負責人與主管並置頂。
- Given Resolved 後 3 天內重開，Then 保留首回結果，從重開時間重算結案期限。
- Given Resolved 連續 3 天未重開，Then 自動轉 Closed；後續問題建立關聯新案件。

## UC-WORKBENCH-01｜統一案件工作台

**角色**：具相應案件領域查看權限的管理員

**驗收條件**：

- Given 客服、檢舉與退貨資料存在，Then 工作台以共同 attentionLevel、dueAt、createdAt、領域與穩定 ID 顯示摘要。
- Given 項目已逾時，Then 排在未逾時之前；其後依注意等級、最早期限、最早建立時間及穩定 ID 排序。
- Given 項目沒有期限，Then 排在有期限項目之後。
- Given 操作者只有客服權限，Then 可看到授權客服摘要，不因統一畫面取得退貨或檢舉處理權。
- Given 從摘要執行操作，Then 導向原領域 Use Case 並重新驗證權限及狀態。

精確 Response DTO 與三領域資料模型仍由 DES-13 追蹤。

## UC-REPORT-01｜查詢 M 營運報表

**角色**：具有對應報表權限的管理員

**驗收條件**：

- Given 管理員選擇日期、分類、品牌與訂單狀態，Then 後端以 SQL Server 彙總並明示指標使用的時間基準。
- Given 查詢毛利，Then 使用 OrderItem 成交成本快照，不使用目前 SKU 成本回推。
- Given 查詢 ABC，Then 以完成訂單扣除成功退款的 SKU 淨營收排序並套用 80%／95% 門檻。
- Given 關聯組合低於共同訂單、Support、Confidence 或 Lift 門檻，Then 不顯示為有效配對。
- Given 預測資料少於 14 天，Then 顯示資料不足；標準差為零時不產生 Z-score 異常。
- Given 操作者沒有報表權限，Then API 回傳 403；前端隱藏畫面不能取代 API 授權。

一般指標公式、同期與退款跨月歸屬仍由 DATA-01、DATA-02 追蹤。

## 尚未涵蓋

- PSU 資料來源與規則門檻：DOM-02、DOM-12。
- 客服／檢舉／退貨完整資料模型與統一 Response：DES-13。
- 客服優先級詳細判定及 SLA 報表公式：CS-02、CS-04。
- 全部報表指標公式與時間歸屬：DATA-01、DATA-02。
