# 商品、組裝與相容性

狀態：已確認

## 商品目錄

第一版商品目錄包含：

- 商品
- SKU 與商品變體
- 品牌
- 分類
- 標籤
- 商品規格
- 多張商品圖片及排序
- 草稿、上架、下架狀態
- 售價及特價
- 搜尋與篩選
- 庫存狀態

商品範圍包含單一電腦零件、周邊商品、品牌套裝電腦及自由組裝電腦。

### 搜尋、篩選與排序

- 有關鍵字時預設依文字與結構化欄位的相關度排序；沒有關鍵字的一般瀏覽預設依近期銷售熱度排序。
- 同值時依上架時間，再依不可變 SKU Code 排序，確保分頁結果穩定。
- 不同篩選群組使用 AND，例如品牌條件、價格區間、分類及庫存需同時成立。
- 同一多選欄位內使用 OR，例如品牌可同時選擇 ASUS 或 MSI。
- 商品規格只允許該分類範本公開的白名單欄位，不接受任意欄名、查詢運算式或 SQL。
- 下架商品與停用 SKU 不出現在可購買搜尋結果；缺貨商品不混入預設可購買結果。
- 沒有結果時保留目前篩選條件並說明可能限制，提供移除條件或改用一般瀏覽的操作，不虛構商品。

### 商品與 SKU 資料來源

- 有變體商品由多個 SKU 分別保存售價、庫存、規格值與上下架狀態。
- 非變體商品仍建立一個預設 SKU；後台顯示的基本售價與庫存欄位實際讀寫該預設 SKU。
- `Product` 不另存一套可與 SKU 不一致的售價或庫存來源。
- 商品列表可以顯示變體數量、SKU 明細、價格區間與加總庫存，但這些都是 SKU 資料的衍生結果。

### 功耗資料來源與可信度

- CPU 優先採原廠公開的 TDP／Processor Base Power／Maximum Turbo Power；GPU 優先採原廠公開的 TBP／TGP 與建議 PSU。欄位必須標示功耗語意，不得把不同指標無說明混為同一值。
- 每筆用於相容性計算的功耗值保存 `SourceType`、來源 URL、提供者、擷取／覆核時間、原始欄位名稱、單位、人工覆核者與資料版本。
- 原廠未提供時，可使用有清楚測試方法或廠商文件的人工維護值；管理員必須附來源與備註，不能由 AI 或商品描述自動猜值。
- 主機板、記憶體、儲存、風扇、散熱與其他零件使用分類固定的保守功耗估值或結構化 SKU 值；固定值必須有版本並顯示為「系統估值」，不冒充原廠規格。
- CPU、GPU 或其他使 PSU 結果不可可靠計算的核心值缺失時，相容性結果為 `InsufficientData`，顯示「資料不足，需人工確認」，不得宣稱相容，也不得一鍵將整套組裝加入購物車。
- 資料不足不禁止使用者單獨購買該 SKU；阻擋範圍只限宣稱完整組裝相容與一鍵加入整套清單。使用者仍可返回修改或聯絡人工客服。
- AI 只能解釋後端提供的來源與結果，不可補造瓦數、以相近型號代替或把警告改成相容。

### SKU 生命週期

- SKU Code 建立後不可修改；編輯既有 SKU 時欄位必須鎖定。
- 已被商品、訂單、庫存、保留、組裝清單或其他資料引用的 SKU 不能實體刪除，只能停用或下架。
- 只有從未被引用、沒有庫存或保留、且仍屬草稿資料的誤建 SKU 才能實體刪除。
- 下架或停用不影響既有訂單快照與歷史報表。

### 後台批次操作與 Excel

優先級：M。

- 商品列表支援批次上架、批次下架及批次調價。
- 支援將商品資料匯出為 XLSX 或 CSV。
- 支援透過 XLSX 或 CSV 批次建立或更新商品。
- 匯入欄位必須能對應分類及規格範本。
- 匯入內容分成 `Product`、`SKU`、`Specification` 三個邏輯資料集，以穩定匯入鍵及 SKU Code 建立關聯。
- 分類、品牌及規格語意鍵只可引用系統既有 Lookup，不得因匯入內容隱式建立新值。
- Excel 匯入先完整驗證所有資料並顯示預覽，管理員確認後才寫入。
- 預覽至少顯示新增、更新、無變更及錯誤筆數。
- 每個錯誤需包含資料集／工作表、列、欄位、穩定錯誤碼及安全訊息，並可下載錯誤資料。
- 寫入採單一資料庫交易；任一筆失敗時整批回滾，不允許部分成功。
- SKU Code 為不可變識別碼：空白 SKU Code 表示新增；既有代碼表示精確更新，但不可改寫代碼本身。
- 同一匯入檔出現重複 SKU Code，或指定更新的 SKU Code 不存在時，整批拒絕並回傳逐列錯誤。
- CSV 使用三個獨立上傳欄位，分別接收 Product、SKU、Specification；必須三份共同完成驗證、預覽及單一交易原子提交，不允許只提交其中一份形成部分更新。
- XLSX 與 CSV 接受目前模板版本及前一版本；前一版本先轉換成目前內部格式，再執行同一套欄位與商業驗證。不支援的版本整批拒絕並提供目前模板。
- 三個 CSV 共用 Multipart Request 的 `templateVersion` 欄位；檔案內不重複保存版本。後端以同一版本解析三份資料，缺少或不支援版本時整批拒絕。
- CSV 固定使用 UTF-8 with BOM、逗號分隔、雙引號跳脫與固定英文 Header。Header 必須完整一致；Null 與空字串是不同語意，日期及小數採不受本機語系影響的固定格式。
- 商品匯入不得直接設定或改寫庫存。初始庫存及後續批次調整使用獨立 Inventory Import／Adjustment，必須保存原因並建立 `InventoryMovement`。
- 精確欄位型別、Header、大小、列數及 Endpoint 見 [[03-架構/03-資料與一致性/匯入暫存與庫存調整設計]]；不得改用商品名稱或規格文字推測更新目標。
- 匯入預覽保存於 `ImportBatch`／`ImportRow` Staging，期限 24 小時；提交時重新驗證擁有者、模板版本、內容 Hash 與目前 Lookup／SKU 狀態。
- CSV Null 使用 `\N`；空欄代表空字串。日期採 ISO 8601、小數使用 `.`，不得依 Excel 或 Windows 地區設定自動猜測。

### 商品特價

- 同一 SKU 的有效特價期間不得重疊，建立或修改時直接拒絕衝突期間。
- 商品特價先於優惠券計算；特價後仍可套用一張符合條件的優惠券，除非該優惠券明確排除特價商品。
- 訂單需分別保存原價、特價及優惠券折扣快照，使退貨與退款可還原計算過程。

## 分類與規格範本

- 管理員可以動態新增規格欄位，並維護顯示名稱、排序、必填及啟用狀態。
- 不同分類使用各自的規格範本，新增或編輯商品時依分類顯示對應欄位。
- 規格欄位至少需要穩定識別碼、不可變的語意鍵、顯示名稱、資料型別、是否必填、排序及啟用狀態。
- 已被商品資料、Excel 範本、搜尋篩選或相容性規則使用的欄位只能停用，不可實體刪除。
- 已被使用欄位的穩定識別碼、語意鍵及資料型別不可變；顯示名稱與排序可以修改。
- 只有從未被使用且沒有任何相依資料的欄位可以實體刪除。
- `SkuSpecificationValue` 依規格定義型別，在同一資料表使用互斥的 String／Decimal／Boolean／Option 值欄位；Check Constraint 保證每列只有正確的一種值。
- 第一版實體欄位固定為 `StringValue`、`DecimalValue`、`BooleanValue`、`OptionId` 四擇一；整數由 Decimal 的小數位限制表達，不另建 Integer 欄位。
- 規格單位使用 `MeasurementUnit` 參照資料，規格定義引用穩定 Unit Code；規格值不重複保存單位文字。
- Option 型規格由 `SpecificationDefinition.AllowsMultiple` 明確區分單選與多選；只有 `ValueType=Option` 才能啟用多選。單選仍使用 `SkuSpecificationValue.OptionId`，多選改用正規化的 `SkuSpecificationOptionSelection` Join Entity，一列代表一個選項，不把多值塞入逗號字串、自由文字或 JSON。
- 每筆多選關聯可各自保存 `SpecificationSourceId`；參與硬性相容規則的每個已選選項都必須有已覆核來源，不能只在整組規格上掛一個來源。
- 核心搜尋、篩選及相容性規格必須使用結構化欄位；任意 JSON 只能保存有版本且不參與核心完整性判斷的輔助內容。
- 商品標籤、分類關聯與其他多對多資料使用明確 Join Entity，不以逗號字串或 JSON 陣列取代關聯。

> [!important] 受保護語意鍵
> 固定相容性程式以受保護語意鍵尋找 Socket、TDP、GPU 長度等結構化規格，不依賴可變的顯示名稱。被規則引用的語意鍵及資料型別不可刪除或變更，因此分類與規格範本仍可動態維護，而相容性程式保有穩定契約。

受保護規格的 Category Code／SemanticKey 組合由程式碼目錄定版；管理員可以調整顯示名稱、排序與允許的警告設定，但不能變更受保護規格的分類、語意鍵、型別、單位或多選屬性。新增或調整相容性硬規格時，必須先更新程式碼目錄、來源要求與回歸測試。

## 相容性規則

第一版必須驗證：

1. CPU Socket 與主機板 Socket 相同。
2. 主機板晶片組支援 CPU 世代。
3. 第一版以主機板晶片組與 CPU 世代映射阻擋不支援組合；已知可能需要更新 BIOS 時顯示警告，不維護每張主機板與 CPU 組合的最低 BIOS 版本。
4. 主機板與記憶體 DDR 世代相同。
5. 記憶體數量不超過主機板插槽數。
6. 記憶體總容量不超過主機板支援上限。
7. 主機板尺寸能安裝於機殼。
8. 顯示卡長度不超過機殼限制。
9. 散熱器支援 CPU Socket。
10. 散熱器高度不超過機殼限制。
11. 儲存裝置介面有對應主機板插槽。
12. 電源額定瓦數不得低於「結構化功耗估值加總後增加 30% 餘裕並向上取常見 PSU 級距」與「GPU 廠商建議瓦數」兩者中的較高值。
13. 電源具有必要供電接頭。

第一版 PSU 常見級距固定為：`450`、`550`、`650`、`750`、`850`、`1000`、`1200`、`1500` W。計算結果超過 1500 W 時不得自動選擇不存在的級距，需回傳無合適 PSU 的阻擋結果。

必要規格應使用結構化欄位，不得只保存成人類描述文字。其他展示型規格可以使用較彈性的規格資料。

硬性相容性判斷只讀取帶有已覆核 `SpecificationSource` 的核心值或選項。來源缺失、未覆核、語意鍵缺失或型別不符時，結果必須為 `InsufficientData` 並阻擋結帳；不得把缺值視為相容、以預設值補齊或交由 AI 猜測。第一版 CPU／主機板判斷使用專案內固定且有官方證據的「CPU 世代／Socket ↔ 晶片組」映射；證據索引見 [[知識點/CPU與晶片組相容性官方證據]]。

### 相容性規則後台

- 相容性規則程式由開發者維護，管理員不能在後台新增、修改或刪除規則程式。
- 管理員可以查看現有規則。
- 管理員可以啟用或停用整條規則，並調整規則明確開放的警告門檻；硬性不相容條件及比較運算式不可調整。
- 只有可量化的警告餘裕可設定，例如 PSU 餘裕或尺寸接近上限；每個門檻都必須有程式固定的安全上下限。
- 管理員可以選擇商品或 SKU 執行規則測試並查看結果。
- 管理員不能修改比較運算式、規格語意鍵或規則程式。
- 可設定門檻的資料型別與上下限、測試輸入輸出格式、操作權限、併發及稽核欄位見 [[03-架構/07-領域設計/相容性規則後台設計]]。

## AI 推薦流程

```text
使用者輸入自然語言需求
→ AI 擷取預算、用途、規格與品牌偏好
→ 後端查詢上架且有庫存的候選 SKU
→ 後端相容性規則驗證
→ 排序候選組合
→ AI 只針對已驗證結果產生推薦理由
```

推薦必須：

- 說明推薦原因。
- 顯示預算使用情況。
- 不推薦下架或不可售商品。
- 不把 AI 文字聲明當作相容性保證。
- AI 不可用時改用一般關鍵字搜尋與篩選。

## 組裝清單

組裝清單包含：

```text
BuildConfiguration
├─ BuildConfigurationItem
└─ CompatibilityCheckResult
```

規則：

- 會員可以將組裝清單保存到伺服器並跨裝置存取。
- 訪客使用瀏覽器本地儲存保存草稿。
- 訪客登入後可以將本地清單匯入會員帳號。
- 組裝清單可以產生不可預測、唯讀的分享連結。
- 分享連結預設不自動到期，可由建立者主動撤銷；原清單刪除或建立者帳號停權時立即失效。
- 分享頁不得包含建立者姓名、Email、購物車、訂單或會員資料。
- 分享清單可複製，不可修改原建立者清單。
- 每次開啟分享頁都重新驗證價格、庫存、上下架及相容性。
- 組合內任何必要零件缺貨或不可售時，整組不能直接結帳，必須先更換零件。

## 加入購物車

組裝電腦在畫面上以群組顯示，但底層保留每一個 SKU：

```text
自訂電腦組合
├─ CPU SKU
├─ 主機板 SKU
├─ 記憶體 SKU
├─ 顯示卡 SKU
├─ 儲存裝置 SKU
├─ 電源 SKU
├─ 機殼 SKU
├─ 散熱器 SKU
└─ 組裝服務費 NT$300
```

每一台實際組裝電腦收取一次 NT$300。例如同一訂單購買三台組裝電腦，組裝費為 NT$900。

同一組裝清單允許購買多台：

- 結帳時依購買台數計算所有零件需求，並在同一交易中原子檢查及保留總庫存。
- 每台客製組裝電腦建立獨立 `AssemblyJob`，可分別追蹤組裝、測試及完成狀態。
- 任一必要 SKU 的總可售數量不足時，整個訂單建立失敗，不做部分保留。

## 組裝生命週期

```text
Draft
→ Submitted
→ Paid
→ AssemblyPending
→ AssemblyStarted
→ Testing
→ ReadyToShip
→ Shipped
```

- `AssemblyStarted` 之前可以取消。
- 開始組裝後不接受無理由取消，但瑕疵、規格錯誤或組裝錯誤仍需處理。
- 分享連結被撤銷、清單刪除或建立者帳號停權時，API 統一回 404；前台顯示「此組裝清單目前無法使用」，不揭露不存在或失效的具體原因，並提供返回組裝首頁入口。
