# 購物車、訂單、付款與物流

狀態：已確認

## 購物車

- 訪客與會員都能使用購物車。
- 組裝電腦以群組呈現，但保留個別 SKU。
- 開啟購物車與結帳前重新檢查商品、價格、折扣、庫存及相容性。
- 購物車中的金額僅供預覽，訂單金額由後端計算。

### 訪客登入後合併

- 一般 SKU 同時存在於訪客與會員購物車時，數量相加。
- 組裝電腦維持各自的組裝群組，不因零件 SKU 相同而拆散或合併群組。
- 合併後超過購買上限或可售數量時不自動截斷，保留項目並標示需要使用者調整。
- 價格改變、庫存不足、商品下架或相容性失效時，保留項目並顯示衝突原因。
- 所有衝突完成價格確認、數量調整、零件替換或移除前，購物車不得進入結帳。
- 合併操作需具冪等性，重新整理或重送不得重複增加數量。

## 結帳

支援：

- 會員結帳。
- 訪客結帳。
- 多個 SKU。
- 優惠券。
- 組裝費。
- 宅配與超商取貨。
- 模擬付款。
- 收件資料與訂單快照。

訪客完成結帳後，以訂單編號及 Email 一次性驗證查詢訂單。

## 訂單狀態

訂單、付款、物流與退款不得只用一個狀態表達，至少分開保存：

```text
OrderStatus
PaymentStatus
FulfillmentStatus
OrderRefundStatus
RefundTransactionStatus
```

訂單需保存狀態歷程及每次變更原因。

### 後台狀態呈現與操作

- 後端仍分別保存 `OrderStatus`、`PaymentStatus`、`FulfillmentStatus`、`OrderRefundStatus` 與 `RefundTransactionStatus`。
- 後台提供主要摘要狀態，但不得另存一個取代上述狀態機的欄位。

| 主要摘要 | 推導條件 |
|---|---|
| 待付款 | `OrderStatus = PendingPayment` |
| 處理中 | `OrderStatus = Confirmed/Processing`，且尚未符合待出貨或配送中條件 |
| 待出貨 | 訂單付款條件已滿足、必要組裝已 `ReadyToShip`，且物流仍為 `Pending/Preparing` |
| 配送中 | 物流為 `Shipped/InTransit/PickupReady` |
| 已完成 | `OrderStatus = Completed` |
| 已取消 | `OrderStatus = Cancelled` |

- 付款失敗／等待 COD、退貨中、部分退款及已退款另以徽章呈現，不改寫主要摘要。
- 主要摘要用於顯示與篩選；若摘要與徽章同時存在，兩者均回傳，前端不得用徽章覆蓋摘要。
- 列表篩選使用可重複的 `summaryStatus` 與 `badge`；同一參數多值使用 OR，摘要與徽章兩群組同時出現時使用 AND。
- 未知摘要或徽章值回傳 400，不靜默忽略。
- 後台依目前狀態、付款、組裝、物流及操作者權限顯示合法操作，例如開始備貨、建立出貨、取消訂單。
- 不提供可直接指定任意下一狀態的通用下拉選單；每個操作都必須呼叫對應 Application Use Case 並驗證前置條件。

## 模擬付款

付款介面：

```text
IPaymentGateway
└─ SimulatedPaymentGateway
```

### 即時付款

- 信用卡
- LINE Pay
- Apple Pay
- Google Pay

共用模擬流程：

```text
建立付款
→ 模擬跳轉
→ 成功／失敗／取消
→ 模擬回呼
```

### 延遲付款

- ATM：產生模擬虛擬帳號及到期時間。
- 超商代碼：產生模擬繳費代碼及到期時間。

### 貨到付款

- 一般宅配及超商取貨都可使用貨到付款。
- 折扣後且包含運費等費用的最終應付金額不得超過 NT$20,000。
- 含組裝電腦或其他限制品的訂單不得使用貨到付款。
- 訂單建立後直接確認庫存，並建立 `AwaitingPayment` 的貨到付款紀錄。
- 一般宅配送達進入 `Delivered`，或超商取貨完成進入 `PickedUp` 時，將該付款紀錄轉為 `Paid`。
- 配送失敗或逾期未取不直接推測最終付款結果；商品確認退回商家且不再收款時，將貨到付款紀錄轉為 `Cancelled`。
- 貨到付款不等待線上付款期限，但仍在訂單成立時保留庫存，出貨時才正式扣除實體庫存。

### 付款狀態

```text
Pending
AwaitingPayment
Processing
Paid
Failed
Cancelled
Expired
```

付款模擬器至少支援成功、失敗、取消、逾時、重複回呼、部分退款及全額退款。相同回呼重複送達時只能處理一次。

### 付款重試與訂單期限

- 一次付款失敗或顧客取消該次付款嘗試時，不立即取消訂單。
- 在訂單原付款期限內可以建立新的 `Payment` 嘗試；每次嘗試各自保存終態，不把失敗紀錄改回等待中。
- 只有訂單原付款期限到期時，才由逾時流程取消訂單並釋放庫存。

## 訂單取消

- 第一版不建立 `CancellationRequest` 或 `CancellationRequested` 狀態。
- 顧客或訪客符合取消條件時直接取消；不符合條件時前台阻擋並引導使用既有售後流程。
- 具例外取消權限的管理員可在商家無法履約等情況下執行人工取消，但必須填寫原因並保存稽核紀錄；精確角色由權限矩陣定義。
- 已付款訂單取消後建立退款交易；已出貨後不再走取消，改走退貨或配送退回流程。

## 退款狀態

- `OrderRefundStatus` 表示訂單累計退款情況：`None`、`Pending`、`PartiallyRefunded`、`Refunded`。
- `RefundTransactionStatus` 表示每次退款交易：`PendingReview`、`Approved`、`Processing`、`Succeeded`、`Rejected`、`Failed`、`Cancelled`。
- 一張訂單可有多次部分退款；成功後重新計算訂單彙總狀態，累計退款不得超過可退款餘額。
- 金額計算、折扣追回、運費、組裝費與明細規則見 [[02-領域需求/退貨與退款政策]]。

## 物流

物流介面：

```text
IShippingProvider
└─ SimulatedShippingProvider
```

### 配送方式與費用

- 第一版一張訂單只允許一種配送方式與一張主要物流單，且同批履約。
- 若商品需要不同配送方式，必須在結帳前拆成不同訂單，不能在訂單成立後隱性拆單。
- 第一版宅配與超商取貨固定啟用，不提供後台停用功能。

| 配送方式 | 基本運費 | 免運門檻 | 限制 |
|---|---:|---:|---|
| 超商取貨 | NT$60 | NT$2,000 | 僅限符合尺寸及重量的商品 |
| 一般宅配 | NT$150 | NT$5,000 | 可預付；符合 COD 金額與商品限制時可貨到付款 |
| 組裝電腦宅配 | NT$300 | NT$30,000 | 不可超商取貨，必須先付款 |

免運門檻使用優惠券折扣後的符合資格商品小計判斷，不包含運費及組裝費。

### 超商門市與包裹限制

- 使用可重複建立的固定門市種子資料，不串接真實物流門市 API。
- 第一版使用 7-ELEVEN 與全家，各 50 間虛構門市，共 100 間；畫面與說明需標示為專題展示資料，不暗示與品牌合作或資料為即時官方門市。
- 門市選擇支援縣市、行政區、店名及店號搜尋，不實作地圖。
- 超商包裹限制的預設值為：單邊最長 45 cm、長寬高合計 105 cm、總重量 5 kg。
- `OrderManager` 與 `SuperAdmin` 可以修改包裹限制；每次修改必須建立不可覆寫的設定版本及 Audit Log。
- 新版本只影響生效後重新檢查的購物車與新訂單；既有訂單使用成立時保存的包裹限制版本快照。
- 超商與宅配使用不同 Provider Profile 及不可由一般管理員突破的安全範圍；管理員設定值需通過正值、單邊不大於三邊和等跨欄位驗證。
- 超商 Profile 繼續使用單邊 45 cm、三邊和 105 cm、5 kg 作為目前有效預設；宅配及兩類 Profile 的可編輯精確上下限仍待決定。
- 設定先建立草稿，可排定生效時間；同一物流服務在任一時間只有一個有效版本。
- 發布使用 `rowversion` 防止並行覆蓋，衝突回傳 409；已發布或已生效版本不可修改，只能建立新版本取代。
- 組裝電腦、螢幕及任何超過尺寸或重量限制的商品只能選擇宅配。
- 前端在選擇配送方式時提示限制；API 在建立訂單前依商品尺寸、重量及分類重新驗證。
- 商品的「可超取／僅能宅配」是依目前有效設定與商品限制衍生的狀態，並需顯示不能超取的原因，不另存為不可追溯的固定布林值。

### 超商門市維護

- 具門市維護權限的管理員可以新增、編輯及停用示範門市；精確角色仍待權限矩陣確認。
- 已被購物車或訂單引用的門市不得實體刪除；停用後不可供新訂單選擇，但既有訂單仍顯示門市快照。
- 門市異動保存操作者、前後值、時間及 Audit Log。

### 物流狀態

```text
Pending
Preparing
Shipped
InTransit
PickupReady
Delivered
PickedUp
DeliveryFailed
Returned
```

後台可以建立模擬物流單號、更新狀態及查看歷程；前台可查看配送方式、運費、物流單號及物流歷程。

### 批次出貨

- 後台可勾選多筆訂單執行批次出貨，但每筆訂單獨立驗證、獨立交易及獨立回傳結果。
- 一筆失敗不回滾其他已成功出貨的訂單。
- 每筆至少驗證：訂單可履約、付款條件已滿足或為合法 COD、組裝工作已可出貨、保留庫存仍為 `Active`、配送方式有效及物流單號符合要求。
- 成功時在同一筆交易中建立／更新物流資料、將保留轉為 `Consumed`、扣除實體與保留庫存、寫入狀態歷程及 Outbox／通知事件。
- 回應需列出每筆訂單的成功結果或穩定錯誤碼。
- 單批最多處理 100 筆訂單；超過上限時整個 Request 回傳驗證錯誤，不開始逐筆出貨。
- 未提供物流單號時由 `SimulatedShippingProvider` 產生唯一單號；重複單號或訂單已有主要物流單時，只有該筆失敗。
- 畫面顯示成功、失敗與逐筆結果，並提供 UTF-8 CSV 下載。
- 結果 CSV 至少包含輸入列號、訂單編號、成功／失敗、錯誤碼、安全訊息及物流單號。
