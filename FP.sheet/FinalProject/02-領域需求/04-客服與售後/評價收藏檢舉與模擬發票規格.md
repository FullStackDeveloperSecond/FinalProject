# 評價、收藏、檢舉與模擬發票規格

## 商品評價與審核（S）

### 資格與內容

- 只有登入會員且訂單已完成，才可對該訂單實際購買的 SKU 建立評價。
- 同一 `OrderItem` 只能有一筆有效評價；購買多件同 SKU 不增加可評價筆數。
- 星等為 1～5 的整數；標題最多 80 字，內容最多 1,000 字。
- 可附最多 3 張 JPG／PNG，每張最多 5 MB；沿用圖片掃描、私有暫存與核准後公開流程。
- 評價顯示「已購買」標記，但不公開訂單編號、姓名或其他個資。

### 狀態

```text
Draft → PendingReview → Approved | Rejected
Approved → Hidden
Rejected → PendingReview
```

- 送出後必須通過後台審核才公開。
- 會員可在公開前修改或撤回；已公開評價修改後回到 `PendingReview`，舊版停止公開但保留版本歷程。
- 審核拒絕、隱藏與恢復都要填寫原因並寫 AuditLog。
- 商品下架不刪除評價；前台商品不可瀏覽時，評價不提供獨立公開頁。

## 收藏（S）

- 只開放登入會員；`MemberId + ProductId` 唯一，重複加入視為成功且不建立第二筆。
- 移除收藏可直接刪除沒有獨立稽核價值的 Join Row；敏感或高風險稽核規則不適用。
- 商品缺貨時保留收藏並顯示缺貨；商品下架時保留但顯示不可購買，不允許由收藏頁加入購物車。
- 商品重新上架後原收藏自動恢復正常顯示。
- 會員匿名化刪除時依會員資料清除規則移除收藏；收藏不保留於交易快照。

## 檢舉（S）

### 範圍

- 登入會員可檢舉商品、商品評價、客服人員公開回覆及系統明列的其他公開內容。
- 檢舉不是一般客服案件，使用獨立 `ReportCase` Aggregate、佇列、狀態與授權。
- 每案選擇受控理由：不實資訊、詐騙／誤導、冒犯／騷擾、不當內容、個資洩漏、其他；其他必填說明。
- 最多 3 個證據附件、每個 10 MB，沿用私有附件掃描與授權下載規則。
- 同一會員、同一 Target、同一理由在未結案期間不得重複建立；API 回傳既有案件 PublicId。

### 狀態與處置

```text
Open → Assigned → InReview → Actioned | Rejected → Closed
```

- 可採處置包含不處理、修正內容、隱藏內容、停用目標或轉交具權限管理員；檢舉處理者不能藉工作台取得原本沒有的商品、客服或會員管理權限。
- 補件不新增 `NeedMoreInfo` 狀態；在 `InReview` 以 `RequestMoreInfo` Action 建立歷程與通知，案件仍維持 InReview。
- 成立案件使用 `Actioned + ResolutionCode` 表達；不得加入 `Submitted/NeedMoreInfo/Founded/Unfounded` 第二套狀態。
- 一般檢舉進專用佇列，可由 `CustomerService` 自領；涉及個資、安全、詐欺、法律或其他高風險內容時，必須由 `CustomerServiceSupervisor` 指派或覆核，不新增 ReportReviewer 角色。
- 會員只看到已受理、處理中、已完成與不成立等安全摘要，不顯示內部備註或處理人個資。
- 所有指派、結論、內容隱藏及權限操作寫入 AuditLog；原內容保留稽核快照，不以實體刪除抹除證據。

## 模擬發票（M 支援流程）

本功能只模擬台灣電商常見發票生命週期，不串接財政部平台、不產生可兌獎或具法律效力的電子發票。

5% 稅率基線已於 2026-08-19 依[財政部稅務入口網「課稅方式」](https://www.etax.nat.gov.tw/etwmain/tax-info/understanding/tax-saving-manual/national/business-tax/6opmkDW)核對；若未來改為真實電子發票或正式營運，必須重新確認適用稅率、免稅／零稅率商品與法定取位規則，不得直接沿用本 DEMO 契約。

### 欄位

- `InvoicePublicId`、展示用 Invoice Number、Order PublicId、Buyer Type。
- 個人發票：Email、載具類型與遮蔽載具值；公司發票：統一編號、公司抬頭。
- 未稅金額、稅額、含稅總額、幣別、開立／作廢時間、狀態與 RowVersion。
- 發票明細保存商品／SKU 顯示快照、數量、單價、折扣分攤、稅額及小計。

### 狀態與事件

```text
Pending → Issued → Voided
               └→ PartiallyAllowed → FullyAllowed
```

- 線上付款成功後開立；COD 在完成收款時開立；未付款或取消訂單不開立。
- 付款成功後又整筆取消且未進入退款者可作廢；已發生金流退款時建立折讓，不回寫或刪除原發票。
- 單項／部分退款建立對應折讓明細；累計折讓不得超過原發票各明細可折讓金額。
- 模擬發票固定使用台灣營業稅率 5%。訂單商品、優惠券分攤、運費、組裝費與發票明細可保留兩位小數；最終應付金額必須在付款前以 `MidpointRounding.AwayFromZero` 四捨五入至整數新臺幣，使訂單總額、金流請款、實付金額與發票表頭含稅總額一致。
- 發票表頭依 `RawGrossAmount = Sum(Line.GrossAmount)`、`IssuedAmount = Round(RawGrossAmount, 0, AwayFromZero)`、`NetAmount = Round(IssuedAmount / 1.05, 0, AwayFromZero)`、`TaxAmount = IssuedAmount - NetAmount` 計算；表頭 Gross／Net／Tax 均為整數元。例如含稅 NT$1,000 固定拆為未稅 NT$952、稅額 NT$48。
- 發票明細 Gross／Net／Tax 可保留兩位小數；每筆必須滿足 `Gross = Net + Tax` 且不得為負。核對口徑為 `Round(Sum(Line.Gross), 0, AwayFromZero) = Header.Issued`、`Round(Sum(Line.Net), 0, AwayFromZero) = Header.Net`、`Sum(Line.Tax) = Header.Tax`；稅額依比例分攤，最後一筆仍有合法調整空間的明細吸收尾差。
- `RoundingAdjustment = IssuedAmount - RawGrossAmount` 由既有訂單總額與明細加總推導，不新增 Schema。不得因單一明細含小數拒絕開立；但明細加總四捨五入後若不等於既有訂單實付金額，視為交易快照不一致並拒絕，不得在發票端自行改寫金額。
- 本次裁定只覆寫 DEC-P280 的發票明細規則；折讓仍沿用原發票的 5% 稅率、整數元與尾差規則，且不得因目前商品價格、稅率設定或分類變更重算歷史交易。小數發票明細的部分折讓若需要不同取位規則，另案裁定。
- 發票號碼明確標示 `DEMO`，不得仿造真實有效號碼；所有開立、作廢及折讓寫入狀態歷程與 AuditLog。

## 驗收重點

1. 未購買、未完成訂單、訪客或他人 OrderItem 不能評價。
2. 評價修改必須重新審核，前台不短暫公開未審內容。
3. 收藏重複請求冪等；缺貨／下架不造成孤兒資料或可購買假象。
4. 重複檢舉回到既有案件，無權限角色不能查看證據附件。
5. 部分退款只建立相應折讓且累計不超額；所有發票資料清楚標示為模擬。
6. 含稅 NT$1,000 必須固定得到未稅 NT$952、稅額 NT$48；含小數明細必須依三條核對口徑與表頭一致，且明細加總四捨五入後不等於訂單實付金額時必須拒絕。
