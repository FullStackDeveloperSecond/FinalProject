# 優惠券規則

狀態：已確認
最後更新：2026-09-10（新增優惠規則已由 alex 裁定；實作／部署狀態另見進度確認紀錄）

## 第一版優惠券類型

### 固定金額折扣

例如滿 NT$3,000 折 NT$300，折扣不得使符合資格的商品金額低於零。

### 百分比折扣

例如滿 NT$20,000 打九折，一般百分比券仍必須設定最高折抵金額。2026-09-10 裁定：明確設定 `MultiItemDiscountValue` 的件數級距券可以不設上限；`MaximumDiscount=null` 表示無上限，不以 0 表示。單件使用 `DiscountValue`，適用商品總數量達 2 件使用 `MultiItemDiscountValue`（同 SKU 多件也計入）；非適用品項不列入件數。

### 免運券

一般免運券適用一般宅配或超商取貨。組裝電腦宅配只有專用的組裝電腦免運券能折抵。

## 共通規則

| 規則 | 決策 |
|---|---|
| 每張訂單優惠券數量 | 一張 |
| 優惠券互相疊加 | 不允許 |
| 訪客使用 | 公開優惠碼可以 |
| 會員專屬券 | 必須登入 |
| 商品特價搭配優惠券 | 預設可以，但優惠券可設定排除 |
| 使用期間 | 必須設定開始與結束時間 |
| 最低消費 | 可設定 |
| 最低消費比對基準 | 只計入符合該優惠券適用範圍的商品小計 |
| 百分比最高折抵 | 一般券必須；件數級距券可明確無上限 |
| 總使用次數 | 可設定 |
| 每人使用次數 | 可設定，預設一次 |
| 適用範圍 | 全站、指定分類、指定商品 |
| 排除商品 | 可設定 |
| 組裝費 | 不參與折扣 |
| 運費 | 只有免運券可折抵 |
| 訂單快照 | 必須保存 |

訪客每人使用限制以正規化後的訂購 Email 及完成訂單紀錄判斷，但文件需註明這無法完全防止使用者更換 Email。

### 適用範圍資料規則

- `ScopeType=All` 表示全站，不建立指定分類或指定商品包含資料。
- `ScopeType=Restricted` 必須至少指定一個分類或商品。
- 指定分類、指定商品及排除商品分別使用 `CouponCategories`、`CouponProducts`、`CouponExcludedProducts` 關聯表，不保存自由格式文字或任意 JSON。
- 排除商品優先於包含分類及包含商品；同一優惠券不可同時把同一商品列為包含與排除。
- 第一版不建立獨立 `Promotions` Aggregate；限時 SKU 特價由 `SalePrices` 管理，訂單折扣與免運由 `Coupons` 管理。

## 計算順序

```text
1. 商品原價
2. 商品特價
3. 找出符合優惠券的商品
4. 套用固定金額或百分比優惠券
5. 加入組裝費
6. 判斷配送與滿額免運
7. 套用免運券
8. 產生訂單總額
```

- 同一 SKU 的有效特價期間不得重疊；建立或修改特價時需直接拒絕重疊區間。
- 特價後仍可套用符合條件的一張優惠券；原價、特價與優惠券折扣分開保存快照。
- `MinimumSpend` 使用商品特價後、優惠券折扣前的適用商品小計；不含不適用商品、運費、組裝費與贈品價格。

免運門檻使用優惠券折扣後的符合資格商品小計判斷，不包含運費、組裝費與贈品價格。

## 優惠券狀態

```text
Draft
Scheduled
Active
Paused
Expired
Exhausted
Disabled
```

使用時仍需重新檢查時間、總量、每人次數、會員資格及商品範圍，不能只依賴狀態欄位。

## 使用與併發

```text
開始資料庫交易
→ 驗證優惠券及狀態
→ 驗證總使用量與每人使用量
→ 驗證商品及最低消費
→ 後端計算折扣
→ 建立訂單
→ 建立 CouponRedemption
→ 提交交易
```

前端只能顯示預估折扣。只剩一個使用名額時，多位使用者同時結帳也只能成功一筆。

- 購物車不保存已輸入的優惠碼；前端在每次優惠預覽請求中帶入優惠碼。重新整理、跨裝置或購物車合併後可以遺失輸入值，Checkout 仍須重新驗證全部規則。
- 購物車預覽不建立或保留 `CouponRedemption`。
- Checkout 在建立 Order 的同一 SQL Transaction 中建立 `CouponRedemption`；OrderId 必填。建單失敗整筆回滾，付款逾時或取消時才依政策 Release／Expire。
- 優惠後再加上運費與組裝費，依付款整數化規則得到的 `GrandTotal` 必須至少 NT$1。低於 NT$1 時回 `409 order_total_below_minimum`；不建立 Redemption、Order 或 PaymentAttempt，Cart 與庫存維持原狀。不得把折扣悄悄截短成只剩 NT$1，也不得略過付款紀錄來成立零元訂單。
- 使用名額以 Serializable 或等價原子條件更新保護，不以先查後寫的非原子流程計數。
- 會員 Redemption 保存 `MemberUserId`；訪客 Redemption 保存 `GuestUsageKeyHash`，兩者恰一有值。
- 訪客 Key 由伺服器以 Secret 對正規化訂單 Email 計算 HMAC-SHA-256，只保存 `binary(32)` Hash，不保存、回傳或反解 Email 副本。V1 固定 Secret Version 1；Secret 不進儲存庫，未來輪替需另定版本與相容規則。

## 訂單快照與折扣分攤

日後修改優惠券不能影響既有訂單，因此需保存：

```text
OrderCouponSnapshot
├─ CouponCode
├─ CouponName
├─ CouponType
├─ RuleVersion
├─ MinimumSpendAmount
├─ EligibleSubtotal
├─ DiscountAmount
└─ IsFreeShipping
```

訂單層級折扣按符合資格商品的成交金額比例分攤至 `OrderItemDiscountAllocation`，以支援單項退貨與部分退款。

- `OrderCoupon` 保存優惠碼、優惠名稱、類型、規則版本、下單時最低消費門檻、訂單級折扣結果、適用小計及免運結果。
- 第一版每張訂單最多一張優惠券，因此 `OrderItem.IsCouponEligible` 保存該品項下單時是否屬於優惠券適用範圍；不得用 `DiscountAllocation > 0` 反推，避免四捨五入為零時誤判。
- `OrderItem`／折扣分攤明細保存各品項實際分攤金額；部分退貨依 `MinimumSpendAmount`、`IsCouponEligible` 與原始成交快照重算，絕不回查目前 Coupon、商品分類或範圍設定。
- 每一步金額分攤使用 `MidpointRounding.AwayFromZero` 至兩位小數，最後一筆合法品項吸收尾差，使分攤合計精確等於訂單級折扣。
- 優惠碼不分大小寫唯一，輸入 Trim 後正規化為大寫保存。

## 取消與返券

| 原因 | 返還使用次數 |
|---|:---:|
| 顧客在允許階段取消 | 是 |
| 付款失敗或逾時 | 是 |
| 缺貨或系統取消 | 是 |
| 商家取消 | 是 |
| 完成後退貨 | 否 |
| 違規或濫用 | 否 |

返還使用次數不延長優惠券期限；優惠券已到期時不恢復可用。

若名額返還後總使用量重新低於限制，`Exhausted` 可在尚未到期且未被停用時回到 `Active`。`Expired` 與 `Disabled` 都是終態；需要暫時停止使用時必須採 `Paused`，不得用 `Disabled` 後再恢復。

待付款訂單自助取消時，Reserved `CouponRedemption` 的釋放、優惠券狀態恢復、訂單狀態、庫存還原、狀態歷程與中央 Audit 必須在同一 SQL Server 交易中完成；任一步驟失敗時全部回滾。

## Demo 優惠券

| 優惠碼 | 活動與規則 |
|---|---|
| CREATOR10 | 創作者指定分類九折，保留為 2026/8/1～8/31 已結束且停用的歷史紀錄；保留原訂單、分攤、使用紀錄，不重算舊單 |
| SCHOOL2026 | 9 月開學季，全商品 1 件九五折、2 件以上九折，無最低消費、無折抵上限、每人一次、不限會員；台北時間 2026/9/1 00:00（含）至 2026/10/1 00:00（不含） |
| MEMBER100 | 會員入會禮 NT$100，商品小計滿 NT$1,000、全商品、每人一次；包含既有會員，原始入會日起一年內可用 |

- 每筆訂單仍只接受一個優惠碼，以上新券也不可合併。
- `MemberValidityMonths=12` 只允許會員券。可信日期取伺服器保存的原始 `ApplicationUser.CreatedAtUtc`；不得接受客戶端自報入會時間，不因修改個人資料重設期限。滿周年（不含該時點）到期；無日期、未來日期或非啟用會員均拒絕。
- 入會禮仍沿用活動起訖欄位：本次持續活動起點為台北時間 2026/9/1，技術上界為 UTC 9999/1/1，用來保留既有必填日期契約，不是會員個人的到期日。前台及列表顯示入會日起一年；實際使用同時受活動狀態、活動期間與個人期限限制。
- 新欄位在舊券為 null，不改既有行為。舊版後台修改時省略／null 的新欄位保留原值，不能無聲移除既有件數或入會限制；需要移除限制時另建券，歷史券仍保留。
- **開學季退貨裁定**：退貨後只剩一件也不改回九五折，只按原成交分攤退該品項的實付金額。訂單保存實際套用率及分攤，不回查目前活動。入會禮原有最低消費退款規則不在本次變更範圍。
- 訪客一次的識別仍依伺服器正規化 Email 的 HMAC；不能防止同一人使用不同 Email，此限制不等同真實身分唯一。
- 原 10,000 筆 seed 的 `DEMO001～DEMO029` 是歷史測試資料，不刪除或改寫使用紀錄；是否停用依本次獨立裁定。活動更新使用明確的本機維護命令，不在服務啟動時自動改資料。
