# 會員、購物與售後驗收規格

本文件將已確認的會員、訪客、購物車、付款、優惠券、退貨與退款規則轉成可測試的使用案例。

## UC-AUTH-01｜會員註冊與 Email 驗證

**角色**：匿名訪客

**主流程**：註冊 → 寄送驗證信 → 開啟 24 小時內的單次連結 → 啟用會員帳號。

**驗收條件**：

- Given Email 格式合法且未被使用，When 完成註冊，Then 建立未驗證帳號並經 `IEmailSender` 排入驗證信，不直接建立已登入 Session。
- Given 驗證 Token 合法且未使用，When 驗證成功，Then Email 狀態只啟用一次，重送同 Token 不產生第二次副作用。
- Given Token 已到期、已撤銷或已使用，When 再次提交，Then 回傳安全錯誤且不洩漏內部 Token 內容。
- Given Email 已被註冊，When 再次送出，Then 對外回應不得用來枚舉有效會員帳號。

- Given 未驗證帳號已建立滿 7 天且沒有必須保存的關聯資料，When 清理工作執行，Then 帳號被清除且相同 Email 可重新註冊。

## UC-AUTH-02｜會員登入、登出與鎖定

**角色**：已驗證會員

**驗收條件**：

- Given 帳號與密碼正確，When 登入成功，Then 建立會員專用 `HttpOnly` Cookie，不把 Token 放入瀏覽器儲存空間。
- Given 會員連續登入失敗 5 次，When 再次嘗試登入，Then 鎖定 15 分鐘；成功登入後重設失敗次數。
- Given 會員已登入，When 登出或變更密碼，Then 既有工作階段失效。
- Given Session 持續無活動 8 小時或超過最長 7 天，Then 必須重新登入。
- Given 會員 Cookie 被送往管理 API，Then 不得取得管理員身分或權限。

- Given 帳號被停權，Then 既有 Session 立即失效、會員不得登入，只能使用匿名公開瀏覽；訂單存取改走 Email 限單驗證或管理員協助。

## UC-AUTH-03｜忘記密碼與重設密碼

**角色**：匿名訪客

**驗收條件**：

- Given 使用者提交 Email，When 要求重設密碼，Then 不論帳號是否存在都回傳一致的安全訊息。
- Given 帳號存在，Then 寄送有效 1 小時、單次使用且可撤銷的重設連結。
- Given Token 合法且新密碼通過規則，When 重設成功，Then 舊密碼失效並撤銷既有會員 Session。
- Given Token 到期、已用或遭撤銷，When 提交，Then 不修改密碼且不把 Token 寫入一般 Log。

## UC-ADMIN-AUTH-01｜管理員 TOTP 2FA

**角色**：管理員

**驗收條件**：

- Given 密碼正確但尚未完成 TOTP，When 呼叫管理 API，Then 不建立完整管理 Session且回傳未完成 2FA 的結果。
- Given TOTP 驗證成功，Then 建立管理員專用 Cookie，採 2 小時絕對期限且不滑動延長。
- Given 管理員連續登入失敗 5 次，Then 鎖定 30 分鐘並留下安全／稽核紀錄。
- Given 使用 Recovery Code，Then 該 Code 只能成功一次，使用事件必須稽核。
- Given TOTP 重新綁定或解除，Then 既有管理 Session 失效且異動必須稽核。

## UC-GUEST-ORDER-01｜訪客取得單筆訂單存取權

**角色**：訪客購買者

**主流程**：輸入訂單編號與購買 Email → 寄送一次性驗證 → 驗證成功 → 核發 30 分鐘限單權杖。

**驗收條件**：

- Given 訂單編號或 Email 不正確，When 送出驗證要求，Then 回應不得洩漏訂單是否存在。
- Given 10 分鐘內的驗證碼正確且未使用，Then 核發只綁定該筆訂單的 `GuestOrderAccessToken`。
- Given Token 指向訂單 A，When 嘗試查看或操作訂單 B，Then API 拒絕存取。
- Given Token 有效且訂單符合條件，Then 訪客可查看訂單與物流、取消、申請單項退貨及查看退款進度。
- Given 訪客持有限單 Token，When 呼叫 AI 或人工客服 API，Then 仍必須拒絕，因客服只開放會員。

## UC-CART-01｜購物車重新驗證

**角色**：匿名訪客、會員

**驗收條件**：

- Given SKU 已上架且有可售庫存，When 加入購物車，Then 保存 SKU、數量及必要組裝群組，但不建立庫存保留。
- Given 使用者開啟購物車、修改數量或進入結帳，Then API 重新檢查上架、價格、可售庫存及相容性。
- Given 價格已改變，Then 顯示新舊差異並要求依正式互動規則處理；訂單不得使用舊購物車價格。
- Given SKU 缺貨、下架或組裝變得不相容，Then 該項目不能結帳且需顯示可處理原因。
- Given 前端竄改價格、折扣、庫存或組裝費，When 送往結帳，Then 後端忽略並重新計算。

## UC-CART-02｜訪客登入後合併購物車

**角色**：剛完成登入的會員

**驗收條件**：

- Given 訪客與會員購物車有相同一般 SKU，When 合併，Then 數量相加且同一合併請求重送不重複增加。
- Given 兩邊存在包含相同零件的不同組裝群組，Then 群組分別保留，不拆散成一般 SKU 或互相覆蓋。
- Given 合併數量超過購買上限或可售庫存，Then 保留項目並標記衝突，不自動截斷。
- Given 價格已改變、商品下架或相容性失效，Then 顯示原因並要求確認、調整、替換或移除。
- Given 任一合併衝突未完成處理，When 嘗試結帳，Then API 拒絕建立訂單。

## UC-CHECKOUT-01｜建立多 SKU 訂單並原子保留庫存

**角色**：匿名訪客、會員

**前置條件**：購物車、配送、收件資料、付款方式及必要告知均合法。

**驗收條件**：

- Given 多個 SKU 均有足夠可售庫存，When 建立訂單，Then 在同一資料庫交易中建立訂單、交易快照及每個 SKU 的 `Active` 保留。
- Given 任一 SKU 不足，Then 整筆訂單與所有保留回滾，不得留下半張訂單。
- Given 兩個請求同時競爭最後一件，Then 最多一筆成功，失敗者取得穩定庫存衝突錯誤。
- Given 相同身分、操作、`Idempotency-Key` 及 Payload 重送，Then 回傳原結果且不重複保留。
- Given 同 Key 搭配不同 Payload，Then 回傳 409 且不修改資料。
- Given 訂單建立成功，Then 保存商品、SKU、價格、折扣、成本、收件、配送、組裝費及政策版本快照。

## UC-PAY-01｜模擬付款、重試與逾時取消

**角色**：匿名訪客、會員

**驗收條件**：

- Given 信用卡、LINE Pay、Apple Pay 或 Google Pay，When 建立付款，Then 模擬成功、失敗、取消與重複回呼；重複事件只改變狀態一次。
- Given ATM 或超商代碼，When 建立付款，Then 產生模擬帳號／代碼及 3 天到期時間。
- Given 即時付款失敗或取消，When 訂單仍在原期限內，Then 可建立新的 Payment Attempt，舊失敗紀錄保持終態。
- Given 付款成功，Then 只更新付款及訂單流程，不減少 `OnHandQuantity` 或 `ReservedQuantity`。
- Given 原付款期限到期，When 背景工作重複執行，Then 訂單只取消一次、保留只釋放一次並留下 InventoryMovement。
- Given Demo 使用縮短期限，Then 只改變展示設定，不改寫正式預設期限。

COD 的金額、限制品、付款與出貨條件另見 `UC-CHECKOUT-COD-01`。

## UC-COUPON-01｜優惠券驗證、併發與快照

**角色**：匿名訪客、會員

**驗收條件**：

- Given 公開優惠碼有效，Then 訪客與會員都可使用；會員專屬券必須驗證會員身分。
- Given 一張訂單已套用優惠券，When 嘗試再套第二張，Then API 拒絕疊加。
- Given 優惠券有期間、門檻、範圍、總量或每人限制，When 建立訂單，Then 在交易內重新驗證，不信任購物車預估。
- Given 優惠券只剩一次總使用量且兩人同時結帳，Then 只允許一筆建立 `CouponRedemption`。
- Given 訂單成立，Then 保存優惠券規則快照，並按符合資格商品成交金額比例分攤折扣至訂單明細。
- Given 訂單因允許取消、付款失敗、逾時、缺貨或商家取消而終止，Then 依正式規則返還使用次數但不延長優惠券期限。

- Given 同一 SKU 的新特價期間與既有有效期間重疊，Then API 回傳 `sale_price_period_overlap` 並拒絕儲存。

## UC-RETURN-01｜單項退貨申請與寄回

**角色**：會員、已驗證訪客購買者

**驗收條件**：

- Given 一般商品到貨翌日起 7 日內且符合政策，When 顧客選擇單一訂單明細、數量、原因及證據，Then 可建立獨立 `ReturnRequest`／`ReturnItem`。
- Given 訂單屬他人或訪客 Token 不符合該訂單，Then API 拒絕且不洩漏資料。
- Given 客製組裝已進入 `AssemblyStarted` 且只是個人因素，Then 不允許自行無理由取消，轉人工審核。
- Given 退貨核准且需要寄回，Then 交寄期限為 7 個日曆日；主管只可在到期前延長一次 7 天且必填原因。
- Given 到期未交寄，Then 背景工作將申請轉為 `Cancelled`、保存原因並通知顧客。
- Given 商品已收回，Then 必須完成退貨檢查後才決定退款與庫存處置。

- Given `ReturnInspection` 結果為 `Resellable`，Then 建立 `ReturnToStock` 異動並回補 `OnHandQuantity`。
- Given 結果為拆封待判定、缺件、瑕疵、損壞或報廢，Then 進入隔離處置且不得增加可售庫存。
- Given 退款已成功但尚無可重新販售的檢查結果，Then 不得只因退款完成自動回補庫存。

## UC-REFUND-01｜人工審核部分退款

**角色**：具退款核准權限的管理員

**驗收條件**：

- Given 退貨或取消符合退款條件，When 建立退款，Then 產生獨立 `RefundTransaction`，不得直接覆寫原 Payment。
- Given 退款待審，Then 未具核准權限者不得核准或執行。
- Given 單項退貨，Then 依成交金額、折扣分攤、優惠追回、運費、組裝費及贈品規則產生可解釋明細。
- Given 部分退貨後不再符合免運門檻，Then 從退款重收原配送方式運費；原本已支付的部分退貨運費不退。
- Given 多次部分退款，Then 累計不得超過可退款餘額，成功後重新計算訂單退款彙總。
- Given 相同冪等請求重送，Then 不得重複退款；失敗、拒絕與成功均保留歷程及稽核。
