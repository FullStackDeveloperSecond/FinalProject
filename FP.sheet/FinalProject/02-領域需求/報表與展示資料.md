# 報表與展示資料

狀態：已確認

## 展示資料與真實品牌界線

- 商品品牌、型號名稱及原廠公開規格可以使用真實資料，但每筆必須在 Source Register 保存來源 URL、提供者、擷取日期及適用欄位。
- 商店身分、價格、成本、庫存、會員、地址、訂單、付款、評價、客服、退貨、退款及營運統計全部使用虛構展示資料，不暗示真實品牌參與或背書。
- 真實品牌 Logo、商品圖及文字只有在授權或合理使用界線清楚時才可使用；圖片依 Asset Register 保存作者、授權與雜湊，來源不明不得進 Demo Seed。
- 前台頁尾、關於頁及 Demo 簡報固定顯示：「本系統為畢業專題教學展示，商品規格可能引用公開資料；價格、庫存、交易與營運資料皆為模擬，與所示品牌無合作或背書關係。」
- 後台與報表標示 `DEMO DATA`；CSV／XLSX 匯出首列或 Metadata 同樣標示模擬資料，避免離開系統畫面後被誤認為真實營運資料。

第一版 API 與 Web Route 使用下列不可任意擴張的 Report Key：

| Report Key | 報表 |
|---|---|
| `sales-overview` | 銷售總覽 |
| `product-abc` | 商品排行與 ABC 分級 |
| `period-comparison` | 同期比較 |
| `inventory-turnover` | 庫存周轉分析 |
| `gross-margin` | 毛利分析 |
| `product-associations` | 關聯組合分析 |
| `forecast-anomalies` | 預測與異常偵測 |

未知 Key 回 `400 report_key_invalid`；新增或更名必須同步更新 Endpoint、DTO、UI Route、匯出 Metadata 與測試，不得將任意字串轉成 SQL 或元件名稱。

已確認的共通實作原則：

- SKU 保存目前單位成本；訂單建立時將當時單位成本快照至 `OrderItem`。
- 毛利與歷史成本使用 `OrderItem` 成本快照，不使用查詢當下的 SKU 成本。
- 第一版依篩選條件使用 SQL 即時彙總並建立必要索引，不預先建立每日報表表或固定快取。
- 先以實際展示資料量測效能；完成查詢與索引優化後仍超過 P95 3 秒，才為該報表另立反正規化決策。
- 匯出欄位依本文件「匯出」章節；查詢效能門檻為優化後 P95 3 秒；一般報表限 `MarketingAnalyst`／`FinanceManager`／`SuperAdmin`，財務成本限 `FinanceManager`／`SuperAdmin`，客服 SLA 限 `CustomerServiceSupervisor`／`SuperAdmin`。

七個報表列為 M 不改變 AI 報表分析的 S 優先級，也不改變自然語言詢問營運資料的 O 優先級。

### 商品 ABC 分級

- 分析單位為 SKU。
- 使用所選期間內完成訂單扣除成功退款後的 SKU 淨營收。
- 依淨營收由高至低排序，同營收以不可變 SKU Code 升冪排序。
- 累計營收占比小於或等於 80% 為 A；大於 80% 且小於或等於 95% 為 B；其餘為 C。

### 關聯組合分析

- 分析單位為完成訂單內共同出現的 SKU 配對。
- 配對至少共同出現在 5 筆完成訂單中。
- 只有 `Support ≥ 1%`、`Confidence ≥ 20%` 且 `Lift > 1` 的配對可以顯示。
- 報表必須顯示共同訂單數、Support、Confidence 與 Lift，避免只顯示高 Lift 的小樣本結果。

### 預測與異常偵測

- 使用最近 30 天資料進行簡單線性迴歸，預測未來 7 天。
- 可用歷史資料少於 14 天時不產生預測，畫面顯示資料不足。
- 預測值小於零時以零呈現。
- 異常偵測使用以標準差計算的 Z-score；`|z| > 2` 時標記為異常。
- 標準差為零或樣本不足時不產生異常判定，不得除以零。

## 指標公式

以下分母為 0 時顯示 `—`，不得顯示 0% 假裝有樣本。金額依訂單／退款快照，不回查目前商品或優惠設定。

| 指標 | 公式／排除 |
|---|---|
| 淨營收 | 線上付款以 `Payment.PaidAtUtc`、COD 以送達且完成收款時間認列；成功退款在 `Refund.SucceededAtUtc` 列負值沖減。取消、付款失敗、退款失敗不列入 |
| 訂單數 | 所選時間基準內符合該報表口徑的 distinct Order；建立量報表另列全部建立訂單 |
| 平均客單價 | 淨營收 ÷ 同口徑訂單數 |
| 取消率 | 以 CreatedAt Cohort 計算：最終取消訂單數 ÷ 建立訂單數 |
| 退款訂單率 | 已成功退款的 distinct Order ÷ 已付款 distinct Order；另列退款金額率=成功退款金額÷已付款金額 |
| 毛利 | 淨營收－已完成銷售之 OrderItem `UnitCostSnapshot × 未退款數量`－成功退款分攤造成的收入調整；不把運費／組裝費算商品毛利 |
| 毛利率 | 毛利 ÷ 淨營收 |
| 商品銷量 | 完成 OrderItem Quantity－已成功退款且驗收通過的退貨數量 |
| 庫存周轉率 | 期間銷貨成本 ÷ 平均庫存成本；平均庫存成本=(期初 OnHand 成本＋期末 OnHand 成本)÷2 |
| 庫存周轉天數 | 期間日數 ÷ 庫存周轉率 |
| 低庫存 | `AvailableQuantity <= ReorderLevel` 且仍上架；缺貨固定 `AvailableQuantity = 0` |
| 長期未銷售 | 上架 SKU 最近 60 天無完成銷售；未滿 60 天的新 SKU 不列入 |
| 新增會員 | Member CreatedAt 落在區間且非匿名化測試帳號 |
| 活躍購買會員 | 區間內至少一筆完成訂單的 distinct Member |
| 回購率 | 區間內有至少兩筆完成訂單的會員 ÷ 至少一筆完成訂單的會員 |
| 訪客／會員占比 | 各 BuyerType 訂單數 ÷ 同口徑總訂單數；同時顯示各自 AOV |
| 首次人工回覆時間 | `FirstHumanResponseAtUtc－CreatedAtUtc－可扣 WaitingForCustomer 秒數`；AI 回覆不計 |
| 客服結案時間 | `ResolvedAtUtc－CreatedAtUtc－可扣 WaitingForCustomer 秒數` |
| AI 轉人工率 | AI 對話建立 SupportTicket 的 distinct Conversation ÷ 有成功或降級結果的 AI Conversation |
| AI 推薦點擊率 | `RecommendedProductClicked` distinct Search＋SKU ÷ `RecommendationDisplayed` distinct Search＋SKU |
| AI 推薦加車率 | `CartItemAddedFromRecommendation` distinct Search＋SKU ÷ RecommendationDisplayed distinct Search＋SKU |
| AI 推薦轉換率 | 24 小時歸因的 `OrderPlacedFromRecommendation` distinct Search ÷ 至少一次 RecommendationDisplayed 的 distinct Search |

### 同期比較

- 預設比較「緊鄰且同長度的上一期間」；例如 8/1～8/7 比 7/25～7/31。
- 月粒度可選去年同月；日數不同時比較總額與日均值，畫面不得只顯示百分比。
- 變化率=`(本期－比較期)÷比較期`；比較期為 0 時顯示「新增」或 `—`，不產生 Infinity。
- 比較的兩期必須使用相同時區、時間欄、狀態排除及認列口徑。

### 匯出

- 每個報表支援目前篩選條件的 CSV／XLSX；最多 100,000 明細列，超過時拒絕並要求縮小範圍。
- 檔頭保存 Report Key、報表名稱、時間基準、時區、區間、篩選、產生時間與資料截至時間。
- 指標型匯出至少包含 Metric Key、顯示名稱、值、單位、本期、比較期及變化率；排行／明細另含穩定 PublicId／Code、名稱、數量、金額、占比與排名。
- CSV 使用 UTF-8 BOM 並防公式注入；不得匯出收件人、Email、電話、地址或 AI 對話全文。

## 篩選條件

- 日期區間。
- 商品分類。
- 品牌。
- 訂單狀態。

### 時間基準

- 資料庫事件時間一律保存 UTC；報表預設以 `Asia/Taipei` 顯示及切日。
- 使用者輸入的日期區間採本地日曆的左閉右開 `[from, to)`，API 轉為 UTC 後查詢，避免 `23:59:59.999` 邊界。
- 訂單建立量與取消率 Cohort 使用 `Order.CreatedAtUtc`；取消事件趨勢另用 `CancelledAtUtc`。
- 付款成功量與付款方式使用 `Payment.PaidAtUtc`；付款失敗使用最終 `FailedAtUtc`。
- 出貨量使用 `Shipment.ShippedAtUtc`；送達與配送時間使用 `DeliveredAtUtc`。
- 完成訂單數、商品銷量、成本與毛利使用 `Order.CompletedAtUtc` 及 OrderItem 快照。
- 線上信用卡、ATM、超商代碼、Line Pay、Apple Pay、Google Pay 皆以 `Payment.PaidAtUtc` 認列營收。
- COD 可用於符合金額與商品限制的一般宅配及超商取貨；宅配於 `Delivered` 且完成收款、超取於 `PickedUp` 且完成收款時認列。建立訂單、出貨或尚未收款的單純送達／取貨都不認列；組裝電腦與限制品仍不得使用 COD。
- 退款事件使用 `Refund.SucceededAtUtc` 在成功日列負值；原銷售月份不回寫。另提供「原訂單完成月份」分析維度，供檢視跨月退款來源，但不改主要財務趨勢。
- 會員成長使用 `Member.CreatedAtUtc`；回購以完成訂單時間判斷。

每張報表標題旁必須顯示採用的時間欄位與時區，不得讓使用者以為所有數字都按下單日計算。

## AI 搜尋漏斗事件

| Event Name | 觸發時機 | 必要欄位 |
|---|---|---|
| `AiSearchSubmitted` | 後端接受一次搜尋 | EventPublicId、SearchPublicId、SessionKey、MemberPublicId?、Locale、OccurredAtUtc |
| `RecommendationDisplayed` | 推薦卡實際進入可視區 | SearchPublicId、SkuPublicId、Position、OccurredAtUtc |
| `RecommendedProductClicked` | 點入推薦商品 | SearchPublicId、SkuPublicId、Position、OccurredAtUtc |
| `CartItemAddedFromRecommendation` | 從推薦結果加入購物車 | SearchPublicId、SkuPublicId、Quantity、OccurredAtUtc |
| `CheckoutStartedFromRecommendation` | 含推薦商品的購物車進入結帳 | SearchPublicId、CartPublicId、OccurredAtUtc |
| `OrderPlacedFromRecommendation` | 建立含推薦商品的訂單 | SearchPublicId、OrderPublicId、AttributedAmount、OccurredAtUtc |

- 匿名與會員共用隨機 Session Key；登入後可關聯當前會員，但不得在事件中保存 Email、電話、地址或自然語言全文。
- 歸因採最後一次有效 AI 搜尋、24 小時視窗；同一 Event PublicId 冪等寫入。
- 搜尋文字只在 AI 對話／搜尋紀錄依既定政策保存；報表事件只保存用途、預算區間、分類及結果數等去識別化維度。
- 曝光分母必須使用實際 `RecommendationDisplayed`，不可用 API 回傳筆數代替。

### S 功能資料切換

- 啟用評價與收藏時使用上表：評價 250、收藏 200、客服訊息 500、AI 漏斗事件 400。
- 尚未啟用這兩個 S 功能時，評價與收藏各為 0；空出的 450 筆改為客服訊息 700 與 AI 漏斗事件 650，其他列數不變。
- 兩種模式都必須維持合計 10,000，並在 Seed Manifest 記錄 `FeatureProfile`、固定亂數種子與各實體實際筆數。
- 啟用其他 S 功能時只能從 Manifest 指定的保留配額重新分配，不得在同一 Seed Profile 產生總筆數漂移。

## 資料要求

- 使用固定亂數種子，使每次重建後的報表數字一致。
- 歷史資料涵蓋最近六個月。
- 商品品牌採真實與虛構品牌混合。
- 商品圖片以授權清楚的開源圖片為主並保存來源資訊。
- 每張外部圖片在 Asset Register 保存內部 Asset ID、原始 URL、作者／提供者、授權名稱與授權 URL、下載日期、原始檔 SHA-256、專案內使用位置及必要 Attribution；缺任一來源或授權欄位不得進入正式 Demo Seed。
- 完成訂單至少 250 筆。
- 取消或逾時訂單至少 100 筆。
- 全額或部分退款至少 100 筆。
- 付款失敗或逾時至少 100 筆。
- 低庫存 SKU 至少 100 筆。
- 包含配送中、待出貨、客服、退貨與評價審核案例。
- 種子資料可以透過腳本重建。
