# 商品、訂單與物流後台驗收規格

本文件把已確認的商品、庫存、訂單與物流後台規則轉成可開發及測試的使用案例；數值、角色、狀態與 API 映射均連回現行正式契約。

## UC-ADM-PROD-01｜管理商品變體

**角色**：`CatalogManager`、`SuperAdmin`

**前置條件**：管理員已完成登入與授權。

**主流程**：

1. 管理員選擇商品是否有多個變體。
2. 多變體商品由每個 SKU 分別輸入名稱、SKU Code、售價、庫存與變體規格。
3. 非變體商品由後台建立或維護一個預設 SKU。
4. 商品列表從 SKU 衍生變體數量、價格區間及加總庫存。

**驗收條件**：

- Given 商品有三個 SKU，When 開啟商品列表，Then 顯示三個變體，價格顯示最低至最高區間，庫存為 SKU 庫存加總。
- Given 商品切換為多變體，When 編輯價格與庫存，Then 基本欄位不得建立第二套 Product 價格或庫存，而是由變體 SKU 管理。
- Given 非變體商品，When 儲存商品，Then 系統存在一個承載售價與庫存的預設 SKU。

## UC-ADM-PROD-02｜維護既有 SKU

**角色**：`CatalogManager`、`SuperAdmin`

**驗收條件**：

- Given SKU 已建立，When 開啟編輯頁，Then SKU Code 為唯讀且 API 拒絕任何改寫要求。
- Given SKU 已被訂單、庫存、保留或組裝清單引用，When 管理員嘗試刪除，Then 系統拒絕實體刪除並提供停用或下架操作。
- Given SKU 從未被引用、沒有庫存與保留且仍是草稿誤建資料，When 具權限管理員刪除，Then 系統才可實體刪除並留下稽核紀錄。
- Given SKU 已停用，When 查看歷史訂單，Then 訂單快照仍正常顯示原 SKU Code、名稱與成交資料。

## UC-ADM-INV-01｜查看與手動釋放庫存保留

**角色**：`InventoryManager`、`SuperAdmin`

**前置條件**：保留紀錄存在。

**狀態顯示**：

| 領域狀態 | 後台顯示意義 |
|---|---|
| `Active` | 保留中 |
| `Consumed` | 已出貨扣庫 |
| `Released` | 已取消／人工釋放 |
| `Expired` | 已逾時釋放 |

**驗收條件**：

- Given 保留為 `Active`，When 管理員選擇手動釋放，Then 必須顯示二次確認並要求原因。
- Given 管理員未填原因，When 送出，Then API 拒絕操作且庫存數量不變。
- Given 手動釋放成功，Then `ReservedQuantity` 只減少一次、狀態轉為 `Released`，並保存 InventoryMovement 與 Audit Log。
- Given 同一請求重送，When 冪等識別相同，Then 不得再次減少 `ReservedQuantity`。
- Given 保留已為 `Consumed`、`Released` 或 `Expired`，When 嘗試手動釋放，Then 回傳狀態衝突。
- Given 付款成功但尚未出貨，Then 保留仍為 `Active`，`OnHandQuantity` 與 `ReservedQuantity` 均不因付款改變。

## UC-ADM-SHIP-01｜維護包裹限制

**角色**：`OrderManager`、`SuperAdmin`

**預設設定**：單邊 45 cm、長寬高合計 105 cm、總重量 5 kg。

**驗收條件**：

- Given 管理員提交合法的新限制，When 儲存成功，Then 建立新設定版本與 Audit Log，不覆寫舊版本。
- Given 新版本已生效，When 開啟或修改購物車，Then 系統依目前版本重新計算超取資格。
- Given 訂單在舊版本下成立，When 限制後續改變，Then 該訂單仍使用成立時的版本快照。
- Given 操作者不是 `OrderManager` 或 `SuperAdmin`，When 嘗試修改，Then API 回傳禁止存取。
- Given 商品是組裝電腦、螢幕或超過有效限制，Then 只能選擇宅配並顯示原因。

超商 Profile 可設定範圍為單邊 `1～45 cm`、三邊和 `3～105 cm`、重量 `0.1～5 kg`；宅配為單邊 `1～150 cm`、三邊和 `3～150 cm`、重量 `0.1～20 kg`。新版本以明確生效時間發布，並以 RowVersion 防止並行覆寫。

## UC-ADM-STORE-01｜維護示範超商門市

**角色**：`OrderManager`、`SuperAdmin`；`CatalogManager` 只有檢視權限。

**驗收條件**：

- Given 門市資料合法，When 管理員新增或編輯，Then 保存門市代碼、名稱、縣市、行政區、地址、狀態與 Audit Log。
- Given 門市已被訂單引用，When 管理員嘗試刪除，Then 系統拒絕實體刪除，只允許停用。
- Given 門市已停用，When 建立新訂單，Then 不可再選取該門市。
- Given 既有訂單引用已停用門市，When 查看訂單，Then 仍顯示成立時的門市快照。
- Given 重建展示資料，Then 建立 7-ELEVEN 與全家各 50 間虛構門市，且畫面標示為專題展示資料。

## UC-CHECKOUT-COD-01｜建立貨到付款訂單

**角色**：會員、訪客

**前置條件**：選擇一般宅配或超商取貨；購物車通過商品、庫存、金額與配送驗證。

**驗收條件**：

- Given 最終應付金額不超過 NT$20,000 且沒有組裝電腦或限制品，When 選擇宅配或超取貨到付款，Then 可以建立訂單。
- Given 最終應付金額超過 NT$20,000，When 選擇貨到付款，Then API 拒絕並要求改用其他付款方式。
- Given 訂單含組裝電腦或限制品，When 選擇貨到付款，Then API 拒絕，不因金額低於上限而放行。
- Given COD 訂單建立成功，Then `OrderStatus = Confirmed`、COD Payment 為 `AwaitingPayment`，庫存建立 `Active` 保留但不扣實體庫存。
- Given 宅配 COD 進入 `Delivered`，或超取 COD 進入 `PickedUp`，Then Payment 轉為 `Paid`。
- Given 商品確認退回商家且不再收款，Then COD Payment 轉為 `Cancelled`，後續庫存處置依退回流程處理。

## UC-ADM-ORDER-01｜查看訂單摘要與執行合法操作

**角色**：`OrderManager`、`SuperAdmin`

**驗收條件**：

- Given 訂單存在，When 開啟後台列表，Then 付款、訂單、物流及退款狀態仍可分別查看。
- Given 畫面顯示「待出貨、已出貨、已完成、已取消」摘要，Then 該值由正式狀態衍生，不另存成可任意修改的領域狀態。
- Given 管理員開啟訂單，Then 只顯示目前狀態及權限允許的操作，不提供任意狀態下拉選單。
- Given 管理員送出操作，Then API 重新驗證目前狀態、`rowversion`、權限與所有業務前置條件。
- Given 訂單同時為配送中且部分退款，Then 主要摘要顯示配送中，並另顯示部分退款徽章。
- Given 使用多個 `summaryStatus`，Then 同群組以 OR 篩選；再加入 `badge` 時兩群組以 AND 組合。
- Given 摘要或徽章值未知，Then API 回傳 400。

## UC-ADM-ORDER-02｜查看訂單收件資料

**角色**：`OrderManager`、`SuperAdmin`

**驗收條件**：

- Given 操作者有訂單履約權限，When 查看訂單，Then 可以查看該筆訂單快照中的收件人、電話、地址、配送方式及必要聯絡資料。
- Given 操作者只有一般客服權限，When 查看相關訂單，Then Email、電話及非必要個資必須遮蔽。
- Given `OrderManager` 從訂單進入會員資料，Then 不得因此查看會員完整檔案或其他不相關訂單。
- Given 會員修改目前地址或電話，Then 不改變既有訂單收件快照。

## UC-ADM-SHIP-02｜批次出貨

**角色**：`OrderManager`、`SuperAdmin`

**主流程**：

1. 管理員勾選多筆待處理訂單並提供必要物流資料。
2. API 逐筆驗證並在各自交易中執行出貨。
3. API 回傳每筆成功或失敗結果。

**驗收條件**：

- Given 三筆訂單中兩筆合法、一筆缺少出貨條件，When 執行批次出貨，Then 兩筆成功、一筆失敗，不回滾成功訂單。
- Given 訂單合法出貨，Then 同一交易中建立物流資料、將保留轉為 `Consumed`、扣除實體及保留庫存並保存歷程。
- Given 組裝訂單尚未 `ReadyToShip`、付款條件不符、保留不為 `Active` 或配送資料不合法，Then 該筆不得出貨並回傳穩定錯誤碼。
- Given 同一筆出貨請求重送，Then 不得重複扣庫或建立第二次相同出貨副作用。
- Given Request 超過 100 筆，Then 整體回傳 400，且不開始任何一筆出貨。
- Given 合法項目沒有物流單號，Then 模擬 Provider 產生唯一單號；重複單號的該筆回傳衝突。
- Given 批次完成，Then 管理員可下載 UTF-8 CSV，含列號、訂單編號、結果、錯誤碼、訊息及物流單號。
