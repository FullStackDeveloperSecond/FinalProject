# DoSelect 工作進度確認紀錄

## 1. 使用目的

本頁用來追蹤 [[2026-09-06-全專案掃描報告]] 找出的修正與補足工作，讓每個項目都能依「實際證據」判定是否完成。

本頁是**稽核收斂工作紀錄**，不取代下列權威來源：

- 正式未完成項目與負責人：[[05-規劃/01-時程與進度/未完成項目追蹤表]]
- M 功能各層實作狀態：[[05-規劃/01-時程與進度/M功能實作矩陣]]
- 需求、API、資料與測試回連：[[05-規劃/03-需求與決策治理/需求追蹤矩陣]]
- 已確認產品與技術決策：[[05-規劃/03-需求與決策治理/決策紀錄]]

本頁項目關閉時，必須在同一次更新中同步修正對應權威來源，避免再產生第二份不同步的進度清單。

## 2. 狀態與完成規則

| 狀態 | 說明 |
|---|---|
| `⬜ 待辦` | 尚未開始，且沒有可驗收產物 |
| `🔵 進行中` | 已有實際修改或執行中的工作，但完成定義尚未全部滿足 |
| `🟡 待驗證` | 實作可能已完成，等待 exact SHA、測試、CI、人工覆核或文件寫回確認 |
| `🔴 阻塞` | 缺少必要環境、授權、決策或外部人員，現在無法安全關閉 |
| `⚪ 延後` | 已明確移出目前 Release Candidate／預演範圍 |
| `✅ 完成` | 完成定義全部滿足，證據已填入，且權威進度文件已同步 |

完成狀態必須符合以下規則：

1. 程式存在不等於完成；必須有對應測試與必要 Gate。
2. PR 開啟或 Review 通過不等於完成；必須記錄合併後 `dev` SHA。
3. CI 全綠只證明已納入的 Gate；Live AI、人工演練與未覆蓋案例仍要獨立驗證。
4. E2E 必須由 UI 經 API 到資料庫／Provider，並提供可重跑命令或 CI artifact。
5. 人工工作必須記錄執行日期、執行人、結果與保存位置。
6. 每次更新狀態時，同步修改頁首 `最後確認`。
