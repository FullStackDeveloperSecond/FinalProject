# DEV-04 展示資料重設與健康檢查執行紀錄

## 結論

本機候選已完成安全的展示資料重設、隔離啟動與健康檢查，T2 證據狀態為 `PASS`。這項結果尚未包含 commit 後 exact-head Security、Required CI、Review 與 squash merge，因此 DEV-04 暫維持進行中；15～20 分鐘真人操作彩排未執行，依 alex 裁定標為未測試／非阻擋，不得改寫為通過。

## 最低成本與安全邊界

- 接受現況不足：`start-all.ps1 -Environment Demo` 原先仍可能使用預設 `DoSelectDb`，共享 `DoSelectDemo` 也已落後固定 Seed v2。
- 人工輸入環境變數不足：無法穩定重現資料庫身分，也不能防止誤連共享庫。
- 選定方案：重用既有 `DemoDataSeeder`、唯讀 Validator、SQL2025 Windows Authentication 與 `.run` 狀態；以最小 PowerShell 變更建立並綁定新的 `DoSelectDemo_<GUID>`。
- 未新增 Dependency、Schema、Migration、Service 或正式環境設定；不刪除、不覆寫 `DoSelectDb`／共享 `DoSelectDemo`。
- 只接受 `^DoSelectDemo_[0-9a-fA-F]{32}$`；資料庫名稱在組合連線字串前再次驗證，服務運行時拒絕重設。

## 實作範圍

- `reset-demo-data.ps1`：產生全新隔離名稱，依序執行 Seed 與 11 項唯讀驗證，成功後才原子寫入 `.run/demo-database.json`。
- `start-all.ps1`：Demo 模式必須取得並驗證隔離資料庫，API 啟動期間明確設定該連線，並在受管狀態與安全輸出中記錄資料庫名稱。
- `test-demo-environment-safety.ps1`：驗證 1 個合法與 4 個危險名稱、PowerShell parse、Seed／Validate 呼叫、服務運行拒絕與 API connection binding；納入既有 Package Source Evidence Job。
- README 與 Demo 前檢查表：改為可直接重現的 isolated reset／start 操作及 Pepper 前置檢查。
