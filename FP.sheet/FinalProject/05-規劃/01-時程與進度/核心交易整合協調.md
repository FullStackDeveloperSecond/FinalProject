## 依賴順序與 Gate

1. **GATE-TX-01｜契約凍結**：Checkout Application 只依賴用途專用規則介面與單一 `ICheckoutTransactionGateway`；Infrastructure Gateway 使用共用 `DoSelectDbContext` 加入冪等 Executor 已擁有的交易，直接鎖定／讀寫原子建單所需表，但不得自行提交。其他 Application 模組不得互相呼叫 Repository。此契約已由 DEC-BATCH-027 定版，本地實作待合併。
2. **GATE-TX-02｜SQL 原子交易**：建立 Order、OrderItems、Coupon／費用快照與 InventoryReservation 必須同交易成功或全部回滾；兩個請求競爭最後一件商品時只能一筆成功。
3. **GATE-TX-03｜付款一致性**：`Order.GrandTotal`、`PaymentAttempt.Amount` 與成功後 `PaidAmount` 必須一致；同 Idempotency-Key replay 不重複建單、扣庫存或付款。
4. **GATE-TX-04｜宅配限制**：既定訪客宅配路徑只能使用預付；費用、滿額免運與組裝配送限制由可信 Shipping／Coupon 規則計算並保存快照。
5. **GATE-TX-05｜Provider-backed 整合**：使用 CI connection template 建立專屬 SQL 測試庫，實際套用目前完整 Migration 歷程；涵蓋成功、缺貨、競爭、付款失敗／replay 與整體回滾。不得把只對既有測試模型建庫的案例當作完整 Migration chain 證據。
6. **GATE-TX-06｜E2E**：Typed Client 更新後，瀏覽器從 Cart UI 完成既定訪客旅程，並以 API／SQL 斷言 Order、Reservation、Payment 與通知排程結果。
