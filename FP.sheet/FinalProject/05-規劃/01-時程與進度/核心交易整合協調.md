# 核心交易整合協調

## 判定

`預付與 COD 核心主旅程 GO／完整變體仍 NO-GO`：WP-A04／WP-H05 已補齊固定 Guest Cart → Checkout → replay → Guest 限單驗證 → 模擬付款 → Invoice 的信用卡隔離 Browser E2E，並以 SQL Server Provider-backed 測試證明同請求不重複與最後一件商品競爭只成功一筆。PR #97 已補 Cart 持久化套券；PR #106 已交付正式物流狀態命令與 COD 收款接線；H-R02／PR #115 再以宅配 `Delivered` 與超取 `PickedUp` 的隔離 Browser E2E 證明中間狀態不提前收款／開票、最終 Paid／Completed、唯一發票與同鍵重播。H-R03／PR #117（等待 Required CI／Review／合併）再以 Browser E2E 補齊已付款送達訂單的 Return → Refund 核准 → 執行 → Order 退款投影 → 發票折讓主旅程（全額與部分退款、Actor Scope 負向案例）。這些展示主路徑具備可重跑證據，但不能因此把 M-09／M-11、零淨額退款或所有錯誤變體標為完整 E2E。

原始碼重驗確認付款完成可同交易更新 `Order.PaidAmount`、PaymentEvent、History、Audit 與通知 Outbox，付款成功發票 Outbox／Consumer、取消與 COD Demo 拒絕亦已進 `dev`。WP-A04 使用確定性八類組裝＋一件獨立 GPU Seed、`CREATOR10`、組裝宅配與信用卡，在專屬 `DoSelectE2E_<GUID>` 完成 UI／API／SQL 跨層旅程；H-R02 則使用兩張一般商品 Guest COD 訂單，經真實管理員密碼／TOTP、批次出貨與物流狀態 UI，驗證宅配送達及超商取貨的收款、訂單完成與發票開立。模擬完成端點依 DEC-P356 只額外允許隔離 E2E Environment，產品仍維持 Demo-only；本機與 CI 皆使用專屬、可清理資料庫。

這是 08-30 檢查點的實際 No-Go 結果，不更改 09-08 功能開發截止日。只有下列 Gate 依序通過，核心交易才可改為可展示。

## 既定最小旅程

沿用既有 Demo 規格，不新增產品決策：

`訪客購物車 → CREATOR10 → 組裝費／宅配運費 → 建立訂單 → 原子保留多 SKU → 顯示訂單編號 → Email 限單驗證 → 即時模擬付款成功／回呼 → 顯示訂單與通知排程`

替代路徑「使用已建立 Pending 訂單完成付款」只供現場備援，不得用來宣告 Checkout E2E 完成。

## 依賴順序與 Gate

1. **GATE-TX-01｜契約凍結**：Checkout Application 只依賴用途專用規則介面與單一 `ICheckoutTransactionGateway`；Infrastructure Gateway 使用共用 `DoSelectDbContext` 加入冪等 Executor 已擁有的交易，直接鎖定／讀寫原子建單所需表，但不得自行提交。其他 Application 模組不得互相呼叫 Repository。此契約與實作已由 DEC-BATCH-027／PR #52 合併至 `dev`。
2. **GATE-TX-02｜SQL 原子交易**：建立 Order、OrderItems、Coupon／費用快照與 InventoryReservation 必須同交易成功或全部回滾；兩個請求競爭最後一件商品時只能一筆成功。
3. **GATE-TX-03｜付款一致性**：`Order.GrandTotal`、`PaymentAttempt.Amount` 與成功後 `PaidAmount` 必須一致；同 Idempotency-Key replay 不重複建單、扣庫存或付款。
4. **GATE-TX-04｜宅配限制**：既定訪客宅配路徑只能使用預付；費用、滿額免運與組裝配送限制由可信 Shipping／Coupon 規則計算並保存快照。
5. **GATE-TX-05｜Provider-backed 整合**：使用 CI connection template 建立專屬 SQL 測試庫，實際套用目前完整 Migration 歷程；涵蓋成功、缺貨、競爭、付款失敗／replay 與整體回滾。不得把只對既有測試模型建庫的案例當作完整 Migration chain 證據。
6. **GATE-TX-06｜E2E**：Typed Client 更新後，瀏覽器從 Cart UI 完成既定訪客旅程，並以 API／SQL 斷言 Order、Reservation、Payment 與通知排程結果。
