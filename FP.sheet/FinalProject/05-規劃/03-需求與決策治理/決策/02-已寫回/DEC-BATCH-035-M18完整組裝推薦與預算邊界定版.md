# DEC-BATCH-035｜M-18 完整組裝推薦與預算邊界定版

## 決策

| ID | 已確認內容 |
|---|---|
| DEC-P340 | `CustomBuild` 成功結果必須回傳一份完整組裝清單，而不是多筆彼此獨立的商品候選。清單固定涵蓋 CPU、主機板、記憶體、顯示卡、儲存裝置、電源供應器、機殼及 CPU 散熱器；既有零件與新購零件共同形成完整清單，並以正式確定性相容性引擎驗證。`Blocked` 或 `InsufficientData` 不得成為推薦結果；`Compatible` 或 `Warning` 才可回傳，且 AI 只能替後端核准的新購商品產生理由。 |
| DEC-P341 | 使用者最高預算定義為「本次新購零件小計＋每台固定 NT$300 組裝費」。使用者既有零件不計入新購預算與本次應付總計，但仍必須顯示在完整清單並參與相容性判定。回應分開提供 `purchaseSubtotal`、`assemblyFee` 與 `purchaseTotal`，不得把既有零件目前市價混入預算。 |

## Lowest-Cost Analysis

1. 沿用單品候選並只改 UI 標題：無法保證八類零件完整，也不能證明整機相容，未採用。
2. 只在文件約定預算算法：API 仍可能回傳超出預算或把既有零件重複計價，未採用。
3. 重用既有 M-18 搜尋流程、M-16 組裝分類、M-17 相容性讀取器／規則引擎及現有商品查詢，在既有回應加入可選 `customBuild`：不新增資料表、Migration、套件或服務即可符合驗收，採用。
4. 新增最佳化求解服務或新的組裝資料模型：40 天專題第一版沒有必要，會增加測試、維運與回復成本，未採用。

## Business Impact

| 面向 | 影響 |
|---|---|
| 受影響角色 | 不熟悉規格的組裝新手、帶既有零件升級的使用者、展示人員 |
| 現況風險 | 單品候選可能被誤認為完整電腦；既有零件若重複計價會讓預算失真；未經完整相容性驗證會削弱核心商業價值 |
| 預期可量測結果 | 每筆成功 CustomBuild 有八類完整清單；新購小計＋300 等於本次總計；既有零件計價為零但參與相容性；不回傳 Blocked／InsufficientData 組合 |
| 建置／持續成本 | 延伸既有 Application、SQL Catalog、API DTO、OpenAPI、Vue 與測試；無新增固定服務、Schema 或套件 |
| 風險成本 | 有界候選搜尋未承諾全域最低價或最佳效能；商品資料規格不足時會回無結果或補問，不得由 AI 猜測 |
| 信心 | 高（契約、Application、API、Vue 與 SQL Server Provider-backed 證據）；真實模型品質仍由 AI-09 驗證 |
| 成功指標 | 完整清單、預算、既有零件及相容性測試通過；OpenAPI／Typed Client 同步；Required CI、Review 與 PR Gate 通過 |
| 停止／回復條件 | 任一超預算、既有零件重複計價、缺少必要類別或不相容組合被回傳即停止；可由 `Features:AiEnabled=false` 降級一般搜尋 |
