# AUTO-DEC-008｜文件分類、權威來源與冗餘收束

## 正式決策

1. 保留 `00`～`05` 大階段，在文件量較大的階段下依領域或用途建立編號式第二層資料夾。
2. 根目錄與各大階段 README 改為任務導向索引，不再重複平鋪全部文件。
3. [[00-專案概述/系統規格書總覽]] 是現行規格權威入口；[[00-專案概述/DoSelect完整系統規格書-v1.0]] 自 2026-08-20 起為凍結的 v1.0 單檔快照。
4. 已完成的互動決策表單不得留在 `00-互動中`；正式決策以 `02-已寫回` 快照保存，原始表單由 Git 歷史追溯。
5. 已被現行追蹤表或正式決策取代、但仍具稽核或交接價值的文件移至 `05-規劃/90-封存`，不得作為現行權威。
6. 知識點按技術主題分類，僅說明概念及連結正式規格，不複製商業規則。
7. 日誌按 `YYYY/MM` 歸檔；日誌 README 與模板固定保留在 `日誌/` 根目錄。
8. 文件搬移必須同步更新全部 Wiki Link、程式內規格來源引用及產生式 AI 評估資料，完成標準為失效連結為 0。

## 最低成本與影響

- 只增加單一索引無法解決 `03-架構`、`05-規劃` 與知識點平鋪，以及已寫回表單造成的同名檔案問題。
- 不新增 Obsidian 插件或另一套文件系統；沿用現有資料夾、README、Wiki Link、Meta Bind 與 Fancy Kanban。
- 受影響者為五位開發者與引用規格來源的 AI 評估資料。主要風險是舊路徑失效及開發中書籤改變；以單一 Git 變更、完整連結掃描及可回復歷史控制。
- 成功指標是各文件能由兩層分類入口找到、現行權威唯一、失效 Wiki Link 為 0，且 AI 評估來源不殘留舊路徑。

## 收束範圍

- 移除 10 份已 `applied` 的原始互動表單；正式決策編號均已存在於 `02-已寫回`。
- 封存 `全文件未完成稽核.md` 與 `Yinyin-優惠券退款與付款裁定回覆.md`。
- 保留需求、驗收、工程包、知識點與日誌各自用途，不以內容相似為由刪除非等價文件。

## 回復條件

若分類造成無法批次修復的引用失效或嚴重阻礙團隊開發，回復本次文件重整 Commit；不得只回復部分路徑而留下兩套權威入口。
