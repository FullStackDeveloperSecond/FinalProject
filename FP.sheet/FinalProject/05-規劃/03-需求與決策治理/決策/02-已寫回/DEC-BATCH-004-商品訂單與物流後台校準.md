# DEC-BATCH-004｜商品、訂單與物流後台校準

本批用於校準商品、庫存、訂單與物流後台原型和正式專案規格。14 項均已由使用者確認，並直接寫回正式文件。

## 決策

| ID | 最終決策 |
|---|---|
| DEC-P71 | 建立訂單時只保留庫存；付款成功不扣實體庫存，直到出貨時才同時扣除 `OnHandQuantity` 與 `ReservedQuantity`。 |
| DEC-P72 | 信用卡、LINE Pay、Apple Pay、Google Pay 保留 15 分鐘；ATM、超商代碼保留 3 天；Demo 可設定為 2～3 分鐘，不採 30 分鐘共用期限。 |
| DEC-P73 | 超商取貨付款與一般宅配皆可使用貨到付款，上限為折扣後且包含運費等費用的最終應付金額 NT$20,000；組裝電腦及其他限制品仍排除。宅配及超商取貨第一版固定啟用，不提供後台停用。 |
| DEC-P74 | 後端繼續分離 `OrderStatus`、`PaymentStatus`、`FulfillmentStatus`；「待出貨、已出貨、已完成、已取消」只能是後台衍生顯示或篩選，不得成為取代領域狀態的單一欄位。 |
| DEC-P75 | 後台依目前狀態顯示合法操作，例如開始備貨、出貨、取消；不得讓管理員以下拉選單直接指定任意下一狀態。 |
| DEC-P76 | 庫存保留使用 `Active`、`Consumed`、`Released`、`Expired`，明確區分一般釋放與逾時釋放。 |
| DEC-P77 | 管理員手動釋放有效保留時必須填寫原因、二次確認、驗證權限並保存 Audit Log；操作必須冪等。 |
| DEC-P78 | SKU Code 建立後不可修改；已被商品、訂單、庫存、保留或其他資料引用的 SKU 只能停用或下架，不能實體刪除。 |
| DEC-P79 | 非變體商品仍建立一個預設 SKU，售價及庫存統一保存在 SKU；商品不得另建一套價格與庫存來源。 |
| DEC-P80 | `OrderManager` 與 `SuperAdmin` 可修改超商包裹尺寸與重量限制。設定需版本化及稽核，只影響修改後的新購物車與新訂單；既有訂單使用成立時的規則快照。 |
| DEC-P81 | 超商門市採固定種子資料，可新增、編輯及停用；已被訂單使用的門市不得實體刪除，訂單保存門市快照。 |
| DEC-P82 | 第一版保留信用卡、ATM、超商代碼、貨到付款、LINE Pay、Apple Pay、Google Pay，並由共用模擬付款能力降低重複實作。 |
| DEC-P83 | `OrderManager` 可查看履約必要的訂單收件快照，但不能因此查看完整會員檔案；客服仍只看遮蔽資料，完整會員資料限 `PrivacyAdmin` 與 `SuperAdmin`。 |
| DEC-P84 | 批次出貨逐筆驗證及逐筆交易；合法訂單可成功、不合法訂單個別失敗，最後回傳逐筆結果，不因單筆失敗讓整批回滾。 |

## 與既有決策的關係

- DEC-P73 明確取代 DEC-P22 的「貨到付款僅限超商、上限 NT$10,000、宅配必須先付款」。其他貨到付款狀態機與限制原則保留。
- DEC-P80 不改變 45 cm、105 cm、5 kg 的預設值，但將其從固定常數改為可版本化管理設定。
- DEC-P71、DEC-P72、DEC-P76、DEC-P78、DEC-P82 延續並補強既有正式規則。
