# AUTO-DEC-004｜報表主責與分工文件收束

## 背景

現有分工文件將 `M-15` 一般與進階營運報表列在 kafen 名下，但組長確認正確主責應為 terry。多份規劃文件同時保存完整分工，並保留已完成資料表提案階段使用的任務書，造成同一責任在不同文件漂移。

## 定案

| 項目 | 統一結果 |
|---|---|
| M-15 一般與進階營運報表 | 由 `terry` 主責七項後台報表、一般營運指標、查詢契約、指標公式、資料來源、索引與測試 |
| Kafen | 主責退貨、客服、SLA、統一案件工作台、檢舉、S-07 RWD 與 PM-02 品牌視覺；不負責 M-15 |
| S-06 AI 報表分析 | 仍由 `alex` 主責 OpenAI、Prompt、輸出驗證、引用、成本與降級；由 `terry` 提供去識別化營運報表 Query／DTO 及領域覆核 |
| 案件資料 | `kafen` 仍提供去識別化客服、退貨與檢舉 Query／DTO；若營運報表需要案件指標，由 terry 透過 Application Query 取得，不直接讀 Kafen Repository |
| 分工正式入口 | [[05-規劃/02-分工與交接/開發分工與交接]] 是正式文字入口；[[05-規劃/02-分工與交接/重新分工看板]] 是互動介面；[[05-規劃/02-分工與交接/重新分工項目池]] 只定義工作包範圍 |
| 舊資料表任務書 | `組員分工與資料表設計任務書.md` 已完成階段用途，其責任邊界由正式交接頁承接，逐項範圍由項目池承接，因此從目前文件樹移除；歷史仍保留於 Git |
| 待確認空殼頁 | `待確認事項.md` 只重導至未完成追蹤表且沒有獨立內容，因此移除；所有未完成狀態只更新未完成項目追蹤表 |
| 全文件未完成稽核 | 保留 2026-08-15 稽核證據，但標為已完成／歷史稽核，不再作為第二份進度清單 |

## 責任數量調整

## 驗收

- 現行文件不再將 M-15 指派給 kafen。
- Terry 的交接界面包含 Report Filter／Metric／Row DTO。
- AI 報表分析仍屬 alex，且不直接讀取 Terry Repository。
- Kafen 報告不再要求完成七項 M-15 報表。
- Terry 報告加入七項 M-15 報表缺口與核取清單。
- README 不再連結已移除的舊資料表任務書。
- README 不再連結已移除的待確認空殼頁。
- 全文件未完成稽核明確標示為歷史證據。
