# 40 天開發計畫

本計畫以五人、每人每週約 30 小時、總工期 40 天為前提，涵蓋開發、整合、測試、文件、簡報與彩排。Day 35 起進入功能凍結，不再新增一般功能。

## 交付階段

| 階段 | 日程 | 主要目標 | 完成條件 |
|---|---:|---|---|
| 1. 架構與契約 | Day 1–5 | 建立 Solution、資料庫基線、共通 API 契約、驗證骨架、前後台骨架及協作規範 | 專案可啟動、Migration 可重建資料庫、共通規範可供各模組依循 |
| 2. 核心 M 功能 | Day 6–18 | 完成會員、商品與 SKU、購物車、訂單、付款、庫存、物流等核心流程 | 核心 API 可整合，主要狀態與資料異動可驗證 |
| 3. AI、報表與其餘 M | Day 19–27 | 完成 AI 商品搜尋、AI 客服、自由組裝與相容性、客服、退貨退款、報表等剩餘 M | M 功能進入可串接狀態，AI 故障時基本功能仍可運作 |
| 4. 整合與測試 | Day 28–34 | 修正跨模組契約、補整合測試、執行核心 E2E、準備一萬筆展示資料 | 所有 M 功能、Migration、API 契約與核心 Demo 測試通過 |
| 5. 凍結與展示準備 | Day 35–40 | 僅修 Bug、調整資料、完成文件、簡報、彩排與預錄備援 | 展示流程穩定，可由一台電腦一鍵啟動並完成備援演示 |

## 功能凍結規則

- Day 35 起不再加入一般新功能或擴大既有範圍。
- 凍結後允許：阻斷展示的 Bug、資料錯誤、安全問題、文件與簡報修正，以及不改變契約的展示性調整。
- 凍結後若要加入任何功能，必須由組長確認它不會危及核心 Demo、Migration、測試與備援。

## S 功能啟動門檻

只有同時滿足以下條件才可開始 S 功能：

1. 所有 M 功能已完成可建置版本。
2. EF Core Migration 可從空白資料庫完整重建。
3. 前後端所需 API 契約已穩定，沒有阻斷整合的變更。
4. 核心 Demo 流程的自動或可重複測試已通過。

未滿足門檻時，所有人優先補齊 M 功能、整合與測試，不以 S 功能取代未完成的核心範圍。

## 人力配置方式

- 採「功能主責＋備援」的混合分工，每個模組有一位主責與至少一位能接手的備援。
- 組長負責架構、跨模組整合、Code Review、文件，以及共用或小型模組開發。
- 主責人負責需求釐清、前後端契約協調、測試證據與交接；備援人至少要能啟動、測試與修正該模組。
- 五位成員的核心主責已確認；每個模組的具名備援仍需補排。

| 位置 | 主要責任 | 實際成員／模組 |
|---|---|---|
| 組長 | 架構、整合、審核、文件、共用模組 | alex；共用相關、架構與整合 |
| 成員 A | 會員功能主責＋其他模組備援 | haru；會員相關 |
| 成員 B | 客服與檢舉主責＋其他模組備援 | kafen；客服與檢舉相關 |
| 成員 C | 優惠與金流主責＋其他模組備援 | yinyin；優惠與金流相關 |
| 成員 D | 商品與購物主責＋其他模組備援 | terry；商品與購物相關 |

## 整合節奏

- 每週進行兩次固定整合，不另設每日同步會議：星期三 10:00、星期日 11:00。
- 每次整合檢查 `dev` 建置、Migration、API 契約、跨模組阻塞、核心流程及下一次整合前責任人。
- 每次整合的時長、必到人員、缺席及整合失敗後處理仍需補充。

## Demo 彩排節奏

- Day 20 起每週一次局部彩排，優先驗證已完成的核心流程與 AI 降級。
- Day 30 起每兩天一次完整彩排，依 15～20 分鐘 Demo 腳本計時。
- Day 36～39 每天一次完整彩排，記錄失敗點、修正責任人及備援影片是否可用。
- Day 35 功能凍結後，彩排發現的問題只允許修正 Bug、資料、講稿及備援，不新增一般功能。
