# 未完成項目追蹤表

本表是專案未完成文件與前置工作的**單一真實來源**。其他文件出現新的待確認或待補內容時，必須先在本表新增編號；完成或狀態改變時，也必須同步更新本表。

> [!important] 追蹤邊界
> 本表追蹤目前需求文件分析所得的未完成決策、設計文件、開發前置、測試與 Demo 準備。它不是逐頁、逐 API 的程式開發 Sprint Backlog；待使用案例與 API 目錄完成後，再另建開發工作分解並回連本表。

## 使用方式

### 狀態

| 狀態 | 意義 |
|---|---|
| `⬜ 待辦` | 已知要做，尚未開始 |
| `🔵 進行中` | 已有人負責且正在處理 |
| `🟡 待確認` | 需要團隊決策、資料或驗收 |
| `🔴 阻塞` | 因相依工作或外部條件無法繼續 |
| `⚪ 延後` | 已明確移出目前階段，但仍保留追蹤 |
| `✅ 完成` | 完成定義已全部滿足且文件已更新 |

### 優先級

| 優先級 | 意義 |
|---|---|
| `P0` | 開始多人開發前必須完成，否則容易造成資料庫、API 或權限返工 |
| `P1` | 第一週或對應功能開發前完成 |
| `P2` | 第一版整合前完成 |
| `P3` | Demo 與交付前完成 |

### 更新規則

1. 開始處理時，將狀態改成 `🔵 進行中`，並填入負責人。
2. 需要團隊決策時，使用 `🟡 待確認`；確定受到相依工作阻擋才使用 `🔴 阻塞`。
3. 只有「完成定義」全部滿足時，才能把 `- [ ]` 改為 `- [x]`，並將狀態改成 `✅ 完成`。
4. 每次更新需修改頁首的 `最後更新`，重要決策另寫回所屬正式文件。
5. 新增項目時沿用分類前綴與流水號，不重複使用已刪除的編號。
