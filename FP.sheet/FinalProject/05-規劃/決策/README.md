## 資料夾

| 資料夾 | 用途 | 可修改性 |
|---|---|---|
| `00-互動中` | 使用 Meta Bind 填寫選項、自主方案及補充內容 | 送出前可反覆修改 |
| `01-待寫回` | 已完成檢查並收束的決策快照，等待一次性授權寫回 | 原則上不可直接修改；變更需建立新批次 |
| `02-已寫回` | 已套用到正式文件及追蹤表的決策快照 | 唯讀保存 |
| `99-模板` | 每批 30 項的 Meta Bind 決策模板 | 只由流程維護者修改 |

## 狀態

```text
drafting
→ submitted
→ ready-to-apply
→ applied
```

| 狀態 | 說明 | 下一步 |
|---|---|---|
| `drafting` | 使用者正在填寫 | 保留於 `00-互動中` |
| `submitted` | 使用者已送出 | Codex 檢查完整性、衝突及自主輸入 |
| `ready-to-apply` | 已收束成決策紀錄 | 保存於 `01-待寫回`，等待明確授權 |
| `applied` | 已更新正式文件及追蹤表 | 保存於 `02-已寫回` |

若答案不完整或互相衝突，原批次不會進入 `ready-to-apply`，而是維持 `submitted` 並建立補充決策。

## 使用流程

1. 在 `00-互動中` 開啟決策批次。
2. 每題選擇一個方案，或在自主輸入提供完整方案。
3. 自主輸入可補充選項，也可取代選項。
4. 按下「送出本批決策」，將 `status` 改為 `submitted`。
5. 告訴 Codex：「收束已送出的決策」。
6. Codex 只產生決策快照，不修改正式需求文件。
7. 累積完成後，明確授權：「將所有待寫回決策套用到正式文件」。
8. Codex 更新正式文件、[[05-規劃/未完成項目追蹤表]] 及 [[05-規劃/決策紀錄]]，再將批次標為 `applied`。

## 一次性寫回規則

- 只處理 `01-待寫回` 且 `status = ready-to-apply` 的紀錄。
- 寫回前先檢查不同批次是否互相衝突。
- 每筆已寫回紀錄需保存套用時間、受影響文件及追蹤項目。
- 互動文件不得直接作為正式需求依據。
- 正式文件不得從 `drafting` 或 `submitted` 批次取得需求。

## Meta Bind

本流程使用 Meta Bind 保存表單內容。選項及文字區會即時寫入互動文件的 YAML Properties；「送出」按鈕只更新批次狀態，不會修改其他文件。
