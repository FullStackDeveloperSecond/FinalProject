# DEC-BATCH-010｜核心產品與責任決策

本批 8 項皆採表單建議方案，沒有自主輸入、缺漏或互相衝突。以下內容已寫回正式文件。

| ID | 正式決策 |
|---|---|
| DEC-P235 | 正式名稱為 `CoreBuild 科築電商`；標語為「說出需求，組出適合你的電腦。」 |
| DEC-P236 | 可引用具來源的真實商品品牌／型號／原廠公開規格；商店、價格、成本、庫存、會員、交易、評價及營運結果全部使用虛構資料，前台、簡報、後台及匯出需明確標示 Demo 與無品牌合作／背書。 |
| DEC-P237 | 固定配對備援與交叉測試：`haru ↔ yinyin`、`kafen ↔ terry`；alex 負責架構、最終整合與第二線備援。主責不得自行完成最終驗收。 |
| DEC-P238 | 一人可多角色，但採高風險 Policy 分離：OrderManager 核准退貨、FinanceManager 執行退款、SuperAdmin 授予角色、PrivacyAdmin／SuperAdmin 查看完整個資、SecurityAdmin 查安全稽核、Audit 匯出只限 SuperAdmin。不建立所有操作都需雙人線上核准的工作流。 |
| DEC-P239 | 功耗資料以原廠 TDP／TBP／TGP／建議 PSU 優先，缺值可用有來源且人工覆核的維護值；核心值缺失回 `InsufficientData`，不得宣稱相容或整套一鍵加車，但可單獨購買 SKU。 |
| DEC-P240 | 線上付款以付款成功日認列，COD 以送達且收款日認列；退款在成功退款日沖減，不回寫原月份，另提供原訂單完成月份分析維度。 |
| DEC-P241 | AI 搜尋既有零件接受站內 SKU 或使用者確認的結構化手填資料；AI 自然語言解析只能形成候選，確認前不得進入相容性計算，也不可直接猜成特定 SKU。 |
| DEC-P242 | Clarification Precision ≥90%、Recall ≥85%；完整組裝的最高預算、用途或既有零件必要相容性規格漏問時，一律阻擋發布。 |
